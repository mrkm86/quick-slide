# INSPECTION.md — html-slide

> 共通項目は検品する側の基準にある。**ここには固有項目だけ書く。**
> 作成: 2026-10-03。

## 商品の型

**画面型**（スライド）。成果物の実体:

```
<出力先>/deck.pptx        # 本体（PowerPoint で開くもの）
<出力先>/inspect.md       # 検品用の写し（html_slide.py が PPTX から書き出す）← 検品役が読むのはこれ
```

`inspect.md` には、スライドごとに 型・画面の文字（出る順）・ノート（話す台本）・クリックの段の数・効果の数・
機械の検査（`check` と `verify`）の結果が入っている。検品役は PPTX を開かない。

⚠️ **中身は毎回違う。** 題材は呼ぶ側が決める。正解の文面は存在しない。

## 読者

**2種類いる。**

| 読者 | 何ができないと困るか |
|---|---|
| **資料を受け取る人**（社内・客先） | 見出しを順に読むだけで、話の筋（何が問題で、どうするか）が分かる |
| **話し手** | ノートを読みながらクリックすれば、話と画面の動きが合う |

## 必須要素（欠けたら失格）

- 表紙（`cover`）が1枚目にある
- 中身の型（`statement` / `big-number` / `cards` / `flow` / `compare` / `bar-chart` / `table` / `photo`）の画面に、見出しがある
- `mode: talk` の資料では、全スライドにノートがある

## 失格条件（あったら失格）

| # | 失格 | なぜ |
|--:|---|---|
| H-1 | **中身の型の見出しが名札になっている**（「現状」「課題」「施策一覧」のように名詞だけで、何が言いたいかが無い） | 見出しを読むだけで筋が分かる、という資料の約束が崩れる（`references/deck-format.md` の「見出しは主張で書く」） |
| H-2 | **画面の数字とノートの数字が食い違う**（同じものを指して値・単位が違う） | 話し手が画面と違う数を口にする |
| H-3 | **プレースホルダが残っている**（`{…}`・`TODO`・`lorem`・`XXX`・「ここに〜」） | 雛形のまま出している |
| H-4 | **機械の検査が通っていない**（`inspect.md` の `check` に違反がある、または `verify` が不一致） | はみ出し・動きとノートのずれが残っている |
| H-5 | **ノートの［クリック］の位置が、画面の出る順と合っていない**（ノートで先に話す要素が、画面では後から出る） | 話と動きがずれる |

## 機械で見るもの

```bash
python3 <このスキルのフォルダ>/scripts/html_slide.py verify <出力先>/deck.pptx --odp
```

`inspect.md` の「機械の検査」の欄にも結果が写してある。

## 見ないもの

- 色・字体・余白などデザインの好み（テーマが決める）
- 型の選び方の好み（明らかに合っていない場合も、指摘に留めて失格にしない）
- PowerPoint で実際に動くか（検品役は開けない。人が最終確認する）
- 内容の事実の正しさ（題材は呼ぶ側の責任。見本の台本は架空と明記している）
