# 0022 余白のあるページは大きく組む（見出しと grow を広げる）

- 日付: 2026-10-10
- 状態: 決定

## 背景

デジタル庁デザインシステムに沿わせた後（ADR 0020・0021）、同じ原稿で台本から作り直して前の版と並べた。土台（色・枠・字）は整ったが、本文の文字はほとんど大きくならず、下の余白が残るページが多かった。

調べると、grow（ADR 0018）は動いていたが、次の3つで頭打ちになっていた。

- 採る条件が「上げた後も置ける高さの 7 割以下」で、もともと 6〜7 割埋まっているページは一段も上がらない
- 上る段は 2 つまでで、28 → 36 の差しか出ない
- 役の上限（本文 36・箱の題 45）

見出しは図解の型（equation・hub・pairs）だけが 80 で、ほかは 64 だった。

## 決めたこと

1. **見出し**: 画像のないページは、80 で1行に収まる見出しを 80 にする（`Slide.big_head`）。2行になる見出しは今までどおり 64 から（2行の 80 は本文の場所を削るため）。80 で中身が入らなければ、今までの見出しで組み直す
2. **grow の条件を2つに分ける**: 置ける高さの 8 割（`GROW_FILL`）に届かなければ試し、上げた結果が 9 割2分（`GROW_MAX`）までに収まる一番大きい段を採る
3. **上る段は 4 つまで**（`GROW_STEPS = (4, 3, 2, 1)`）
4. **役の上限を上げる**: 箱の題 45 → 57・本文 36 → 45・用語と説明 45 → 57（`skills/dads/tokens/slide.json` の `roles` も同じ）
5. **どれかの役が元より小さくなる段は採らない**: 題が上がった分、本文が下がる組み方（箇条書きで題 57・本文 24 になった）を防ぐ
6. 用語と説明（deflist）の用語の列の幅は、組む大きさで測って格子の 3〜5 列から選ぶ
7. 見出しの下限を 45 から 48 に上げる（本文の上限 45 と同じにならないように。見出しは常に本文より大きい）

## 採らなかったこと

- 2行の見出しも 80 にする: 本文の文字が下がるページが出る
- 表・グラフ・お知らせの枠を grow の対象にする: 表とグラフは行や軸の数で高さが決まり、お知らせの枠は中身が 8 割埋まっていた
