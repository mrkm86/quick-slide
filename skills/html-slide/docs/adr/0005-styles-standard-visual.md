# 0005 スタイル（standard・visual・カスタム）を持つ。名前は image-slide とそろえる

- 日付: 2026-10-05
- 状態: 採用

## 決めたこと

1. 層の並び: ストーリー（何を言うか）→ コンテンツ（何を載せるか・`type`）→ **スタイル**（どう見せるか・資料全体）と **レイアウト**（ページごとの変化形・座標は型が決める）。色と字体はテーマ（ブランド）
2. スタイルは `--style standard|visual|<YAML>`（`check`・`deck`・`images`）。既定は standard
   - `standard`: 説明・報告・社内資料向け。今までの見た目そのもの（何も足さない）
   - `visual`: ビジュアル寄り。プレゼン・ピッチ向け。表紙・章扉は全面写真、写真は全面、画像つきの箇条書きは写真1/2、3枚のギャラリーはコラージュ、出方はフェード
3. html-slide のスタイルは **決まった項目の値だけ** を持つ（`defaults` ＝型ごとの変化形の既定・`motion` ＝ fx と transition の既定・`name`・`description`）。文章を読んで解釈する仕組みは無い（文章で自由に書けるのは image-slide のカスタムスタイル）
4. **台本に書いた値が勝つ。** スタイルは台本に無いキーを埋めるだけ。画像が要る変化形は、そのページに画像があるときだけ当てる（無ければ型の既定のまま。止めない）。1枚目と `mode: handout` の切り替えは今までどおり fade
5. **知らないキー・知らない型・その型に無い変化形・選べない値は rc=2**（`scripts/deck_style.py` の `VARIANTS` が正本）
6. 組み込みは `styles/standard.yaml`・`styles/visual.yaml`。カスタムの雛形は `templates/custom-style.example.yaml`
7. 足した既定はページごとに `build` 情報（`styled`）と `inspect.md` に出す

## 追記（2026-10-05）: 見た目の調子（look）

- 週報の比較で、3つのスタイルとも3〜5枚目（流れ・主張・カード）が同じ見た目になった。理由は、この3つの型に変化形が無く、スタイルが当てられたのが動き（静止画では見えない）だけだったため。既定の見た目の差が小さすぎるので、見た目の調子を足した
- スタイルに **`look`** を足した。**文字の大きさ・余白は変えない**（はみ出しの検査は字体で実測しているため）。色は全部テーマから作り、読みやすさの検査も通す
  - `background`: plain／tint（地に強調色をうっすら）
  - `surface`: soft／white（白に影）／primary（主役の色の淡い地。2026-10-05 に accent から改名）／line（白に枠線）。カード・比較の列・KPI・吹き出し
  - `radius`: default／square／round
  - `band`: small／bar（上端に全幅の帯）／none
  - `emphasis`: default／strong（強調する箱を強調色のベタ塗りに白い文字）
  - `statement`: plain／panel（主張の1枚を強調色の全面に白い文字）
- visual は tint・white・round・bar・strong・panel。standard は look を持たない（今までの見た目のまま）
- 残る弱さ: 中身の型は中身を画面の上から詰めて置くので、情報の少ないページは下が空く。これは型の配置の話で、スタイルの外

## 持たないもの（今は）

- 文字の大きさ・余白の段階: 文字のはみ出しの検査（字体で実測する）とぶつかりやすい。要る資料が出てから
- 言葉遣い: html-slide は台本の文字をそのまま描くので、変えられない。ストーリーの側（台本を書く側）の話
- 台本の一番外の `style` キー: 一番外のキーは image-slide と共有しているので、増やすなら2つ一緒に。今は引数だけ

## 却下した案

| 案 | 却下の理由 |
|---|---|
| ピッチ・ビジネスなど用途の名前にする | image-slide と名前がずれる。用途は description に書けば足りる |
| スタイルとレイアウトを束ねた「デザイン」を作る | 色・素材まで入れたくなり、層が分からなくなる。組み合わせるのは呼ぶ側 |
