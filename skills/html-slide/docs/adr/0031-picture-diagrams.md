# 0031 絵で描く図解（図の中の文字も描かせる）

- 日付: 2026-11-19
- 状態: 採用
- 関係: ADR 0011（生成の枠を Codex で描いて埋める）・ADR 0030（自由なページ。段階 3 の一部を先に入れる）

## 背景

自由なページ（型 `free`）で、数字・比較・手順のページは中身に合う形で組めるようになった。
一方、全体の構成図・システムの構成・画面のイメージのように、**関係や配置そのものが中身のページ**は、箱と矢印を並べても伝わりにくい。
実際の原稿（概要設計の 20 枚）で作ると、こうしたページが 4 枚ほどあり、全部を画像生成で描いた版に見劣りした。

今までの生成の枠は、絵に文字を描かせない（文字はエンジンが置く。絵の中の文字は直せず、誤字も出るため）。図解は名前のラベルが無いと成り立たない。

## 決めたこと

画像の指定（`image`）に、**`labels`（図の中に描く文字の並び）** を書けるようにする。`labels` のある枠だけ、文字つきの図解として描かせる。

- **台本**: `"image": {"prompt": "何をどう並べて描くか", "labels": ["紙の帳票", "AI OCR アプリ", …], "alt": "…"}`。
  `labels` は 1〜30 個・1 つ 30 字まで・改行なし・重なりなし。`prompt` と一緒に書く（持ち込みの絵 `path` には書けない）
- **描かせ方**: 描く指示に「図の中に描く文字は、次の N 個だけ。1 字も変えず、この表記のとおりに描く」と一覧を足す。
  ふつうの生成の決まり（文字・ロゴ・透かしを描かない）の代わりに、**一覧に無い文字を描かない**と言う
- **画風**: 資料の画風（写真風・イラスト・手描き）に関係なく、平らな図解にそろえる（地の色の無地の背景・テーマの主役の色と差し色・文字の色）。
  台本からは選べない。キャラ（`_characters`）は図解には描き込まない
- **置く型**: まず `figure`（見出しの下に、図を切らずに大きく置く）。画像の枠を持つ型ならどれでも書けるが、切り抜く枠（`cover`）では
  端の文字が切れるので、台本の決まりは `figure` を案内する
- **枠の一覧**（`image_slots`）に `labels` を出す（検品が、絵の文字と一覧を照らせるように）
- **使い分け**（台本の決まりに書く）: 数字・比較・手順は自由なページか型（正確で、編集できる）。絵で描くのは、関係や配置そのものが中身のページ。
  1 つの資料で 2〜5 枚が目安
- image-slide（同じ台本を絵で描く）は、`labels` を描く絵の言葉に続けて受け取る

## 確かめたこと

実際の原稿で、台本係が 20 枚のうち 4 枚を絵で描く図解に選び、Codex で描いた。目で照らした 2 枚（ラベル 16 個ずつ）は、全部が表記どおりに出た。
1 枚では、書類の絵の中に一覧に無い仮の文字（ABC・123）が描かれたので、指示に「書類や画面の絵の中も、仮の文字を入れず線や四角で表す」を足した
（足したあとの描き直しでは確かめていない）。

## 理由

- 図解の文字を絵に描かせると見た目は良いが、誤字と直せなさが弱点。**描いてよい文字を台本に並べる**ことで、指示がはっきりし、
  検品の物差し（一覧と絵を照らす）ができる。直すときは一覧を直して描き直す
- 文字を描かせる例外を「`labels` のある枠」に限れば、今までの生成の絵（空気・場面）は変わらない

## 却下・見送ること

| 案 | 理由 |
|---|---|
| 絵には文字を描かせず、ラベルはエンジンが箱として重ねる | 文字は編集できるが、絵とラベルの位置を合わせられず、矢印の途中の名前などが作れない |
| ページを丸ごと絵で描く（image-slide と同じ） | 見出し・出典・ロゴ・ページ番号がエンジンの枠から外れ、編集できる所が無くなる |
| 絵の文字を機械で読んで、一覧と照らす検査 | 読み取りの道具が要る。まず目での検品と、描き直しで回す |
| 自由なページの中の絵の枠（図と数字の箱を 1 ページに混ぜる） | ADR 0030 の段階 3 の残り。`figure` で足りないページが出てから |
| 図のテイストの作り込み・図をいつ使うかの基準の精査 | 使ってみてから詰める（2〜5 枚の目安は仮） |
