# 0011 画像の枠は Codex で描いて埋める（叩き台は絵の入った形で返す・差し替えは path・画風は資料全体で1つ）

- 日付: 2026-10-07
- 状態: 採用（4. の置き場は [ADR 0014](0014-cache.md) で置き換えた）
- 比べたもの: 前の決まり（`references/images.md`「画像を作らず、枠の一覧を出して呼ぶ側が埋める」）、image-slide の Codex の呼び方（`codex_run.py`・ADR 0002）と revise（ADR 0012）

## 決めたこと

1. **絵の出どころを3つに分ける。** 持ち込み（台本の `path`・置き場 `images/s{NN}-{枠}.png` に置いた絵）／生成（`prompt` だけの枠）／図解（型が HTML で組む）。
   Codex が描くのは生成だけ。実在のもの（自社の製品・特定の人や場所）は持ち込みだけにし、生成で作らない
2. **画像を置くかは台本を書く側（LLM）が決める。** エンジンは判断しない。deck-format.md に使い分け（構造・手順・数字は図解、空気・場面・気持ちは生成）を書き、
   スタイルの `expects_images`（visual は表紙・章扉・締め）で画像の無いページを警告する
3. **`deck` は既定で、まだ絵の無い生成の枠を Codex で描いて埋めてから組む**（standard・visual とも）。描けなかった枠は仮の枠で組み、rc=1（もう一度流すとその枠だけ描く）。
   `--no-fill` は描かずに仮の枠、`fill` は描くだけ。認証は1回の実行で1度・並列8本（image-slide と同じ）。Codex の認証が切れていれば rc=4
4. **生成の絵の置き場は `images/gen-<鍵>.png`**（置き場は [ADR 0014](0014-cache.md) でキャッシュの区画に移した。鍵の作り方はこのまま）。**鍵は描く指示（prompt・文字を重ねる側・画風・色・キャラの絵の中身・形）から作り、ページ番号を入れない。**
   叩き台はページを足したり並べ替えたりするのが普通なので、ページ番号で置き場を決めると絵が別のページへずれる。横に何から描いたかの `.json` を置く（呼ぶ側の DB が拾える）
5. **差し替え（「あの資料のあの写真」）は、その枠に `path` を書く。** 持ち込みの枠は Codex が触らない。「あの資料」を探して写真を抜き出すのは呼ぶ側
   （エンジンはほかのスキルを呼ばない）。縦横比は `focus`・`fit: contain` で合わせる
6. **生成の絵の直しは `revise`**（image-slide の ADR 0012 と同じ）: `--page N [--slot 枠] --note …`、既定は微修正（今の絵を土台に）・`--remake` で作り直し・`--attach` で参考画像。
   前の絵は `images/history/` に写し、鍵は元のまま上書きする（次の deck も直した絵を使う）。直したら deck を組み直す。
   入口の名前は両方のエンジンで `--remake` にそろえた（image-slide は初め `--mode minor|remake` だったが、html-slide の `--mode`（talk・handout）とぶつかった）
7. **画風は資料全体で1つ: `--image-look photo|illustration|handdrawn`。** 省けばスタイルの `image_look`（standard は illustration・visual は photo）。
   prompt には「何を描くか」だけを書き、画風はエンジンが足す。illustration・handdrawn は色をテーマの主役の色と差し色に寄せる（写真は寄せない）。
   変えると鍵が変わり、生成の枠だけ描き直す。前の画風の絵は残るので、戻すときは描かない。**image-slide にも同じ3語・同じ言い回しで入れた**（指定したときだけ、スタイルの節に「絵の部分の画風」を1行足す）
8. **生成した絵に「イメージ」などの印の文字は入れない**
9. **キャラはページの `_characters`（image-slide と同じ書き方）。そのページの最初の生成の枠に参照画像として添える。** 生成の枠が無いページには描かない（警告）。
   透過は白に合成して渡す。参照画像は合わせて5枚まで
10. **Codex の呼び方は image-slide の `codex_run.py` を写す**（共通の部品に切り出さない。型の定義と同じく、写してテストで見比べる。違いは名前の image-slide → html-slide だけ）。
    絵の形（横長・縦長・正方形と比）を渡せるようにし、image-slide 側は既定の「landscape 16:9」のまま（描く指示は昨日と1字も変わらないことを確かめた）

## 理由

- **叩き台に絵が無いと、冊子の形が見えない。** 灰色の仮の枠で返すと、人が絵を想像して読むことになる。最初から絵を入れて返し、直すところだけ直す（差し替え・微修正）
- **Codex は道具でスキルではない。** エンジンはほかのスキルを呼ばない、という決まりは崩れない（image-slide も Codex を直に呼ぶ）
- **画風を prompt に書かせない。** 書く側がページごとに言い方を変えると、資料の中で絵の調子がばらつく。エンジンが足せば必ずそろい、切り替えも1つの引数で済む
- **字体は画風と別。** 手書き風の字体はテーマの `font` の持ち物で、台本は変わらない（PPTX は字体を埋め込めないので、入っていない PC では置き換わる）

## 確かめたこと（2026-10-07）

visual・10枚の叩き台（画像の枠9つ・1ページにキャラ）で:

- 9枠を並列で描いて PPTX まで 1分34秒（rc=0・verify OK）
- 1枚を持ち込みの写真に差し替え: Codex を呼ばずに約10秒で組み直した
- 1枚を微修正（窓の明かりを消して、屋根の上に満月）: 描いたのはその1枚・約53秒。部屋・机・空の色は保ち、明かりが消えて月が出た
- 同じ台本を `--image-look handdrawn` でも組めた

## 見送ったこと

- 置き方を型ごとに決めてキャラの立ち絵を貼る形（standard・handout 向け）。生成の枠に描き込む方が紙面となじむので、要るとわかったら足す
- 「あの資料」の PPTX・PDF から写真を抜き出す道具（呼ぶ側の仕事）
- キャラが多いときに1枚の画像にまとめて渡す形（参照画像の枚数を節約できる）。2人を横に並べた1枚で試し、別々に渡すのと差は見えなかった（image-slide の ADR 0011 の見送りに結果）。今は要らない。5枚を超える場面が出たら、両方のエンジンで「超えたときだけまとめる」形で入れる（入れる前に3人以上で試す）
