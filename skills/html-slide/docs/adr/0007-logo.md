# 0007 ロゴは右下の固定の枠に縮めて収め、そのページの地の色で地を敷く。写真がかかれば左下、両方だめなら置かない

- 日付: 2026-10-05
- 状態: 採用（角の選び方は [ADR 0008](0008-logo-position.md) で広げた）
- 比べた案: 幅の割合で大きさを決めて右下に固定し、角まで白く塗る案／幅の割合で決めて四隅から選び、塗らない案／
  固定の枠（329×44）に縮めて収めて右寄せにする案（quick-slide の `placement.py`）

## 決めたこと

1. 受け口は `deck --logo <PNG か JPEG>`。台本には書かない（image-slide と同じく引数。台本に足すと片方のエンジンで止まる）
2. 大きさは **329×44 の固定の枠に縦横比を保って収める**（quick-slide と同じ寸法）。縮めるだけで引き伸ばさない。透明な余白は切ってから収める。短辺が 30px 未満なら警告
3. 位置は右下。右は本文の余白（120px）、縦は下の文字の行の中心。ページ番号はロゴの左へ寄せる
4. ロゴの後ろに**ロゴと同じ大きさの地**を敷く（PPTX では別の部品 `!!logo-plate`）。色は、組んだ HTML を Chrome で開いて測る、ロゴの周り 16px で一番多い色（`scripts/logo_ground.mjs`）
5. 右下に写真・絵（`<img>`）か文字がかかるページは**左下**に置き、そのページの左半分の文字の左端にそろえる。左下もふさがれば**置かない**
6. 左下のロゴは別の名前（`!!logo-left`）。同じ名前だとモーフで右下へ滑る

## 理由

- 幅で決めると、正方形に近いロゴが大きくなりすぎる（幅の割合で決める形では、正方形に近いロゴが 230×141・画面の高さの 13% になった）。高さに上限を置けば形が違ってもそろう
- 地をテーマの地の色で塗ると、地の色が違うページ（主張の全面・章扉・表紙の面）で四角が浮いた（2026-10-05 の見本で確認）。型ごとに色を書き分けると、型23種とカスタムのスタイルに追いつかない。組んだ結果を測れば、どの型でも同じ規則で済む
- 写真の上に地を敷くと四角が浮き、敷かなければ写真によってはロゴが読めない。写真は色ではなく要素で判定する（まだらな色の判定より確か）

## 見送ったこと

- 暗い地での白いロゴの差し替え（quick-slide の `LOGO_VARIANTS` の考え方）。既定の色の visual の締め（`#097ea9`）では黒いロゴが弱いが、いったん今のままにした
- 全面の絵の上でも、地が平らな所なら置く形
- 四隅を選ぶ引数（→ [ADR 0008](0008-logo-position.md) で右下・左下・右上の3つから選べるようにした）

## その後

- 2026-10-06: image-slide も同じ規則にした（image-slide の [ADR 0008](../../../image-slide/docs/adr/0008-logo-same-rules-as-html-slide.md)）。要素が無いので「写真・文字がかかるか」を「周りが1色か」で見る。数字はテストで突き合わせている
- 2026-11-18: **地の上でロゴが読めるかを見るようにした。** 既定の見た目に、ほぼ黒の面（締め・主張）と主役の色の面（表紙・章扉）が入り（[ADR 0029](0029-design-direction-per-deck.md)）、黒いロゴが暗い面に沈むページが出たため。「見送ったこと」の白いロゴの差し替えを入れた
  - ロゴの明るさ（不透明な画素の相対輝度の中央値）と、測った地の色のコントラスト比が 3.0 以上なら今までどおり（地は同じ色で、見えない）
  - 読めなければ、白いロゴ（`--logo-white`。縦横比が 2% 以内で合うもの）で読めるならそのページだけ替える。無ければ、ロゴの周りに 12px の余白をとった角丸の地（白か黒の読める方）を敷く
  - 判定の値・測り方は image-slide（`layout.LOGO_CONTRAST`・`compose._logo_lum`）と同じ。サーバは、プレゼンにもブランドの白いロゴを渡す
  - 却下: 暗い面ではロゴを置かない（どの資料のロゴかが締めのページで消える）／いつも白い地を敷く（明るい主役の色の表紙で四角が浮く）
  - 余白つきの地の帯（12px）に絵・文字・透かしがかかるページと、帯がページの外へ出る角では、余白をとらず角も丸めない（置き場の検査はロゴの枠で行うので、広げた帯がほかの中身を覆わない・はみ出さないようにする）
  - 透けている所がほとんど無いロゴ（余白を切った範囲の内側のうち、透けている画素が 2% 未満。外周は数えない）は、自分の地を持つとみなし、明るさを測らずそのまま置く（明るさの中央値が、ロゴではなく画像の地の色になるため。縁の数画素だけ半透明な画像で扱いが切り替わらないよう、割合で見る）。べた塗りの暗い形だけのロゴは暗い面で沈むが、見分けられないので割り切った。全部が透明な画像は止める
  - サーバの「白いロゴの縦横比がロゴと合うか」は、エンジンと同じく、透明な余白を切った大きさで比べる
  - 残した制約: 不透明な画素が 1 つも無い、ごく薄い線だけのロゴ（不透明度 20% ほど）は、線の色だけで「読める」と判定する（地に重ねた結果の明るさでは見ていない）。暗い面で薄く見えても、白いロゴに替えず、地も敷かない。当てはまるロゴは稀なので、要る資料が出てから直す（image-slide も同じ）
