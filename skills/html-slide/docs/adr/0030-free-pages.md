# 0030 自由なページ（枠はエンジン・真ん中は書く側）

- 日付: 2026-11-18
- 状態: 案（設計のレビュー前。実装していない）
- 関係: [0029](0029-design-direction-per-deck.md)（見た目の方針を型に足す）・[0001](0001-html-contract.md)（HTML の決まり）・[0025](0025-import-pptx.md)（取り込んだページの型 `html`）

## 背景

0029 で既定の見た目を直したあとも、「そのページの中身に合わせた形」は型では出せなかった（割合を 100 マスの塗り分けで見せる・料金の数字を主役にする・時間帯ごとの埋まり具合を並べる、など）。型は中身の種類を描き、どこが数字でどこが名前かを知らないためである。

試しに、取り込んだページ用の型 `html`（HTML をそのまま通す）を借り、「色・文字の大きさ・余白の決まりだけを 1 枚の文書で渡し、真ん中は書く側が自由に組む」作り方で、架空の原稿 2 本（8 枚ずつ）と、表と構成図を含む 14 枚の資料 1 本を作らせた。

| | 結果 |
|---|---|
| 通るまで | 架空の 2 本は 1 回目で全ページが通った。14 枚の資料は 1 回目に文字のはみ出しの警告が 2 件出て、直して通った（どれも、そのあと見た目の直しで 3〜5 回描き直した） |
| 見た目 | その場で設計する作り方と同じ水準の形が出た。色はテーマの変数だけを使うので、ブランドの色に従う |
| 原稿 | 「原稿に無い数を足さない」と決まりに書くと、足さなかった |
| PPTX | 書き出せた。全部が図形と文字の部品（画像は無い）。別の表計算・文書ソフトで開いても、ほぼ同じ位置に出た |
| グラフ・表・構成図 | 書く側は、折れ線・表・構成図では型を選んだ（軸・凡例・色つきのセル・矢印を手で組むより確か）。14 枚の資料では 9 枚が自由・5 枚が型になった |

足りなかった所も出た。

1. 下の文字（footer）・ページ番号が、自由なページに出ない（書く側が手で置いてそろえた）
2. 見出しの大きさと位置が、型のページとずれる（型は 1 行の見出しを 80 にする。中身の始まる高さも違う）
3. 見出しが 1 行か 2 行かが、描くまで分からない（中身を置く高さが決まらない）
4. はみ出しが警告止まりで、PPTX を書く経路でしか出ない（取り込んだページ用に緩めてあるため）
5. 100 個のマスが、PPTX で 100 個のばらばらの部品になる
6. 棒の長さを手で計算して丸め、比がずれた
7. アイコンの形（SVG）を、書く側がエンジンのコードを呼んで取り出していた
8. 英字と全角が混ざる見出しは、字数の目安では 1 行に入るかが分からなかった（書く側が改行を決め打ちした）
9. 表紙・章扉まで自由に組ませると、下の文字を置くかどうかがページごとにぶれた
10. 良い・悪いの色を、札の地（白い文字を載せる面）に使ってよいかが決まっていなかった

## 決めること（案）

### 1. 型 `free` を足す。枠はエンジンが描き、書く側は真ん中だけを書く

```json
{"type": "free", "kicker": "課題", "headline": "荷物の 5個に1個は、1回で届いていない",
 "body": "<div class=\"f-row\">…</div>", "source": "…", "talk": ["…"]}
```

- 見出し（kicker・headline・sub）・出典・下の文字・ページ番号・ロゴ・透かしは、ほかの型と同じ部品でエンジンが置く（大きさも位置も型のページと同じになる）
- `body` は、エンジンが用意する **中身の箱**（左右は本文の幅 1680、上は見出しの下、下は中身の下端）の中に置く。箱の大きさは見出しの行数で決まる
- 書く側は箱の中を **flex で割って組む**（ページの左上からの絶対の座標は書かない）。箱の高さが 1 行ぶん変わっても崩れない
- 表紙・章扉・締め・表・グラフ・構成図は、今までどおり型を使う。`free` は「中身の型」の 1 つ（表紙・章扉を自由に組ませない。試しでは、下の文字とロゴの扱いがページごとにぶれた）
- 見出しは型のページと同じ決まりで組む（1 行に入れば 80、入らなければ 64 から。書く側は字数を数えない）。中身の箱の高さはエンジンが決め、書く側は知らなくてよい

`html`（取り込んだページ）は今のまま残す。`free` とは検査の厳しさが違う（下の 3.）。

### 2. 書く側に渡すのは「使ってよい値」と「部品」

文章で好みを伝えるのではなく、検査できる形で渡す。`references/deck-format.md` に「自由なページ」の節として書く。

| 何 | 決まり |
|---|---|
| 色 | CSS 変数だけ（`--bg`・`--ink`・`--muted`・`--primary-soft`・`--primary-fill`／`--on-primary-fill`・`--accent-fill`／`--on-accent-fill`・`--deep`／`--on-deep`／`--deep-pop`・`--primary-text`・`--accent-text`・意味の色）。色の直書きは rc=2。意味の色（良い・悪い・注意）は、面の箱の class（`f-box good`・`bad`・`warn`）と札で使う。面と文字の組はエンジンが決める（書く側が、意味の色の面に文字の色を合わせない） |
| 文字の大きさ | 文字の段だけ（本文 28 以上・注記 22 以上）。段の外は rc=2 |
| 余白・大きさ | 8 の倍数（警告） |
| 使えない CSS | HTML の決まりの「止めるもの」と同じ |
| 高さ | 中身の箱を使い切る（下の 3. の検査） |
| 原稿 | 原稿に無い数・言葉を足さない（図にするのは原稿にある数だけ） |

部品は、雛形の class と、エンジンが展開する短い書き方で用意する。

| 部品 | 書き方 | 何になるか |
|---|---|---|
| 面の箱 | `class="f-box"`（淡い面）・`f-box fill`（主役の色）・`f-box deep`（ほぼ黒）・`f-box accent` | 地の色・角・内側の余白・その上の文字の色がそろう箱 |
| 並び | `class="f-row"`・`f-col`（間は 8 の倍数の段） | flex の行・列 |
| アイコン | `<icon name="users" size="56"/>`・丸つきは `<icon name="users" disc/>` | 図形のアイコン（置いた面に合う色） |
| 割合のマス | `<cells total="100" on="21" cols="10"/>` | マスの塗り分け（数から作る。PPTX では 1 つのグループ） |
| 棒 | `<bar value="21" max="21" label="21%"/>` | 数に比例した長さの棒（丸めない） |
| 札・番号 | `class="f-chip"`・`f-no` | 札・番号の丸 |
| まとまり | `data-group="名前"` | PPTX でグループにする |

部品は最小から始め、自由なページでよく出る形が見つかったら足す（または型に昇格させる）。

### 3. 検査は、取り込んだページより厳しくする

- はみ出し・ページの外は **誤り**（rc=2）。画像だけ描く経路でも止める
- **文字の色と、その下の地の色の比を、ブラウザが計算した色で測る**（4.5:1 未満は誤り）。色の面の上に通常面用の色が残る誤りを、規則の並びではなく結果で拾う。この検査は型のページにも掛ける（0029 の査読で残った提案）
- **下の空き**: 中身の箱の高さに対して、中身が使っている高さが 8 割に届かなければ警告
- クリックの段と `talk` の数の照合は、型と同じ（`body` の中の `data-step` を数える）

### 4. 画面からの直し方（サーバ側。別の ADR に分ける）

| 直し | 道 |
|---|---|
| 文字 | 取り込んだページと同じ道を使う（文字に番号を振り、番号ごとの直した文字だけを受け取って差し替える。はみ出したら書き直させる） |
| 図解・組み替え | そのページの `body` を、書く側に書き直させる（見出し・出典は変えない） |
| 挿絵・画像 | 次の段階（下の「見送ること」） |

台本係への決まりは、今と同じく `deck-format.md` から渡る。

### 5. 段階

1. エンジン: 型 `free`・部品の展開・検査・文書・見本・試験（この ADR の範囲）
2. サーバ: 台本係の指示（型と自由の使い分け）・直し・検品の言葉（リポ直下の ADR）
3. 自由なページの中の絵の枠（生成・挿絵）と、絵の上に名前の札を重ねる図解

## 理由

- 型だけでは、中身に合わせた形が出ない。型を足し続けても、新しい中身のたびに足りない形が出る
- 取り込んだページの型をそのまま使うと、見出し・下の文字が型のページとそろわず、検査も緩い
- 枠と部品をエンジンが持てば、色・字・余白・検査・PPTX への写しは今までどおり守れる。書く側の自由は「箱の中の組み」に限られる
- 絶対の座標を書かせると、見出しの行数や文字の長さが変わるたびに崩れる。箱の中を flex で割れば、直しにも強い

## 却下・見送ること

| 案 | 理由 |
|---|---|
| 型を全部やめて、全ページを自由にする | グラフ・表は手で組むと遅く、間違えやすい（試しでも書く側が型を選んだ）。弱い書き手の回で出来が落ちる |
| 取り込んだページの型 `html` を、そのまま台本係に開ける | 枠がそろわない・検査が緩い・絶対の座標になる |
| 書く側に文章の指針だけを渡す | 検査できない。書き手のモデルしだいになる |
| 絵の枠（生成・挿絵）を最初から入れる | 置き場と直し方の設計が増える。枠と検査が固まってから |
| 部品を最初から多く用意する | 使われない部品の保守が増える。試しで出た形から足す |

## 確かめること（実装の前に）

- 実題材（14 枚・表と構成図を含む）で同じ試しをし、PowerPoint で開いて、部品として直せるか・グループの扱いを人が見る
- 書き手を替えて（弱いモデルで）同じ決まりを渡し、どこまで通るか
- 箱の中を flex で組む書き方で、試しの 2 本と同じ形が出せるか（試しは絶対の座標で書いた）
