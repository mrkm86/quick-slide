# 0028 レビューモード（review）: deck と同じ HTML・CSS を外枠で包み、止まらずに全ページを描く

- 日付: 2026-10-23
- 状態: 採用（初版の範囲）

## 背景

台本を 1 ページずつ詰めるとき、PDF を毎回作るより、ブラウザで全ページを並べて見ながら直すほうが速い。
ただ、その画面をエンジンの外で別の HTML として作ると、PDF の見た目とずれ、ずれを直す手間が増える。
また deck は最初の誤りで止まるので、1 ページの誤りで残りのページが見えなくなる。

## 決めたこと（初版の範囲）

### 入れるもの

- `html_slide.py review --script 台本.json`: 全ページ・目次・メモ・検査結果を並べた `review.html` を出す。deck の成果物は上書きしない
- スライドは deck と同じ section・CSS・素材で描く（`templates/deck.html` が正本。review 用に型やスライドの CSS を複製しない）。
  review のスライドは固定寸法の `iframe srcdoc` に入れ、外枠だけを縮小する（外側の CSS をスライドへ入れないため）
- `review.html` は 1 枚で完結させない。deck.html と同じ参照にする。画像は出力フォルダの `assets/`（相対パス）、
  字体は生成した機械のファイル（絶対の file URL）。字体を data URL で埋め込むと重くなるため。フォルダごと動かせば画像は付いてくるが、
  字体は付いてこない（別の機械では字体を用意して作り直す。説明書に書く）
- ページ直下の `_memo`（メモ・文字列）・`_wish`（見せ方の希望・文字列）・`_ok`（真偽値。`true` なら初期状態で畳む）を読む。
  メモと希望は読み取り専用の本文として、改行を保って出す（HTML の上では編集しない）
- `--wishes [PATH]`: 全ページの希望を台本順に Markdown で書き出す（希望のないページは「希望なし」）
- `--watch`: 台本のバイト列のハッシュが変わったら作り直す。表示の更新はブラウザの再読み込み。保存途中の壊れた JSON は直前の出力を保って続ける
- 止まらずに描く: ページ単位の誤り（型・設定・検査）は、そのページに理由を出して残りを描く。終了コードは、誤りがあれば HTML を書き終えてから返す
- `_ok` のページも検査は行う（OK は検査の免除ではない）。畳んだ見出しにも検査の件数を残す
- 画像生成は呼ばない。未生成の画像は仮枠のまま描き、そのページに「画像未生成」を出す

### 入れないもの

- HTML 上での編集、OK のサーバへの送り返し（OK は台本に書く）
- 希望に基づくエンジンの自動変更。「希望を書けばエンジンが更新される」とは書かない
- 自動リロードや HTTP サーバ（`--watch` は再生成だけ）
- 大量ページで重い場合の工夫（初版は同一性を優先し、サイズの工夫はしない）
- 画像生成の前後で見た目が一致することの保証（同じ素材・設定で描けるページの一致だけを保証する）
- 常駐サーバ・image-slide への組み込み（台本のキーを受け渡すだけ。保存の保証は初版に含めない）

### `_` で始まるキーの予約（ページ直下だけ）

| 用途 | 名前 | 扱い |
|---|---|---|
| レビューの注記 | `_memo`・`_wish`・`_ok` | review が読む。deck は読まず、出力も変わらない |
| 利用者の指定 | `_characters` | 既存どおり（画像の指定） |
| エンジンの内部 | `_auto_number`・`_motif_seed` | 既存どおり。注記として表示しない |

- 新しい内部用のキーは `_engine_` から始める。レビュー用の 3 名を内部の処理に使わない
- 未知の `_` キーを一律に禁止する変更は入れない（いまの「`_` は未知キーの検査から外れる」を保つ）
- 型が誤っている注記（`_ok` が真偽値でない等）は、そのページの検査結果として出し、スライドの描画は続ける

## 理由

- deck の組み方を共通にすれば、「review と PDF が同じ見た目」は作りで保たれ、ずれを後から直さずに済む
- 止まらない作りにするのは review だけ。deck の「最初の誤りで止まる」は変えない（配る前の関門だから）
- 注記を台本に置けば、正本が台本のままで、版の履歴・差分も台本で追える

## 却下した案

| 案 | 却下の理由 |
|---|---|
| deck とは別実装の HTML でレビュー画面を作る | PDF の見た目とずれ、ずれを直すたびに型ごとの二重の保守になる（Issue の背景そのもの） |
| スライドを画像（PNG）にして並べるだけの review | 検査結果を対象の要素に結び付けられず、折り返し・はみ出しを文字で確かめられない。撮る時間もかかる |
| `deck` に「止まらない」オプションを付けて兼用する | deck の関門（最初の誤りで止まる）の意味が薄れる。共通にするのはページの組み立てだけにして、止める・止めないは呼ぶ側で決める |
| ページごとに台本を分けて `build_html` を何度も呼ぶ | ページ番号・章番号・図柄の種が台本全体の順で決まるため、分けるとずれる |
| `_ok` のページは検査もしない | 後から直した別ページの影響で壊れたとき、畳んだままで見落とす |
| 字体・画像を data URL で埋め込んで 1 枚で完結させる | 字体が重く、ページ数分の素材が膨らむ。初版は deck.html と同じ参照にする |
| `_` で始まるキーを全部予約して未知を禁止する | 既存の台本を壊す。ページ直下の既知の名前だけを決めれば足りる |
