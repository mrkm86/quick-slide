# 0019 図解の型（式・放射・対）・線のアイコン・締めの帯を足す

- 日付: 2026-10-09
- 状態: 採用

## 決めたこと

1. 型を3つ足す。どれも見出しを大きく出す（84px から。ほかの型は 60px のまま）
   - `equation`（式）: 要素 2〜4 を「＋」でつなぎ、「＝」の先に答え（`result`）。答えは主役の色で塗る。要素は1つずつ、答えは最後に出る
   - `hub`（放射）: 中心（`center`）の丸と、左右に分けた周り 3〜6 を線でつなぐ。周りは1クリックで出る
   - `pairs`（対）: よくない例 → よい例 を 2〜4 組（`label`・`before`・`after`）。4組は 2×2、2組は横に2つ、3組は縦に3つ
2. 線のアイコンを同梱する（`scripts/deck_icons.py`・45種）。`cards`・`bullets`・新しい3つの型の項目に `icon: "名前"` で添える。
   24×24 の升目に線の基本図形だけで描き、色はテーマの変数を style で渡す（PPTX では図形のまま・色はテーマに従う）
3. 中身の型に `takeaway`（結論の1行の帯）を足す。中身の下端の上に置き、中身はその分だけ上で止まる（`Slide.bottom`）。
   最後の段と一緒に出る（クリックは増やさない）
4. 台本の決まりの「書く前に」に 10. を足す: 箱の中は名詞と短い補足まで。言い切りは見出し、結論の1行は `takeaway`
5. 見た目の調子（スタイル）は増やさない。箱は `.card` を使うので、スタイルの look（白い箱と影など）がそのまま効く

## 理由

- 資料が冗長に見えた主な原因は、箱の中を文で埋めることと、目印（アイコン・結論の帯）が無いことだった。型の数より、組み方と文字量の差
- 構成要素・中心と周り・直し方は、カードや矢羽根で書くと「同格の並び」に見えてしまい、関係が伝わらない
- アイコンを画像にせず図形にするのは、文字と同じく PPTX で直せるようにするため（ADR 0001）

## 見送ったこと

- 全部の型の見出しを大きくすること。今の資料の見た目がまとめて変わるので、図解の型だけにして様子を見る
- 矢羽根（`flow`）へのアイコン。矢羽根の中は短い名札で、アイコンを入れる幅が無い
- アイコンを台本で自由に描かせること（SVG を台本に書く）。台本係の負担と、検査できない形が増える

## 追記（2026-10-10）アイコンを Material Symbols の塗りの図形に替えた

デジタル庁デザインシステムの素材（Material Symbols）に合わせるため、決めたことの 2. を次のとおり改める。

- 形は Material Symbols（Outlined・weight 400）の部分集合 100 種。実体は `skills/dads/icons/material-symbols.json`（取得元・版・対応表は同じフォルダの README.md）。
  ライセンスは Apache License 2.0（同じフォルダの `LICENSE-material-symbols.txt`）。名前は引き継いだ 45 種を変えず、55 種を足した。日本語の説明は `scripts/deck_icons.py` が 100 種すべてに持ち、`words()` が台本係に渡す一覧になる（`references/deck-format.md` の一覧と同じ文字列で、試験が一致を見る）
- 線（stroke）ではなく **塗りの図形**になった。色は style の fill で渡し、stroke は使わない。viewBox は `0 -960 960 960`
- PPTX への写し方: 曲線は折れ線に近似し（0.05px の許容で間引く）、1 つの path の部分パス（`M` で始まる区間）ごとに 1 つのサブパスとして、**1 つの自由形（1 つの `a:path`）に入れる**。穴は入れ子の部分パスで、PowerPoint の塗り（even-odd）でも向きの規則でも同じ形になる。
  サブパスの切れ目は、`M`・`m` の手前までの長さを測って区間を切って見つける（点の飛びでは、前の終わりの近くから始まる穴を取り違える）
- 見送ったこと: optical size 24 用の絵（取り込んだのは opsz 48 の絵だけ。24px に小さく置くと線がやや細く見える。スライドの大きさでは問題にならない）
