# 0019 全面に描かせたページでも、フッタ・ページ番号を載せる所は見る。読めなければ描き直し、直らなければ文字の後ろに地を敷く

- 日付: 2026-11-19
- 状態: 採用（ADR 0009 の 2「帯の検査・描き直し・帯の板は無い」を、フッタとページ番号の所だけ置き換える）
- 前提: visual（全面に描かせるスタイル・既定）の資料で、絵の中の帯や文字が下端まで描かれ、フッタ・ページ番号と重なって読めないページが続いた。
  試した 5 枚のうち 3 枚で重なり、前の月に作った資料にも同じ重なりがあった。「下端 7% に文字や図を置かない」と頼むだけでは守られない

## 決めたこと

1. 全面に描かせたページ（`bleed`）で、**フッタとページ番号を載せる枠だけ**を見る（`compose.chrome_check`）。帯の全体は見ない
2. 見るのは「重ねる文字が読めるか」。枠と周り 8px の中で、載せる文字の色（下の明るさで白かテーマの文字の色・`area_ink`）との
   コントラスト比が 3 に届かない画素が 2% を超えたら、読めないとする（絵の中の文字の端がかかるだけの重なりは 5% に届かなかった・実物で確認）（`layout.CHROME_CONTRAST`・`CHROME_MAX_SHARE`。ロゴと同じ 3）
3. 描いた直後に見て、読めなければ理由を添えて描き直す（帯の検査と同じ回数・`--retries`。`codex_run.Runner.RETRY_KINDS` の `chrome`）
4. 最後まで読めなければ、**その文字の後ろにだけ**角丸の地（テーマの地の色）を敷き、文字はテーマの文字の色にする。警告を出す。
   確認用の絵と PDF には焼き、PPTX では「フッタの地」「ページ番号の地」という部品にする（文字より下）。帯いっぱいの板は敷かない
5. **前に描いた絵は描き直さない。** 使い回す絵（鍵が同じ）・`--keep` の絵・`revise` の対象でないページは、読めなくても描かずに、
   仕上げで文字の後ろに地を敷く（帯の検査と同じ扱い）。一度見せた絵を、頼まれていないのに別の絵に替えないため。
   描き直したいページは `--redo` か直しで指定する
6. 枠の位置は、描いた直後の検査も仕上げも同じ計算（`image_slide.bottom_row`）。ロゴが指定の角から別の角へ移るとフッタの位置が変わるので、
   検査の前にロゴの置き場まで決める。字体のファイルが無い機械では、文字の幅を 1 文字＝文字の高さで広めに見積もる（`compose.text_width`）
7. 記録: `build.json` の各ページに `chrome`（検査の結果）と `text_plates`（地を敷いた枠）。検品用の写しは、帯を頼んだページと
   全面のページで行を分け、見ていないものを「空いていた」と書かない

## 理由

- **全面の絵は残す。** ADR 0009 で帯をやめたのは、白い帯が全面の絵の良さを消すから。そこは変えない。見る所を文字の枠だけに絞れば、
  写真や背景が下端まで続いていても通る
- **「物があるか」でなく「読めるか」で見る。** 代表色から離れた画素の割合（帯の検査の見方）だと、淡い波の飾りのように、
  文字は読めるのに描き直しになる絵があった（実物で確認）。描き直しは 1 枚に 1 分ほどかかるので、読めるものは通す
- **直らなければ地を敷く。** ロゴは ADR 0009 でステッカーを敷いて読めるようにしている。フッタとページ番号にも同じ手当てをする。
  資料が出ないより、小さな地で読めるほうがよい

## 見送ったこと

- 帯の全体に物が描かれていないかを見ること（絵の中の帯の文が下端に寄っていても、フッタと番号が読めれば通る）
- 透かし（中央下の端）の下を見ること（ADR 0010 のとおり、色は固定で下は測らない）
- 表紙・章扉・写真のページ（フッタもページ番号も載せない）
- 字体のファイルが無い機械で、確認用の絵と PDF の文字が PIL の小さな既定の字体になること（前からの動き。PPTX はテーマの字体で置く。
  検査の枠と地は広めに取るので、PPTX の文字は地からはみ出さない）
