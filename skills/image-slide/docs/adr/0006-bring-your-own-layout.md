# 0006 レイアウトはユーザーが持ち込める（--layout）

> 追記（2026-10-05）: レイアウトのファイルの `style` は [0007](0007-styles-standard-visual-custom.md) でカスタムスタイル（`--style`）に分けた。

- 日付: 2026-10-05
- 状態: 採用
- 問い: 0005 でレイアウトの層をやめたが、週報・月報のように型（上にヘッダ、ロゴ…）が決まっている資料は、その型をはめ込みたい。新しい言葉は足さず、どの層に足したのかが分かる形にする

## 決めたこと

1. **製品はレイアウトを持たない（0005 のまま）。ユーザーが自分のレイアウトをファイルで持ち込める。** 引数は `--layout <yaml>`（何度でも）、ページは `_layout` で名前を書く。言葉は「レイアウト」にそろえ、新しい言葉は足さない
2. レイアウトのファイル（`scripts/layouts.py` の冒頭に書式）: `name`・`composition`（構図の文章・必須）・`style`（このレイアウトの作風・`--style-base` より優先）・`reference`（構図の見本の絵）・`parts`（台本の型のキーに無い部品の置き場）
3. ページの `_layout` は名前だけか `{name, parts}`。`parts` に部品の文字を書く（週バッジ・学び・チームの近況の欄など）。書いた文字は一字一句描かせ、`inspect.md` にも写す
4. `_layout` の無いページは、これまでどおり構図を Codex に任せる。渡していない名前・無い部品は rc=2
5. 構図の見本は参照画像として添える（並びは このページの画像の枠 → 構図の見本 → `--ref`。合わせて4枚まで）。見本の中身（文字・数字・絵）は写さないよう指示する
6. レイアウトのファイルは**エンジンの外**に置く（呼ぶ側のスキル・自分のフォルダ・将来は quick-slide v2 の DB）。ストーリーと同じく使う側の持ち物で、ユーザーが自由に足せる

## 試したこと（2026-10-05・実際の週報の材料・本物の Codex）

固定の週報のレイアウトを文章にした `weekly-report.yaml` を作り、2通りで描いた。

| | 結果 |
|---|---|
| ① レイアウトのファイルだけ | ヘッダ・キーワード・4段の流れ・学びの帯・チームの近況の4段の型に収まった。近況のサマリが途中で切れ、テーマに誤字が1つ |
| ② ①＋構図の見本（別の週の絵） | 実物にかなり近い。近況が最後まで描け、ヘッダの部品の形も見本に寄った |

- どちらも、キャラのアイコンが指定と違う犬になった（`icon_hint` で犬種と色を書いても効かなかった）
- ②は下端の帯に近況がはみ出し、地の色の板を敷いた。週報はロゴを右下だけに置ければよく、帯で全幅を空けさせる必要が無い。ロゴ・帯の置き場を選べるようにするのはフォーマットの話なので、そこで扱う

## 却下した案

| 案 | 却下の理由 |
|---|---|
| 製品のレイアウトの棚に週報を足す | 週報は使う組織ごとの資料の形で、製品の持ち物ではない |
| `--custom-layout` など別の名前にする | 製品のレイアウトはもう無いので「custom」で区別する相手がいない。`--layout` で足りる |
| 部品を台本の一番外に書く | html-slide で知らないキーとして止まる。ページの `_layout` の中なら html-slide は読み飛ばす |
