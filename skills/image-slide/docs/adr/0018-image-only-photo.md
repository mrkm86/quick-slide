# 0018 photo の全面の hide_text を受け、画像だけの絵を描く

- 日付: 2026-10-15
- 状態: 採用

## 背景

html-slide が `photo` の `layout: full` に `hide_text: true`（画像だけの扉絵）を足した（html-slide の ADR 0026）。
image-slide の受け口はこのキーを知らず、`hide_text` を書いた台本は「知らないキー」で rc=2 になった。
同じ台本を両方のエンジンが受ける約束（ADR 0001）が崩れ、型のキーを見比べる試験も落ちていた。

## 決めたこと

- `photo` のキーに `hide_text` を足す。止める所は html-slide と同じ: 真偽でない・`layout: full`（既定）以外で true
- true のページは、`kicker`・`headline`・`body` を「描く文字」から外し、「画像だけの扉絵: 絵を全面に描く。文字・幕・枠を
  描かない。`caption` があるときだけ出典として右下に小さく」と言い切る（`prompt.IMAGE_ONLY`）。`headline` は
  html-slide と同じく必須で、ページの名前（文脈の一覧・PPTX の代替テキスト）として持つ
- 1枚に凝縮するスタイル（infographic など）では、その区画を「絵だけ」にする（`prompt.IMAGE_ONLY_SECTION`）
- `hide_text` は配置の指定（`LAYOUT_KEYS`）に入れない。`false` を書いても書かなくても描く指示は同じで、鍵も変わらない
- 言葉を足しただけで、ほかのページの指示は変わらないので `PROMPT_VERSION` は上げない

## 理由

- 同じ台本が、どちらのエンジンでも同じ意味になる（文字の無い扉絵）。読み飛ばすだけだと、プレゼンでは文字が無いのに
  ピッチでは見出しが描かれ、企画（台本）を変えずに描き方だけを選ぶ、が成り立たない
- 見出しを描く文字に残したまま「描かない」と言うより、渡さない方が確実（描く文字は一字一句描け、と言っているため）

## 却下した案

| 案 | 却下の理由 |
|---|---|
| キーを受けて読み飛ばす（見出しは描く） | 同じ台本で、エンジンによって見出しの有無が変わる |
| 型を見比べる試験から `hide_text` を除く | 片方のエンジンだけで通る台本ができる（ADR 0001 の「知らないキーは止める」） |
| 配置の指定として渡し、`LAYOUT_WORDS` に意味を足す | `LAYOUT_WORDS` は配置の指定のある全ページに入るので、言葉を足すとそれらが全部描き直しになる |
