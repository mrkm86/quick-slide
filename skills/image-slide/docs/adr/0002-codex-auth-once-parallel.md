# 0002 Codex の認証は1度だけ確かめ、隔離ホームで並列に描く

- 日付: 2026-10-03
- 状態: 採用（2026-10-06 に追記）

## 決めたこと

1. 画像は Codex CLI の組み込みの画像生成（gpt-image-2・ChatGPT のサブスク枠）で描く。`OPENAI_API_KEY`・`CODEX_API_KEY` は codex に渡さない。API キーのログインの `auth.json` は断る
2. **認証の確認は1回の実行で1度だけ**（`codex_run.check_auth`）: `auth.json` の有無・ChatGPT のログイン・`codex login status`・トークンの新しさ。トークンが古いとき（最後の更新から7日以上・期限まで3時間未満）だけ、**実ホームで1回・直列に** codex を走らせて更新させる。使い回しだけで済む実行では、認証の確認もしない
3. 確認した `auth.json` の中身を1度だけ読み、**各ワーカーにコピーを渡す**。ワーカーは使い捨ての隔離ホーム（コピーの `auth.json`・最小の `config.toml`）と空の作業フォルダで `codex exec -s read-only` を1回だけ走らせ、`<隔離ホーム>/generated_images/` から絵を拾い、隔離ホームごと消す
4. 並列は ThreadPoolExecutor（中身は子プロセス）。既定8本（設定の `max_parallel`・`--parallel`）。サブスク枠は画像で減りが速いので、それ以上は上げない
5. 失効の文言（`token_revoked` など）が出たら、**残りを止めて rc=4**。枠切れ（429・usage limit）は全ワーカーを一緒に待たせる。待ちが15分を超えるなら止めて rc=1
6. 描いた絵は鍵（描く指示と参照画像のハッシュ）と一緒に `raw/` に残す。止まっても、もう一度流せば残りだけを描く

## 理由

- ワーカーが同じ `auth.json` を共有すると、トークンの更新のときに使い捨ての refresh token を奪い合い、失効する。コピーなら実ホームは壊れない
- ただしコピーの中で更新が走ると、実ホームのトークンが古くなる。だから**配る前に**新しくしておく。隔離ホームの中で温めて（warmup）そのコピーを配るやり方だと、実ホームが古いトークンのまま残る。こちらは実ホームで1回だけ更新させ、実ホームを正にする
- codex は最後の更新から8日でトークンを更新しに行く（2026-10-03 の実ホーム: 最後の更新から4日・アクセストークンの期限は10日）。7日を境にすれば、ワーカーの中で更新は起きない見込み。起きたら（コピーが書き換わったら）数えて警告する
- `-s read-only` と空の作業フォルダ: 画像の生成は codex が自分のホームに保存するので、書き込みの許可は要らない（2026-10-03 に実測: 38秒・1672×941）。画像を描く以外のことをさせない
- 実ホームの `config.toml` を持ち込まない: プラグイン・フック・MCP の起動が重く、ほかの作業に引きずられる。`--skip-git-repo-check` と空の作業フォルダで足りる

## 却下した案

| 案 | 却下の理由 |
|---|---|
| ワーカーごとに `codex login status` を叩く（quick-slide の初期） | ログインの確認が並列に走る。quick-slide も後で「同時に始まる一群で1回にまとめる」に直した |
| 実ホームのまま並列に走らせる | 生成物の取り違え（同時に描いた絵を互いに拾う）と、トークンの奪い合い |
| `codex app-server` を常駐させる | 1プロセスで並列に描けるかが確かめられていない。experimental の扱い |
| 毎回 warmup（隔離ホームで温めてから配る） | 上の理由（実ホームが古いまま残る）。新しいうちは何もしないほうが安い |

## 追記（2026-10-06）: 「古い」は期限だけで決める

codex-cli 0.159.2 は、期限が読めるアクセストークンを**期限の5分前まで更新しない**（`should_refresh_proactively`・
openai/codex `codex-rs/login/src/auth/manager.rs:3004-3026`・`CHATGPT_ACCESS_TOKEN_REFRESH_WINDOW_MINUTES = 5`）。
最後の更新から8日（`TOKEN_REFRESH_INTERVAL`）は、期限が読めないときの予備でしかない。

前は「最後の更新から7日以上」でも古いとして実ホームで1回走らせていたが、codex は更新しないので、7日目から期限まで
（実測では残り約3日）毎回 rc=4 で止まった（2026-10-06 に発覚）。

- 期限が読めれば、期限まで `MIN_LEFT_HOURS`（3時間）より長いかだけで決める。日数は見ない
- 期限が読めないトークンだけ、最後の更新から `REFRESH_DAYS`（7日）を予備に使う
- 期限まで3時間を切ったら、実ホームで1回走らせても codex はまだ更新しないので rc=4 のまま。案内に「codex は期限の5分前まで自分では更新しない。
  `codex login` で入り直す」と書いた
