# 0013 出力は PPTX・PDF・ページの画像・サムネイルの4つ（html-slide と同じ --format）

- 日付: 2026-10-07
- 状態: 採用
- 前提: html-slide の ADR 0012 と同じ議論・同じ判断（クリップボードを入れない理由はそちら）
- 前の形: PPTX・PDF・`slides/slide-NN.png`（確認用の扱い）。PDF を外す `--no-pdf` だけがあった

## 決めたこと

1. **出力は html-slide と同じ4つ・同じ入口: `--format pptx,pdf,png,thumbs`**（省けば4つとも）。`--format` の読み方とサムネイルは `scripts/outputs.py`（html-slide と同じファイル。テストがバイト単位で見比べる）。
   前の `--no-pdf` は残す（`--format` から pdf を外すのと同じ）。revise も同じ `--format` を受ける
2. **ページの画像（`slides/`）はどの指定でも残す。** PDF と検品（inspect.md と一緒に検品する側へ渡す絵）の元なので。`--format png` は「PPTX・PDF・サムネイルを作らない」の意味になる
3. PDF は今までどおり、ページの画像を並べたもの（13.333×7.5 インチ・144dpi）。文字は絵の中なので選べない
4. サムネイルの見出しは、各ページの代替テキストと同じ（`script_io.headline_of`。ポスターは資料の題）
5. ページを減らしたら、前の回の余ったページの画像は消す。PPTX を作らなかった回の inspect.md は「PPTX: 作っていない」と書く

## 理由

- 2つのエンジンを同じ台本・同じ出力で使い分ける（ADR 0001）。呼ぶ側が出力の名前と置き場を覚え分けなくてよい
- 描く時間が大半なので、`--format png` でも速さはほぼ変わらない。入口をそろえることの方が大事
