# 0001 受け口を html-slide と同じにする（同じ台本・同じ段）

- 日付: 2026-10-03
- 状態: 採用

## 決めたこと

1. 入力は **html-slide の台本 JSON をそのまま**読む。一番外のキー・型23種・型ごとのキー・`talk`・画像の枠の置き場まで同じ。html-slide の側は変えない
2. 型ごとのキーと帯の有無は html-slide の定義の写しを持つ（`scripts/script_io.py`）。**ずれたらテストが落ちる**（`tests/test_logic.py` の `same_types_as_html_slide` が html-slide の `deck_types.TYPES` と見比べる）。実行時に html-slide を import しない
3. 知らないキーは html-slide と同じく止める。エンジン固有の値は台本に書かず、引数（`--logo`・`--ref`・`--style`）で受ける。ページごとの注文だけは `_visual`（html-slide が読み飛ばす `_` のキー）に書ける
4. 文字の長さ・talk とクリックの数・画像が無いことでは止めない（絵で描くので、測る物差しが無い・クリックが無い・画像は生成が描く）
5. 出力の形も html-slide にそろえる: `<出力先>/<台本の名前>/deck.pptx`・`slides/slide-NN.png`・`build.json`・`inspect.md`。終了コードも同じ（0/1/2/4）
6. テーマ（色）は html-slide の3つを写して持つ。値がずれたらテストが落ちる
7. ほかのスキルを呼ばない。素材（画像・キャラの絵・ロゴ）はファイルのパスで受ける。DB・履歴は持たない（quick-slide が持つ）

## 理由

- 同じ台本を html-slide に渡せば編集できる資料、image-slide に渡せば絵の資料になる。**企画（台本）を変えずに描き方だけを選べる**のが、2つのエンジンを同じ段に置く意味。将来、1冊の中で表紙だけ image・本文は html と混ぜるときも、受け口が同じなら台本を分けずに済む
- quick-slide の生成（`generate/`）は DB の企画ページ・ブランド・書式の改訂・ワーカーの台帳と一体で、そのまま持ってくると状態を持つエンジンになる。Markdown を入口にする生成器は、Markdown → ページの計画 → プロンプトのファイル、という別の入口を持つ。どちらも html-slide の段には合わない
- 定義を import せず写しにするのは、エンジン同士を実行時に結ばないため（片方を直したら片方が壊れる、をテストで先に知る）

## 却下した案

| 案 | 却下の理由 |
|---|---|
| Markdown を入口にする既存の生成器を改名・改修する | 入口（Markdown・プリセット・週報や月報の型）と、それを使っている呼び手がある。受け口を変えると呼び手が壊れる |
| quick-slide の `generate/` を切り出して使う | DB・改訂・ワーカーの台帳に結びついている（上の理由） |
| 台本の一番外に `logo` などを足す | html-slide で「知らないキー」で止まる。同じ台本を両方に渡せなくなる |
| html-slide の検査（文字の長さ）を通す | 絵は文字の大きさを型が決めない。止める理由にならない |

## 今後

html-slide の入力を quick-slide の形（ブランド・フォーマット・企画）に合わせるときは、テーマ・フッタ・ロゴの受け方を html-slide と一緒に変える。受け口は2つのエンジンで同じであり続ける。
