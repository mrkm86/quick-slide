# 0012 描いた1枚を指示で直す revise（微修正は今の絵を土台に渡す・作り直しは渡さない）

- 日付: 2026-10-06
- 状態: 採用
- 前提: 素材の層（ADR 0011）の論点から。quick-slide の GUI に載せ、直しは微修正を既定として受けたい。テイストを変えたいときは今の絵を渡さないほうがよい。
  見本で微修正・作り直しを1回ずつ試し、どちらも狙いどおりに効いたので口を足す
- 比べたもの: quick-slide の改稿（`docs/adr/0009-edit-modes-and-reference-origins.md`・`src/quick_slide/generate/prompt.py` の `_REVISION_LEADS`）

## 決めたこと

1. 入口は `revise`（deck と同じ引数＋`--page N`・`--remake`・`--note <文>`・`--attach <画像>`…）。**既定は minor（微修正）**で、`--remake` で作り直し（quick-slide の GUI で既定を微修正にしたい）。
   初めは `--mode minor|remake` だったが、html-slide の `--mode`（talk・handout）とぶつかるので、同じ日に両方のエンジンを `--remake` にそろえた（html-slide の ADR 0011）
2. **微修正（minor）**は今の絵を土台として添える。**作り直し（remake）**は添えない。`--attach` はどちらにも添える。`--note` が無ければ `--attach` だけで直せる
3. 描く指示は、元のページの指示の後ろに直しの節を足す。言い方は quick-slide と同じ（モードの1行目・画像の役割・利用者の指示・「指示に無い内容を足さない」）
4. 土台は**ロゴ・番号・透かしを載せる前の絵**（`raw/`）。quick-slide は載せた後の絵を渡すので「予約領域の印を描き写さない」と頼んでいるが、image-slide は要らない
5. 参照画像の並びは 元の並び（枠・見本・キャラ・`--ref`）→ 土台 → `--attach`。元の指示の番号をずらさない。合わせて5枚まで（ADR 0011）
6. **描くのは直すページだけ。** ほかのページは前に描いた絵をそのまま使い、台本が変わっていても描かない（警告だけ）。まだ描いていないページがあれば止める
7. 前の絵と鍵は `raw/history/slide-NN-<日時>.png`・`.json` に写してから描く。直した結果の鍵は**台本から作った元の鍵**のまま入れ、
   `revision`（モード・指示・添えた画像・前の絵・日時）を `raw/slide-NN.json` と `build.json` に残す。台本を変えずに deck を流し直しても、直した絵が使い回される。
   台本を変えたページや `--redo` は、台本から描き直す（直しは消える）

## 理由

- **土台を渡すかどうかで、結果の性質がまったく変わる。** 渡し続けると絵がそこへ引っ張られ「いくら指示しても何も変わらない」になる
  （quick-slide `docs/REQUIREMENTS.md:388-389`）。見本でも、微修正は文字・色・札を保ってキャラの左右だけ入れ替わり、作り直しは画風ごと変わった
- **部分編集ではない。** Codex の画像ツールは参照画像を添えて丸ごと描き直す（マスクは無い）。「ほかはそのまま」は文で頼んでいるだけ
- **鍵を元のままにする。** 直した絵を次の deck で消さないため。直しの記録は鍵とは別に持つ
- **版の管理はしない。** エンジンは状態を持たない（ADR 0001）。前の絵を `raw/history/` に残すだけで、どれを採るかは呼ぶ側（quick-slide の DB）が持つ

## 見送ったこと

- 候補を並べて選ぶ形（quick-slide の候補の版）。呼ぶ側が要るとき、出力先を分けて呼べば足りる
- 複数ページを同じ指示で直す形
