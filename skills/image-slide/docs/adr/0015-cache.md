# 0015 描いた絵はキャッシュに置き、作り直せる中間物は出力フォルダに残さない

- 日付: 2026-10-07
- 状態: 採用（macOS 版。Windows・Linux はロードマップ）。キャッシュの場所は ADR 0016 で `~/Library/Caches/quick-slide/image-slide/` に変えた
- 前提: Quick Slide の GUI に入る前に、出力の置き場で容量を食いつぶさないかを見直した。中間物の画像を多く作るので、無頓着に作り続けると機体の容量を食いつぶす。
  スキルを GUI なしで単体で使うことも多く、気づけば容量が増えている。まずキャッシュを使うことだけを macOS 版で入れ、Windows・Linux はロードマップに回す
- html-slide の ADR 0014 と同じ判断（html-slide は台本のフォルダごとの区画）

## 測ったもの（2026-10-07・使っている機体の出力フォルダ）

| 中身 | 合計 | 消したときの重さ |
|---|---|---|
| `raw/`（image-slide が Codex で描いた絵） | 366 MB | 描き直し（1枚 40〜70 秒＋サブスク枠） |
| `assets/`（html-slide の画像の枠。描いた絵の写しを含む） | 124 MB | 写しなら無し |
| `base/`（raw を 1920×1080 にそろえたもの） | 507 MB | raw から機械的に作り直せる |
| `slides/`（ページの画像） | 595 MB | 成果物（ADR 0013） |
| PPTX | 559 MB | 成果物 |

image-slide の10ページは1回あたり約 90 MB。そのうち `base/` と `raw/` が約 40 MB。

## 決めたこと

1. **Codex で描いた絵と鍵（`slide-NN.png`・`.json`）・直す前の絵（`history/`）は、キャッシュの区画に置く。** 区画は出力フォルダごと
   （名前は「フォルダ名-絶対パスのハッシュ」）。置き場は `~/Library/Caches/image-slide/`。環境変数 `IMAGE_SLIDE_CACHE` か設定の `cache_dir` で変えられる。
   区画の場所は `build.json` の `cache`
2. **区画の単位で上限を持つ。** 合計が設定の `cache_max_mb`（既定 1024 MB。0 は消さない）を超えたら、最後に使った時刻の古い区画から丸ごと消す。
   今の区画と、10分以内に使われた区画（並行して走っている実行）は消さない。印（`owner.json`）の無いフォルダは消さない
3. **そろえた絵（PPTX に敷く元）は、実行中だけの tmp に置く**（`tempfile.TemporaryDirectory`・終わったら消す）。出力フォルダに `base/` を作らない
4. **出力フォルダに残すのは、成果物（PPTX・PDF・`slides/`・サムネイル）と台本の写し（`prompts/`）・`build.json`・`inspect.md`・`logs/`。**
   `slides/` は検品（`inspect.md` と一緒に検品する側へ渡す絵）が実行の後で見るので、tmp に置かない（ADR 0013 のまま）。`logs/` は合計 1 MB ほどなので動かさない
5. **前の形の出力フォルダは、流したときに移す。** `raw/` は区画へ移し（区画に同じ名前があれば区画の方を残す）、`base/` は消す。どちらも描き直しは起きない
6. 消された区画のページは、次の deck で描き直す（鍵が無いのと同じ）。revise の微修正は土台が無いので rc=2（「先に deck を流すか、--remake で描く」）

## 理由

- **何を消してよいかを知っているのはスキルだけ。** 外から出力フォルダを古い順に消すと、描き直しに数分と枠を使う絵まで消える。
  逆に「何日残すか」は使い方の方針なので、呼ぶ側（GUI・定期実行）が出力フォルダごと決める。キャッシュの上限はスキルの側で持つので、呼ぶ側が何もしなくても描いた絵は増え続けない
- **tmp に描いた絵を置かない。** macOS は tmp をしばらく触らないと消す。消える時期をこちらで決められず、直している途中で消えると黙って描き直しになる。
  `~/Library/Caches/` は OS が「作り直せるものを置く場所」と決めているが、macOS は普通のファイルを勝手に消さない（容量の管理はしない）。上限と消す順はスキルが書く
- **鍵だけを名前にした共有のキャッシュにしない。** revise で直した絵は元の鍵のまま置く（ADR 0012）ので、鍵だけで共有すると同じページを持つ別の資料に直した絵が混ざる。
  出力フォルダごとの区画なら、今までの使い回しの意味が変わらない
- **区画の名前は絶対パスのハッシュ。** フォルダを写したときに2つの資料が区画を共有しない（共有すると、片方の revise がもう片方に効く）。
  フォルダを動かすと区画が見つからず描き直しになるが、黙って違う絵が出るより安全

## 実物での確かめ（2026-10-07）

前の形の出力（5ページ・visual）を tmp に写して流し直した。Codex は呼ばず（描く 0・使い回す 5）、
`raw/` は区画へ移り、`base/` は消えた。出力フォルダは 43 MB → 28 MB、区画は 8.5 MB。

## 見送ったこと

- **Windows・Linux の置き場**（`%LOCALAPPDATA%`・`$XDG_CACHE_HOME`）。いまは macOS 以外では `~/.cache/<スキル>` に置くだけ。字体のパス・`soffice` の探し方など、
  ほかの OS で動かすための直しと一緒にロードマップへ
- **PPTX に入れる絵の圧縮。** PDF は約 1/6 に収まっているので余地は大きいが、文字まで絵なので劣化が見えないかを実物で確かめてから
- **出力フォルダを日数で畳む・消す仕組み。** 呼ぶ側の仕事（GUI のプラグイン・定期実行）
