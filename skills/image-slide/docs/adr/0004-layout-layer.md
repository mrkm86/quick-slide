# 0004 レイアウトの層を、ページの型とは別に持つ

> **置き換え済み（2026-10-05）: [0005](0005-no-layout-layer.md) でレイアウトの層をやめた。** 構図は Codex に任せる。この ADR は経緯として残す。

- 日付: 2026-10-03
- 状態: 置き換え済み（[0005](0005-no-layout-layer.md)）
- 問い: ピッチなので html-slide と同じレイアウトにする必要は無いが、構造としてレイアウトの層は要るのではないか

## 決めたこと

1. **ページの型（`type`）は中身の形、レイアウトは見せ方。** 型は html-slide と共通の23種で、どのキーが何で何が主役かだけを言う（`prompt.TYPE_NOTES`）。並べ方・構図はレイアウトが言う
2. レイアウトの棚は `layouts/<名前>.yaml`（15種）。**名前と中身は quick-slide の `generate/patterns.py` に合わせる**（split・process-flow・grid・center-focus・structure-diagram・illustration・full-bleed・icon-matrix・timeline・data-viz・table・concept-map・section-break・cover・summary）。色の役の名前だけ、テーマの言葉に置き換えた。ずれはテストが quick-slide と見比べる
3. 型ごとの既定・候補・配置の指定による既定の変え方は `layout-map.yaml`。候補は2〜4個に絞る
4. 決め方の順: 台本の **`_layout`**（名前か `auto`）> 配置の指定（`layout: left` など）による既定 > **`--auto-layout`**（指定の無いページを候補から AI に選ばせる）> 型の既定。知らない名前は rc=2、候補の外は警告
5. `auto` のときは、その型の候補だけを描く指示に並べて、AI に1つ選ばせる
6. レイアウトは描く指示に入るので、変えれば鍵が変わり、そのページだけ描き直す

## 理由

- ピッチでは、同じ「主張」でも中央に大きな文字・全面の写真・大きなイラストのように、見せ方を選びたい。型にレイアウトを焼き込むと、型を変えるしかなくなり、中身の形（台本）まで書き換えることになる
- html-slide は「型＝座標まで決まったレイアウト」で、変化形（`layout`・`split`）を型の中に持つ。image-slide は座標を持たないので、同じ層を言葉の棚として外に出すのが素直
- quick-slide の名前に合わせれば、quick-slide の企画の `layout_key` がそのまま使える（ピッチモードからの呼び出し）。ほかのスライド生成器が持つパターンの棚もほぼ同じ中身
- 「毎ページ候補を全部渡して選ばせる」やり方は採らない。ページごとに選び方がぶれて、資料の調子がそろわない。quick-slide も1ページ1パターンを先に決める形にしている。おまかせは型に合う候補だけに絞る

## 却下した案

| 案 | 却下の理由 |
|---|---|
| html-slide の描いた PNG を配置の下敷きにする | ピッチでは html-slide と同じ配置にする必要が無い |
| image-slide 独自の名前の棚を作る | quick-slide とつなぐときに対応表が要る |
| 台本の一番外に既定のレイアウトを書く | html-slide で「知らないキー」で止まる。資料全体のおまかせは `--auto-layout` で渡す |

## 残り

- 全面のレイアウト（full-bleed・section-break）でも下端の帯は無地で空けさせるので、写真の下に帯が残る。帯に載せるものが無いページ（ロゴ・フッタ・ページ番号なし）なら帯は空けない
- B スタイル（使ってよいレイアウトの部分集合）はまだ無い。quick-slide の `allowed_layouts` に当たるもの
