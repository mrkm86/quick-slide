# 基本デザイン（DADS の要約）

デジタル庁デザインシステム（DADS）の「基本デザイン」の要約。色・タイポグラフィ・余白・角の形状・エレベーション・アイコン・レイアウト・リンクテキストを、数値は表で正確に、考え方は短く書く。

> 出典: デジタル庁デザインシステムウェブサイト https://design.digital.go.jp/dads/ のコンテンツを加工して作成（2026-10-08 版の Markdown 一括版をもとに要約・再構成した）。
> 一次情報は各節の URL。この要約は公式の文書そのものではなく、デジタル庁が作成したものではない。出典と加工の表記は [`../README.md`](../README.md)。
> スライドに当てはめた値は [`slide-local.md`](slide-local.md)、アクセシビリティの要点は [`accessibility.md`](accessibility.md)。

**表の数値の出どころ**: 色・文字の大きさ・行高・角丸・影の値は、公式のデザイントークン（[`../tokens/dads.css`](../tokens/dads.css)・MIT）と、サイトの本文に書かれた値。コンポーネントの細かい寸法（ボタンの高さ・カードの余白など）は Figma 側にあり、サイトの Markdown には無い。ここに書かれていない寸法は「不明」とし、推測で埋めない。

## 1. カラー

出典: https://design.digital.go.jp/dads/foundations/color/ （概要・カラーパレット・アクセシビリティ）

DADS は「プラットフォーム型」で、ブランドの色を持たない。使う側が**キーカラー**を決めてローカルデザインシステムを作る前提になっている（[`slide-local.md`](slide-local.md)）。

### 1-1. キーカラー

同じ色相の階調から選ぶ 4 つ。

| 役 | 役割 | コントラストの条件 |
|---|---|---|
| プライマリー | トーン＆マナーを決める色。ロゴ・ヘッダー・主要な操作（CTA ボタン・現在地の表示）。文字の色にも使う | 主要な背景色に **4.5:1 以上** |
| セカンダリー | プライマリーを補う、目立たなくてよい副次的な操作・状態。プライマリーと**同じ色相で明度が高いまたは低い** | 背景に隣接する要素なら 3:1 以上。**文字に使うなら 4.5:1 以上** |
| ターシャリー | セカンダリーと**反対の明度**（セカンダリーが明なら暗） | セカンダリーと同じ |
| バックグラウンド | 白・黒以外の背景色（ごく淡い地など） | その上に載る文字・非テキストが、あらためて要件を満たすこと |

- プライマリーを複数設定してもよい（その場合はそれぞれにセカンダリー以下を作る）
- 公式の例: 青・緑・ニュートラル・ライトブルー・シアン・オレンジ・紫

### 1-2. 共通カラー（ニュートラル）

白から黒のグレーの階調。文字・枠線・背景・UI の構成に使う。

- テキストと背景のコントラスト比は常に **4.5:1 以上**
- 枠線・ディバイダーなどの非テキスト要素は、隣接する背景に対して **3:1 以上**
- 個別のサイトでは、ニュートラル以外の色味を足して共通カラーを作ってよい

| トークン | hex | 白に対して | 黒に対して |
|---|---|---|---|
| `solid-gray-50` | `#f2f2f2` | 1.12 | 18.76 |
| `solid-gray-100` | `#e6e6e6` | 1.25 | 16.83 |
| `solid-gray-200` | `#cccccc` | 1.61 | 13.08 |
| `solid-gray-300` | `#b3b3b3` | 2.10 | 10.02 |
| `solid-gray-400` | `#999999` | 2.85 | 7.37 |
| `solid-gray-420` | `#949494` | 3.03 | 6.92 |
| `solid-gray-500` | `#7f7f7f` | 4.00 | 5.24 |
| `solid-gray-536` | `#767676` | 4.54 | 4.62 |
| `solid-gray-600` | `#666666` | 5.74 | 3.66 |
| `solid-gray-700` | `#4d4d4d` | 8.45 | 2.48 |
| `solid-gray-800` | `#333333` | 12.63 | 1.66 |
| `solid-gray-900` | `#1a1a1a` | 17.40 | 1.21 |

- Gray-420 は白に対して 3:1 を確保できる最初の段（これより暗い段は非テキストの要件を満たす）
- Gray-536 は白に対して 4.5:1 を確保できる最初の段（これより暗い段はテキストの要件を満たす）
- 黒の地では Gray-600 以上の明るさが 3:1、Gray-536 以上の明るさが 4.5:1

### 1-3. 機能カラー

| 種類 | 内容 |
|---|---|
| リンクカラー | 4.5:1 以上。ウェブの慣習で未訪問は**青**・訪問済みは**マゼンタ（紫）**。青と紫は色覚多様性で見分けにくいので、紫には少し赤みを足して明度差を作る。色だけに頼らず**下線**などと組む |
| フォーカスカラー | **Yellow-300 と Black の 2 重構造**。「いかなる場合も変更してはいけない」 |
| 検索ハイライト | シアンまたはマゼンタの淡い地と、濃い同色の枠 |
| UI のステート | ボタンなどはキーカラーでデフォルト・Hover・Active を決める（例: 青のプライマリー → Hover はやや暗い青 → Active はさらに暗い青。ラベルは白）。サイト内で一貫させる |

### 1-4. アクセントカラー

特定の要素に注意を引くための色で、多用しない。装飾以外の用途・機能を持つコンポーネントに使うなら、コントラスト（文字 4.5:1・非テキスト 3:1）を確保する。例は紫・青・ライトブルー・シアン・緑・ライム・黄・明るいオレンジ・暗いオレンジ。

### 1-5. セマンティックカラー

意味（成功・エラー・警告）が割り当てられた色。緑＝成功、赤＝エラーのように、色と意味の結びつきは**変えない**（エラーを緑にはできない。明度・彩度を、コントラストを確保できる範囲で調整するのは可）。

| トークン | 意味 | プリミティブ | hex | 白に対して | 使いどころ |
|---|---|---|---|---|---|
| `--color-semantic-success-1` | 成功 | `green-600` | `#259d63` | 3.45 | 枠・アイコンなど非テキスト（3:1 以上） |
| `--color-semantic-success-2` | 成功 | `green-800` | `#197a4b` | 5.35 | テキスト・ボタンの塗り（4.5:1 以上） |
| `--color-semantic-error-1` | エラー | `red-800` | `#ec0000` | 4.60 | 枠・アイコンなど非テキスト（3:1 以上） |
| `--color-semantic-error-2` | エラー | `red-900` | `#ce0000` | 5.79 | テキスト・ボタンの塗り（4.5:1 以上） |
| `--color-semantic-warning-yellow-1` | 警告（黄） | `yellow-700` | `#b78f00` | 3.02 | 枠・アイコンなど非テキスト（3:1 以上） |
| `--color-semantic-warning-yellow-2` | 警告（黄） | `yellow-900` | `#927200` | 4.54 | テキスト・ボタンの塗り（4.5:1 以上） |

- 末尾 `-1` は非テキスト（枠・アイコン・図形）向けの明るい側、`-2` はテキスト・ボタンの塗り向けの暗い側。値はプリミティブへの参照（`green-600` など）
- 背景が白・黒以外のときは必ずコントラストを測り直す
- 色だけで意味を伝えない（アイコン・ラベルと組む）

### 1-7. コントラスト要件（DADS の読み替えに注意）

- JIS X 8341-3:2016・WCAG 2.1/2.2 の要件: 1.4.3（テキスト 4.5:1）・1.4.11（非テキスト 3:1）・1.4.6（高度 7:1）
- **DADS はここを厳しくしている**: WCAG が認める「サイズの大きなテキスト（24px 以上、または太字 18px 以上）は 3:1」の例外を使わない。**文字の大きさに関わらず、テキストと文字画像は 4.5:1 以上**
- 対象外: 無効（disabled）の UI のテキスト・純粋な装飾の文字・重要でない写真の中の文字・ロゴやブランド名
- 非テキスト 3:1 の対象: UI コンポーネント・グラフィカルオブジェクト・フォーカスインジケーター。グラフ・チャートで目盛り線が 3:1 を満たさないときは、値のすぐ近くに 4.5:1 のテキストを置く。インフォグラフィックは、代替として説明テキストを用意する
- 前景色を指定したら、その文字が載りうる背景色も必ず指定する（ブラウザの背景色設定でコントラストが崩れるため）

### 1-8. ブランドカラーがコントラスト要件を満たさない場合

ブランドの色はロゴの色味としては対象外でも、プライマリーは文字にも使うので 4.5:1 が要る。**ブランドと同じ色相で明度を調整する**。セカンダリー・ターシャリーも同様（文字なら 4.5:1・非テキストのみなら 3:1）。あるいは、ブランドの色はロゴ・純粋な装飾に使い、キーカラーはブランドと相性のよい別の色（コントラストを満たすもの）にする方法もある。この方法は [`../scripts/keycolors.py`](../scripts/keycolors.py) で機械的に行える。

### 1-9. 色覚多様性

色弱の特性を持つ人は全国に約 290 万人と推定される。多くは赤近辺と緑近辺の識別が難しい。色の組み合わせを避ける、または**色だけで情報を伝えない**（1.4.1）。ダイヤグラムでは色の組み合わせを考え、図形の近くにテキストを置く。配色はカラーユニバーサルデザイン推奨配色セットを参考にする。

## 2. タイポグラフィ

出典: https://design.digital.go.jp/dads/foundations/typography/ （概要・テキストスタイル一覧・アクセシビリティ）

### 2-1. 書体と太さ

- 書体: **Noto Sans JP**（SIL OFL 1.1）。等幅は Noto Sans Mono。システムフォントを制限するものではなく、情報伝達は書体に依存しないこと
- 太さレベル: **N = 400（normal）**・**B = 700（bold）** の 2 つ

```css
body { font-family: 'Noto Sans JP', sans-serif; }
pre, code { font-family: 'Noto Sans Mono', monospace; }
```

### 2-2. 大きさ（`font-size`）

| 大きさ（px） | 主な用途 |
|---|---|
| 48〜64 | 視覚的なインパクトが必要なデザイン要素 |
| 16〜45 | 読み物の見出し・本文。**本文と UI は 16px 以上が基準値** |
| 14 | 基本的に使わない。フッターなど付随する情報や領域の制約があるときだけ。**14 未満は原則許容されない** |

公式トークン（`--font-size-*`）にある段: **14・16・17・18・20・22・24・26・28・32・36・45・48・57・64**。規範的な目安で、コンテンツに応じて追加・変更してよい。

### 2-3. 行高（`line-height`）

読み物の本文は**フォントサイズの 1.5 倍以上**を推奨。大きな文字（見出し）は本文より狭くてよい。

| 行高 | 主な用途 |
|---|---|
| 100% | ボタンなど、上下の余白を持たない 1 行のテキスト |
| 120% | 管理画面・業務システムで情報量を最優先する行間 |
| 130% | 同上（情報量を優先） |
| 140% | 見出しなど、やや大きな文字 |
| 150% | 一般的な本文・見出し（**本文の行間としては最低限度**） |
| 160% | 一般的な本文 |
| 170% | 本文（心理的負荷の軽減を考えた行間） |
| 175% | 本文（同上。グリッド幅とフォントサイズに応じて 170% と使い分け） |

CSS では単位なしの数値（`1.5` など）で書く（Figma は `%` 表記）。

### 2-4. テキストスタイルの名前と種類

名前は `種類-大きさ 太さ-行高`（例 `Std-17N-170` = Standard・17px・Normal・行高 170%）。5 種類ある。

**Display（Dsp）**: 冒頭の大きなメッセージ・ヘッドコピー。行高はすべて 140%・文字間隔 0。背景画像が入る場合は大きさと行間を調整する。

| スタイル名 | 大きさ | 太さ |
|---|---|---|
| Dsp-64B-140 / Dsp-64N-140 | 64 | B / N |
| Dsp-57B-140 / Dsp-57N-140 | 57 | B / N |
| Dsp-48B-140 / Dsp-48N-140 | 48 | B / N |

**Standard（Std）**: 見出し・本文など最も使う普遍的なスタイル。基本は 16px 以上。見出しは本文との違いが視覚的に明確になるようにする。B と N が同じ大きさ・行高・文字間隔で揃う。

| スタイル名（B／N） | 大きさ | 行高 | 文字間隔 |
|---|---|---|---|
| Std-45B-140 / Std-45N-140 | 45 | 140% | 0 |
| Std-36B-140 / Std-36N-140 | 36 | 140% | 1% |
| Std-32B-150 / Std-32N-150 | 32 | 150% | 1% |
| Std-28B-150 / Std-28N-150 | 28 | 150% | 1% |
| Std-26B-150 / Std-26N-150 | 26 | 150% | 2% |
| Std-24B-150 / Std-24N-150 | 24 | 150% | 2% |
| Std-22B-150 / Std-22N-150 | 22 | 150% | 2% |
| Std-20B-150 / Std-20N-150 | 20 | 150% | 2% |
| Std-18B-160 / Std-18N-160 | 18 | 160% | 2% |
| Std-17B-170 / Std-17N-170 | 17 | 170% | 2% |
| Std-16B-170 / Std-16N-170 | 16 | 170% | 2% |
| Std-16B-175 / Std-16N-175 | 16 | 175% | 2% |

**Dense（Dns）**: 管理画面・データテーブルなど、情報量を優先する。文字間隔 0。

| 大きさ | 行高 |
|---|---|
| 17・16・14 | 130% / 120%（それぞれ B・N。例 `Dns-17N-130`） |

**Oneline（Oln）**: 1 行展開が前提の UI 要素（ボタンなど）。行高 100%・文字間隔 2%。`Oln-17B-100`・`Oln-16B-100`・`Oln-14B-100`（と N）。

**Mono**: コード。等幅・行高 150%・文字間隔 0。`Mono-17N-150`・`Mono-16N-150`・`Mono-14N-150`（と B）。

### 2-5. そのほか

- 文字間隔（`letter-spacing`）はスタイルが決める（上の表）。両端揃え・空白文字で位置を調整することはしない（スクリーンリーダー・拡大表示に不都合）
- 下線（`text-decoration`）はリンクの慣習。色だけでリンクを表さないために重要。既定の装飾を取り消さない
- イタリックは日本語では使わない（字体が無く、傾けた合成になって読みにくい）。ルビの既定サイズは親文字の 50%
- 閲覧者が書体や大きさを変えても、読みやすさと機能が変わらないようにする。**フォントを変えさせないための文字画像は使わない**（ロゴは除く）
- 行ボックスは文字の 1.5 倍以上。段落の間は行ボックスの 1.5 倍以上（文字の 2.25 倍以上）が望ましい
- 1 行の長さ（テキストブロックの幅）は**半角 80 字（全角 40 字）程度**が目安。ただし網羅性を優先すべき内容や、読みやすさの工夫（目次・概要・見出し構造・拡縮できるレイアウトなど）がある場合は適用しなくてよい

## 3. 余白

出典: https://design.digital.go.jp/dads/foundations/spacing/ （概要・アクセシビリティ）

- 余白の要素: パディング（要素の内側）・マージン（外側）・行間隔・空白（ホワイトスペース）
- **基準単位は 8px が一般的**。その倍率で 3〜5 段のスケールにする（例: 8・24・64 の 3 段。1 倍・3 倍・8 倍）。コンポーネントが余白を内包しているので、余白だけを単体で置くことは通常ない。トークン化は必要に応じて
- ルール:
  - 同種の要素には同じ間隔値を使う（一貫性）
  - 関連する要素は近く、関連の低い要素は遠く（余白で関係性を示す。キャプションは画像に近く、本文から遠く）
  - 重要・上位の要素ほど大きな余白（余白で階層を示す。見出しのレベルが下がるほど、見出しと本文の間も狭くなる）
  - 詰め込まない。レスポンシブでは各画面幅で間隔がつり合うようにする
- アクセシビリティ: **空白文字・両端揃えでレイアウトを調整しない**（日本語は川が少ないが、表のセルや定義リストの見出しで両端揃えをしがち。拡大ソフトで 1 つの語に読めなくなる）

## 4. 角の形状

出典: https://design.digital.go.jp/dads/foundations/corner-shapes/

5 段階を基本の目安にし、スタイルガイドでコンポーネントごとに角丸値を決める。形が大きい・縦横比が違うと同じ値でも丸みが違って見えるので、コンポーネントごとに半径を調整して視覚的に揃える。

| 段階 | 正方形の半径 | 横長の長方形の半径 |
|---|---|---|
| 角丸なし | 0 | 0 |
| スモール | 8 | 8 |
| ミディアム | 16 | 12 |
| ラージ | 32 | 16 |
| フル | 高さ（幅）の 50% | 高さの 50% |

公式トークン（`--border-radius-*`）: **4・6・8・12・16・24・32・full（`9999px` 相当）**。

- 同じ半径でも図形が小さいほど角丸は強く、大きいほど弱く見える。図形のサイズに応じて半径を変える
- 角の形を変えることで特定の図形を強調できる（1 つだけ円など）
- 部分的な角丸（上の 2 角・左上だけ）もある

## 5. エレベーション

出典: https://design.digital.go.jp/dads/foundations/elevation/

高さレベルの表現。デフォルトは**レベル 0**（高さを持たない）。表現はドロップシャドウとオーバーレイシェード（下のコンポーネントの視線と操作を遮る透過背景）。

| トークン | 値 |
|---|---|
| `--elevation-1` | `0 2px 8px 1px rgba(0,0,0,0.1), 0 1px 5px 0 rgba(0,0,0,0.3)` |
| `--elevation-2` | `0 2px 12px 2px rgba(0,0,0,0.1), 0 1px 6px 0 rgba(0,0,0,0.3)` |
| `--elevation-3` | `0 4px 16px 3px rgba(0,0,0,0.1), 0 1px 6px 0 rgba(0,0,0,0.3)` |
| `--elevation-4` | `0 6px 20px 4px rgba(0,0,0,0.1), 0 2px 6px 0 rgba(0,0,0,0.3)` |
| `--elevation-5` | `0 8px 24px 5px rgba(0,0,0,0.1), 0 2px 10px 0 rgba(0,0,0,0.3)` |
| `--elevation-6` | `0 10px 30px 6px rgba(0,0,0,0.1), 0 3px 12px 0 rgba(0,0,0,0.3)` |
| `--elevation-7` | `0 12px 36px 7px rgba(0,0,0,0.1), 0 3px 14px 0 rgba(0,0,0,0.3)` |
| `--elevation-8` | `0 14px 40px 7px rgba(0,0,0,0.1), 0 3px 16px 0 rgba(0,0,0,0.3)` |

- ほとんどの要素はレベル 0。レベルは、使うコンポーネントを洗い出してから、必要な段だけを設計する。**過度に定義しない**（高低差で理解しやすくなるときだけ）
- 立体感のある要素はサーフェスがレベル 1。Hover で浮く要素は、設置面より 1 レベル以上上に設計する
- ダイアログなどオーバーレイは**少なくとも 2 段階上**（0 の上なら 2、レベル 1 のボタンがあるなら 3 以上）
- **ドロップシャドウでコントラスト比は確保できない**。高さを持つ要素は、置かれる面に対して 3:1 以上の**ボーダー**を持たせる（影が無くてもコントラストが成り立つように設計する）
- オーバーレイシェードの上の要素にも必ずボーダー（強制カラーモードで影が無効になるため。透明のボーダーでもよい）
- オーバーレイシェードは、モードレスのダイアログには使えない。シェード自体はフォーカス可能にせず、閉じる操作はオーバーレイ内に用意する
- ダークモードでは影の表現ができないので、色の変更だけでは定義できない。ダークを想定するなら最初から設計する

## 6. アイコン

出典: https://design.digital.go.jp/dads/foundations/icon/

DADS のアイコンは **Material Symbols**（Apache License 2.0）。文書構造のどこに置くかで 4 つの仕様がある。

| 種類 | 位置 | 例 |
|---|---|---|
| ① フロントアイコン | ブロックレベルボックスの**先頭** | カードの頭・注釈ブロックの頭 |
| ② リードアイコン | 行ボックスの**先頭**（テキストの一部） | 箇条書きの行頭・見出しの左 |
| ③ テールアイコン | 行ボックスの**末尾** | リンク末尾の「新しいタブ」 |
| ④ エンドアイコン | ブロックレベルボックスの**末尾** | メニュー項目の右端のシェブロン |

- **アイコンは必ずラベルと組み合わせる**（視覚だけでなく、スクリーンリーダー・意味の多義性のため）。ラベルと組むアイコンに代替テキストは不要（`alt=""`・`aria-label` を付けない）
- ラベルがリンクなら、アイコンもリンクの範囲に入れる（別の `<a>` にしない）
- やむを得ずアイコン単体にする場合は、ラベルの内容を代替テキストにし、アクションを伴うなら 44×44px 以上のターゲットを確保する。アイコン単体のボタン用に、ラベルを一部に含めた専用アイコンが定義されている
- **色は背景に対して 4.5:1 以上**（リードアイコン・テールアイコンとしてテキストの一部になりうるため）。非テキストとしてしか使わないことが保証されているときだけ 3:1

アイコンの実体（名前と path）は [`../icons/`](../icons/)。

## 7. レイアウト

出典: https://design.digital.go.jp/dads/foundations/layout/

- **グリッドシステム**: マージン・カラム・ガターで構成する。1 カラム・12 カラム・左メニュー付き 12 カラムがある。12 列は分割・結合しやすい
  - カラム幅は**本文の文字サイズの整数倍**
  - ガターは狭いと隣のカラムの文字と接近して誤読するので、原則として**本文の文字サイズの 2 倍**
  - 左のメニュー・ナビゲーションは固定幅または可変幅。右端からマージンを取ってグリッドを作る
- **ブレークポイント**: DADS は 1 つを想定。**768px 未満 = モバイル・タブレット、768px 以上 = デスクトップ**。必要なら増やす
- カラムレイアウト: 1〜4 カラム、カラムオフセット（記事など読み物に使うと焦点が絞れる）
- アクセシビリティ:
  - **リキッドレイアウト**にする（カラムかガターのどちらかを可変幅、もう一方を固定幅）。固定幅で横スクロールが出ても、スクロールバーを隠さない
  - **視覚的な配置と読み上げ順序を一致させる**。CSS の `order`・`grid-placement` は視覚的な並べ替えだけに使い、DOM の順序から大きく外れるなら文書構造を見直す（フォーカス順序・スクリーンリーダーの順序は DOM に従う）

## 8. リンクテキスト

出典: https://design.digital.go.jp/dads/foundations/link-text/

- 通常の文字と区別できるように、色と下線などを組み合わせる。**色だけにしない**（下線が最も一般的。ビュレットや矢印のリンクマークでもよい）
- 色: コントラスト 4.5:1 以上・色覚多様性を考える・サイト内で一貫させる。未訪問は青、訪問済みはマゼンタが一般的。青以外（ブランドの色相）にしてもよいが、リンクだと迷わず分かること
- ステート: Hover・Active・Visited で見た目を変える。Hover で太さ・大きさを変えると文字領域が変わってがたつくので、周りに影響しない場合だけ。Visited は未訪問と明瞭に区別する
- 新しいタブを開くリンクは、末尾（テールアイコン）に外部リンクのアイコンを置いて知らせる（代替テキスト「新しいタブを開きます」など）。アイコンは下線を引かないがクリック範囲には含める。PDF などウェブページ以外は、形式・容量を書く
- アクセシビリティ: リンクの目的が分かるテキスト（**「ここ」「こちら」だけにしない**）。リンク先のタイトルか、前後の文脈で分かるもの。ターゲットは隣接と重ならず **24×24px 以上**（リンクの高さが 24 に満たなくても、上下に 4px ずつの余白があればよい）
