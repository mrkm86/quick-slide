# コンポーネント（DADS の要約と、スライド・画面への対応）

デジタル庁デザインシステム（DADS）の全コンポーネント（49 個）を 1 つ数行で要約し、**スライド**（html-slide・motion-slide）と**画面**（Quick Slide のようなウェブアプリ）でどう使うかの対応表を付ける。スライドに転用できるものは後半で詳しく書く。

> 出典: デジタル庁デザインシステムウェブサイト https://design.digital.go.jp/dads/ のコンテンツを加工して作成（2026-10-08 版の Markdown 一括版をもとに要約・再構成した）。デジタル庁が作成したものではない。出典と加工の表記は [`../README.md`](../README.md)。
> 各コンポーネントの URL は `https://design.digital.go.jp/dads/components/<スラッグ>/`（概要・使い方・アクセシビリティ・作例が同じ URL 内のタブ）。下の表の「スラッグ」がそれ。
> 基本デザイン（色・文字・余白）は [`foundations.md`](foundations.md)、アクセシビリティは [`accessibility.md`](accessibility.md)。

**サイトの Markdown にある情報の範囲**: 使い分け・構成・ふるまい・アクセシビリティは本文に書かれている。**寸法（ボタンの高さ・パディングなど）の多くは Figma 側にあり、Markdown には無い**。ここに数値が無いものは「不明」として、推測で補っていない。スライドの寸法は DADS ではなく [`slide-local.md`](slide-local.md) で決める。

**達成基準の表記**: JIS2016 = JIS X 8341-3:2016、WCAG2.2 = Web Content Accessibility Guidelines 2.2。

## 1. 全コンポーネントの対応表

スライド列の「型」は html-slide の型（`deck-format.md`）。**新**は計画で足す型（`notice`・`deflist`・`steps`）。「—」は使わない（理由は後半）。画面列は Quick Slide の画面での使いどころの目安。

## 2. スライドに転用できるもの（詳しく）

スライドは押せない・スクロールしない・遠くから見る。DADS の「構造と意味の決まり」（色だけに頼らない・ラベルとアイコン・見る順）を借りて、寸法は [`slide-local.md`](slide-local.md) で決める。**スライドでの寸法は DADS の値ではなく、スライド用の値**。

各項の「**スライドへの転用**」は DADS の記述ではなく、この資料の提案（計画で決めたものは [`slide-local.md`](slide-local.md) に反映している）。その前の「使うとき・形・決まり」までが DADS の記述の要約。

### 2-1. 注釈ブロック `notice-block` → 新 `notice`

https://design.digital.go.jp/dads/components/notice-block/

- **使うとき**: 手続き・入力に必要な補足（ヘルプ・必要な資料）／具体的な例（入力例・選択肢の違いが分かる例）
- **形**: 段落の周りに**ボーダー**。視覚的な特徴は「これは補足情報」と表すためのもの
- **使ってはいけないとき**: 入力・操作そのものの条件（サポートテキストを使う）／**本文の調子を変える飾り**・コラムのように文脈を切り替える・本文を強調する目的／重要な情報を折りたたむ（ディスクロージャーを入れるのは、読まなくても進められる補足だけ）
- **関連**: ディスクロージャー（折りたたみ）・インプットテキスト（サポートテキスト）
- **スライドへの転用**:
  - 型 `notice`: 「補足・注意・例」を、枠線（3:1 以上）で囲んだ 1 つの箱にする。**頭にアイコン（フロントアイコン）とラベルの文字**を必ず付ける
  - 種類は 情報（既定・ニュートラルまたはキーカラー）・成功・エラー・警告。意味の色はセマンティックカラー（[`foundations.md`](foundations.md) の 1-5）で、**色だけで種類を示さない**（アイコン＋「注意」「例」などのラベル）。ノティフィケーションバナーの色の使い方（枠は `-1` の 3:1、文字・アイコンは `-2` の 4.5:1）に従う
  - 本文の中の飾り・強調としては使わない。1 枚に 1〜2 個まで
  - 地は白（または淡い地）。意味の色は**白い箱の上**で使う（淡い色の地の上では 3:1 を割ることがある）

### 2-2. 説明リスト `description-list` → 新 `deflist`

https://design.digital.go.jp/dads/components/description-list/

- **使うとき**: 用語と説明をセットで繰り返す（用語集・FAQ の質問と回答・仕様の項目名と内容）／データを名前と値のペアで示す（プロフィール・設定項目・確認画面）
- **使ってはいけないとき**: 値を比べる・行列で構造化する（→ テーブル）／セクションの主題を示す（→ 見出し。説明リストのタイトルで見出しの代わりにしない）／ペアでない列挙（→ 箇条書きリスト）／複数の情報・リンク・選択を含む項目（→ リソースリスト）
- **スライドへの転用**:
  - 型 `deflist`: 左に「項目名」（太字・`box-title` か `body` の B）、右に「内容」（N）。行の間は余白で区切る（区切り線を使うなら 3:1 の線）
  - 項目名と内容の**幅を揃える**。両端揃え・空白で位置を調整しない。項目名の列は固定幅（格子の 3〜4 列）にして、内容は残りに折り返す
  - 比べたいならテーブル、並べるだけの要点なら `cards`・`bullets`。ペア 2〜6 組まで

### 2-3. ステップナビゲーション `step-navigation` → 新 `steps`

https://design.digital.go.jp/dads/components/step-navigation/

- **使うとき**: 一連の手続きの流れを論理的なステップで示し、完了までの作業を俯瞰する／現在どこにいるか・完了・スキップ・エラーの状態を示す
- **使ってはいけないとき**: 一時的な処理の待機（→ プログレスインジケーター）／ページ・コンテンツの前後移動（→ ページナビゲーション）
- **関連**: カルーセルのステップナビゲーションは番号ボタン（現在位置・左右キーで切り替え）
- **スライドへの転用**:
  - 型 `steps`: 番号つきのステップを並べ、**今どこ・どこまで済んだか**を示す（`flow` が「順序のある説明」なのに対し、`steps` は「状態を持つ手順」）。状態は色だけにせず、**番号の丸の形（塗り・枠・チェック）＋ラベル**（「完了」「いま」「これから」）で示す
  - 段は 3〜6。横に並べる（左から右）か縦に並べる。番号は文字として書く
  - 動きのある資料では、1 クリックで 1 ステップ進めて「いま」を移す表現ができる

### 2-4. テーブル `table`

https://design.digital.go.jp/dads/components/table/

- **使うとき**: 構造化されたデータを見せる・データを比べる（データテーブルは大量データの操作用）
- **使ってはいけないとき**: 名前と値だけのペア（→ 説明リスト）／レイアウト目的
- **外観**:
  - サイズは Default と Dense（Dense は画面向け。**スライドは Default**）
  - **テーブルヘッダーとデータセルは黒いボーダーで区切り、ヘッダーセルの文字は太字**。ヘッダーとデータを視覚的に判別できるようにする
  - セルの結合は最小限（データテーブルでは行わない）
  - 文字の配置: **縦は上寄せ**。横は左寄せが通常、数値・日付は右寄せにしてよい
  - ストライプ（行・列）は、ボーダーと背景色のコントラストが **3:1** を下回らないように。ホバー・行の選択も同様
  - テーブルの幅がコンテンツ幅を超えるとき、モバイルは領域内の横スクロール（スクロールを促すシャドーを出す）。外周の枠線を持つ作例（v2.16）
  - セル内の位置揃えに空白・改行を使わない
  - リンクはセル単位。1 つならセル全体、2 つ以上は文字列ごと。行全体をリンクにしない
- **アクセシビリティ**: シンプルな構造で作る（見出しのような行を差し込んでグループを表さない・入れ子にしない・1 レコードを 2 行にしない。必要なら表を分ける）
- **スライドへの転用**: `table` 型（2〜5 列・1〜7 行）。ヘッダー行は太字＋区切りの線（3:1 以上）、データセルは `table-cell`（下限 24px）。縦は上寄せ・数値は右寄せ。ストライプにするなら、ストライプの面と文字（4.5:1）・面と罫（3:1）を測る。結合しない

### 2-5. 箇条書きリスト `list` → `bullets`

https://design.digital.go.jp/dads/components/list/

- **形**: ①リストマーク／項番 ②コンテンツ。2 タイプ
  - **リストマークタイプ**: 順序に関わらない列挙。入れ子の深さに応じてインデントし、**3 種類のマーカーを使い分ける**
  - **項番タイプ**: 項番自体が情報（条文・規約・手順）。**項番も文字として書く**。マーカーは既定で全角 2 文字分の幅（3 桁以上なら広げる）。数字・丸付き数字・ローマ数字・アルファベット・かな・括弧・ピリオド・コロンなど自由
  - 項目の上下の間隔は **3 段階**
- **注意**: HTML の `<ol>` と CSS カウンターを使わない（項番をコピーできない・勝手に変わる）。タイトル以外の情報・操作を持つ項目は リソースリスト、名前と説明のペアは 説明リスト
- **スライドへの転用**: `bullets` 型（2〜5 項目）。マーカーはアイコン（リードアイコン）か形。項目の間隔は余白の段（[`slide-local.md`](slide-local.md)）。入れ子は 1 段まで

### 2-6. 引用ブロック `blockquote` → `quote`

https://design.digital.go.jp/dads/components/blockquote/

- 段落単位の引用（**左に縦線・段落をインデント**）。文献・資料の一部、法令の条文の引用に使う
- **本文の見栄えのために使わない**（コラムのように文脈を切り替える・本文を強調する目的は不可）
- スライド: 他人の言葉・出典のある文だけ。縦線は 3:1 以上（またはキーカラー）。出典（誰の言葉か）を必ず添える。自分の主張の強調には `statement` を使う

### 2-7. カード `card` → `cards`・`team`・`hub`

https://design.digital.go.jp/dads/components/card/

- **構成（最大 4 パーツ）**: ①コンテナ（必須・外周と背景色を必ず持つ） ②イメージエリア（任意） ③メインエリア（必須） ④サブエリア（任意・イメージエリアと隣接させない）
- **外観の決まり**:
  - コンテナは**必ず外周**を持ち、外周の色は**外側の背景に対して 3:1 以上**。影だけで境界を表すのは悪い例。「Gray-300 を白の上に置く（2.1:1）」も悪い例
  - 角の形は自由（子エリアはコンテナからはみ出さない範囲）。エレベーションはコンテナだけが持てる
  - 背景色: コンテナは必ず持つ。子エリアは任意
- **メインエリア**: タイトル（必須・リンクなら下線）・ラベル・コンテンツ・機能ボタン（1 つまで）。イメージエリア: イメージ・ラベル（画像の上に重ねてよい）。サブエリア: リンクリストかアクションボタン
- **ふるまい**: コンテナ／メイン／イメージのエリア全体を押せる場合、その中にリンクやボタンを持てない。サブエリアは全体を押せない
- **作例の種類**: テキストのみ・画像とテキスト（縦・横）・ダッシュボードのようなカード・ボタンのようなカード
- **スライドへの転用**: `cards`（並列の要点 2〜4）・`team`・`hub` の箱は、**外周を持つ**（2px・3:1 以上）。影に頼らない（スライドは平ら）。画像つきカードは、イメージエリアを上に、メインエリアを下に。タイトルは `box-title`

### 2-8. チップラベル `chip-label`

https://design.digital.go.jp/dads/components/chip-label/

- 状態や状況を示すキーワードを表示する（リスト・テーブルの各行の状態・お知らせの種別・注釈の種別・記事のタグ）
- **色だけで意味を伝えない。必ずテキストで状態・分類を明示する**。多くの色を使わない（識別しにくくなる）。アクセントカラーを使うときは、文字・輪郭と背景のコントラストを確保する
- ユーザーが選んだ・入力した値は チップタグ（削除できる）
- スタイル: アウトラインの背景は White（v2.14.1）。見出しの左に付ける（チップ）作例もある（v2.16.0）
- スライドへの転用: 増減（「増加」「減少」）・NG／OK・章の印の**札**。文字は 4.5:1、札の枠・面は 3:1。形は角丸フル（`radius-full`）。色は 3 色まで

### 2-9. ディバイダー `divider`

https://design.digital.go.jp/dads/components/divider/

- 異なるセクション・コンポーネント・グループの視覚的な区切り。**全幅タイプ**（コンテンツ全幅・セクションやリストを区別し、インタラクティブな領域とそうでない領域も分ける）と**インセットタイプ**（同じセクション内のグループ化・関連性を保つ）
- **余白**: リストで使うときは **8px 以上**、セクションで使うときは **16px 以上**
- ディバイダーは余白を明確にする補助で、**線が無くても文意が伝わる**構成にする（余白が足りないと複数項目が 1 かたまりに見える）
- 非テキストなので 3:1 以上（[`foundations.md`](foundations.md)）
- スライドへの転用: 区切り線は 2px（[`slide-local.md`](slide-local.md)）・3:1 以上の色（`border`）。装飾の薄い線は、情報を持たせない場合だけ

### 2-10. 見出し `heading`

https://design.digital.go.jp/dads/components/heading/

- **要素**: ①ショルダー ②見出しテキスト（必須） ③サブタイトル ④リードアイコン ⑤チップ ⑥飾り罫。ショルダー・サブタイトルは `<p>` で、`<hgroup>` と組む（`<h1>〜<h6>` にしない）
- h1 はページの主題（`<title>` に相当）、h2 以降はセクションの主題。**見出しレベルを飛ばさない**。**見出しのレベルと文字サイズは別々に定義**する（スタイルガイドで対応づける）
- リードアイコンは見出しの左・チップは見出しの左・飾り罫は見出しの下（セクションの開始を強調）
- 箇条書き・説明リストを見出しの代わりにしない（逆も）。見出しが要らない文書に無理に付けない
- スライドへの転用: `kicker`（ショルダー）＋見出し（`heading`）＋副題（`subtitle`）。1 枚に見出しは 1 つ。見出しの左のリードアイコンは、種類を示す場合だけ。**飾り罫**（見出しの下の線。太さ・長さは Figma 側で不明）は、スライドではキーカラーの短い線にしてよい（章の始まりを強調する。提案）

### 2-11. プログレスインジケーター `progress-indicator`

https://design.digital.go.jp/dads/components/progress-indicator/

- ユーザーの操作に対して処理が進行中であることの通知。**画面全体**が待ち: サークル（回る）・リニア（横棒が動く）。**一部**が処理中: **動かない砂時計**。サークル・リニアは全体のときだけ
- スケルトン UI を使わない。手続き全体の進行は ステップナビゲーション（リニアの見た目は進み具合を連想させるが別物）
- スライドへの転用: **使わない**（資料に「待ち」は無い）。資料の進み具合は `steps` かページ番号。処理の様子を見せる図（砂時計のアイコン）は `hourglass` を静止で
- 画面: 描画・読み込みで使う。動くものは画面全体が処理中のときだけ

### 2-12. 画像と写真の上の文字（`image`・`carousel`）

https://design.digital.go.jp/dads/components/image/ ・ https://design.digital.go.jp/dads/components/carousel/

- 画像: 写真・図版・グラフ・地図。**画像だけで重要な情報を伝えない**（本文でも）。**文字画像を使わない**（ロゴを除く）。キャプションと組める
- カルーセルの「スライド画像の作り方」（スライドの写真の文字に当てはまる）:
  - 画像内の文字は**大きく読みやすく**（320px まで縮小される前提）。代替テキストは画像内の文字をそのまま
  - 文字と背景は **4.5:1 以上**。背景が一定でないとき（写真）は**最もコントラストが低くなる箇所**で測る
  - **写真や図版の上に文字を載せるときは、文字に帯の背景を敷く**。ほかに文字の縁取りもある
  - 図形・アイコンは背景に **3:1 以上**。調整しにくいなら帯を敷くか枠線をつける
  - 画像の内側 2px には枠線が重なるので、読み取るべき要素を置かない
- スライドへの転用: 写真の上の文字は帯（`photo-band`）を必ず敷く（[`slide-local.md`](slide-local.md)）。画像は端を切って意味が変わるもの（図・スクリーンショット）を切らない

### 2-13. 目次 `toc` → `agenda`

https://design.digital.go.jp/dads/components/toc/

- 長い文章の見出しを取り出してページ冒頭に目次として置く。箇条書きリストと組んで階層化できる
- 「このページの目次」の見出しを消さない。**項目は見出しの文言をそのまま使う**。階層が複雑なら絞る
- スライド: `agenda`（2〜6 項目）。章の題を見出しと同じ文言にする。章の頭で再掲するとき現在の章を示す（色だけにせず、太さ・印・「いま」のラベル）

### 2-14. ノティフィケーションバナー `notification-banner`（意味の色の根拠）

https://design.digital.go.jp/dads/components/notification-banner/

- 種類: **サクセス**（操作の完了）・**エラー**（正しく完了しなかった）・**警告**（注意喚起）・**情報提示（Info）**（セマンティックでない重要な情報。1: プライマリーの色相、2: ニュートラルの黒）。スタイルは「スタンダード」と「カラーチップ」
- パーツ: ①アイコン（必須）②タイトル（必須）③閉じるボタン④年月日⑤デスクリプション⑥アクションボタン
- **コントラストの作例（警告・黄）**: バナーの外枠と警告アイコンは非テキストなので白に対して 3:1 以上 → `warning-yellow-1`（`#B78F00`）。アクションボタンのラベル（白）はテキストなので、ボタンの背景に対して 4.5:1 以上 → `warning-yellow-2`（`#927200`）
- 固定表示（`position: fixed` など）なら「× 閉じる」を必ず付ける。「閉じる」をアクションボタンで作らない
- スライドへの転用: `notice` の種類の色・アイコン（成功・エラー・警告・情報）の決め方に使う。バナーそのものは使わない

### 2-15. アコーディオン・ディスクロージャー（スライドで使わない理由）

- どちらも**隠す**ためのコンポーネントで、重要な情報には使えない。スライドは見せるもの。補足を隠すなら、`talk`（話す台本）かノートへ
- 画面では `<details>` を使う（キーボード操作と WAI-ARIA が要らなくなる）。リターンリンクのラベルは「『ヘッダー』の先頭に戻る」

## 3. 画面で使うもの（要点）

画面の作り直しで使う。細かい寸法は Figma 側なので、サイトに無いものは不明とする。

### 3-1. ボタン `button`

https://design.digital.go.jp/dads/components/button/

- **3 スタイル**: 塗り（背景が色付き・ラベルが White）・アウトライン（外周とラベルが色付き・背景が White）・テキスト（透明・下線つきの色付きラベル）。重要度の階層は 塗り = プライマリー（高）・アウトライン = セカンダリー（中）・テキスト = ターシャリー（低）
- **使う数**: プライマリーは 1 画面に原則 **1 つ**。セカンダリーは文脈ごとに原則最大 **3 つ**（4 つ以上ならフロー自体を見直す）。ターシャリーは**キャンセル行為**のために 1 つまで
- **配置**: 進める（OK・完了・次へ）は**右**、進めない（キャンセル・戻る）は**左**。デスクトップはプライマリーが右端。モバイルは縦積みで、DOM の順と見た目の順を合わせる（プライマリーが上、ターシャリーは一番下）。1 つだけのときは、フローなら右端、モーダルダイアログ・緊急時バナーなら中央
- **大きさ**: ボタンは文字量に応じた可変幅で、スタイルごとに最小幅・最小高さがある。**ターゲットは 44px 以上**（Small・X-Small は上下に余白を足して確保）。Figma の作例（ローカルデザインシステムのガイダンスの図）には、高さ 56・48・36・28 のボタンが並ぶ（Large・Medium・Small・X-Small にあたる）
- **コントラスト**: ラベル 4.5:1・ボタンの面と背景 3:1・アウトラインは背景と面（White）の両方に 3:1
- **重要度を色だけで区別しない**（塗りとアウトラインで形を変える）
- **disabled を原則使わない**（押せない理由が分からない）。必要なら理由と条件を近くに書く
- アイコンだけのボタンは `aria-label` で代替テキスト。ページ遷移ボタンは hover で pointer にしてよい

### 3-2. フォーム部品

- **インプットテキスト**（https://design.digital.go.jp/dads/components/input-text/）: 構成は 入力フィールド・項目ラベル（必須）・要否ラベル（「※必須」「※任意」）・サポートテキスト・エラーテキスト。ラベルとサポートテキストは縦に積む。エラーテキストは冒頭に「＊」。サイズは周囲の UI 密度に合わせる。**プレースホルダー・disabled・readonly・maxlength を使わない**。穴埋め文章にしない・文字種を限定しない
- **テキストエリア**: 構成はインプットテキストに文字数カウンターを足したもの。最大文字数はラベルに書き、おおむね 20 字を超える・スクロールが要るなら文字数カウンターを併記する
- **セレクトボックス**: 6 つ以上の選択肢のとき。5 つ以下はラジオボタン。リストは OS 標準のスタイル
- **チェックボックス**: 複数選択・単一のオンオフ。テキストの左に置く。単一回答はラジオボタン
- **ラジオボタン**: 1 つだけ選ぶ。選択解除できないので、任意なら「あてはまるものはない」を設ける
- **スイッチ**: 切り替えたら即座に反映され、結果がその場で分かる設定。確定操作が要るものはチェックボックス・ラジオボタン
- **ファイルアップロード**: **ファイル選択ボタンを必ず置く**（ドロップだけにしない）。ドロップエリアはボタンの後ろに「または、このエリア内にドラッグ＆ドロップ」。ボタンとチェックボックスの間は 56px 以上
- **日付ピッカー**: 年月日の入力フィールド 3 つ（Consolidated／Separated）。`<select>`・`<input type="date">` を避ける。全角数字・ゼロ埋めは自動で直す。フォーカスを自動で移動しない

### 3-3. 通知・ダイアログ・ナビゲーション

- **ノティフィケーションバナー**: 上の 2-14。ページ上部のファーストビューに。リンクがあるときは、アクションボタンとして**プライマリーボタンを 1 つ**付け、バナー全体を押せる。選択的な行動ならプライマリーとセカンダリー。閉じたことを記憶し、再表示の救済も用意する
- **モーダルダイアログ**: 破壊的な操作の確認・短いメッセージ。ユーザーのボタン操作なしに出さない・完了通知・告知・ナビゲーションに使わない・フォームを入れない・モーダル外の情報を見ないと判断できないときは使わない。アクションボタンがあるなら閉じるボタンを併用しない。確認ダイアログだけを安全策にしない（取り消し・復元も考える）
- **タブ**: 同じ主題を観点で切り替える（概要・仕様・レビュー）。フィルタリング・手続きの進行には使わない
- **ページナビゲーション**: 一覧を分割した前後・「1/24」。前後が無いときは非表示にする（disabled にしない）
- **パンくずナビゲーション**: ヘッダーとページ見出しの間。長いときは改行
- **水平メニュー・ハンバーガーメニューボタン・モバイルメニュー・ドロワー**: 主要な目的地へ。モバイルはハンバーガー（アイコン＋ラベル）→ドロワー内のモバイルメニュー。ラベルは遷移先のページ名。**ボトムナビゲーションとスクロールトップボタンは非推奨**
- **メニューリスト・メニューリストボックス**: 縦のメニュー・ドロップダウン。クリックで開く（ホバーで開かない）。リンクの強調はエンドアイコンで、リンクとサブメニュー開閉を区別できる別のアイコンにする
- **リソースリスト**: 複数の情報（見出し・説明・リンク・操作）を持つアイテムの一覧。アイテム全体を押せるときは中にリンク・ボタンを置かない。択一・複数選択も可
- **テーブルコントロール・検索ボックス**: テーブルの周りの絞り込み（キーワード）・表示件数・ページ移動。複数条件の詳細検索は検索ボックス

### 3-4. 共通の決まり

- 見出しのレベルを飛ばさない。箇条書きは本物のリスト。表はシンプルな構造
- アイコンはラベルと組む。フォーカスインジケーターは変えない
- 色は 4.5:1・3:1。意味の色にはアイコンとラベル
- ローカルデザインシステムでは、キーカラー・角の形・余白を変えてよい。コンポーネントに備わるアクセシビリティの仕組み（フォーカス・ラベル・強制カラーモード）は外さない

## 4. 非推奨のコンポーネント

- **ボトムナビゲーション**（`bottom-navigation`）: 画面下に固定するとモバイルブラウザの UI・ジェスチャー領域と競合し、DOM の最下部に置くとキーボード・スクリーンリーダーで届きにくい。水平メニューをページ上部に、モバイルはハンバーガーメニューボタン＋モバイルメニュー
- **スクロールトップボタン**（`scroll-top-button`）: 固定配置のボタンがコンテンツを覆い（拡大表示で特に）、キーボードでは最下部まで行かないと届かない。Home キーで足りる
