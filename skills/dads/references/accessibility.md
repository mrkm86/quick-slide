# アクセシビリティの要点（スライドと画面）

DADS はアクセシビリティを最優先に作られている。ここは、**スライド**（html-slide・motion-slide が出す資料）と**画面**（Quick Slide のようなウェブアプリ）に効く要点だけを、DADS の各ページから拾って並べたもの。

> 出典: デジタル庁デザインシステムウェブサイト https://design.digital.go.jp/dads/ のコンテンツを加工して作成（2026-10-08 版の Markdown 一括版をもとに要約・再構成した）。デジタル庁が作成したものではない。出典と加工の表記は [`../README.md`](../README.md)。
> 元のページ: カラー https://design.digital.go.jp/dads/foundations/color/ ／ タイポグラフィ https://design.digital.go.jp/dads/foundations/typography/ ／ アイコン https://design.digital.go.jp/dads/foundations/icon/ ／ レイアウト https://design.digital.go.jp/dads/foundations/layout/ ／ 余白 https://design.digital.go.jp/dads/foundations/spacing/ ／ エレベーション https://design.digital.go.jp/dads/foundations/elevation/ ／ リンクテキスト https://design.digital.go.jp/dads/foundations/link-text/ ／ ガイダンス https://design.digital.go.jp/dads/guidance/accessibility/ ・ https://design.digital.go.jp/dads/guidance/local-design-system/ ／ 各コンポーネントのアクセシビリティ（ボタン・インプットテキスト・テーブル・見出し・箇条書きリスト・カルーセルなど。[`components.md`](components.md) に URL）。

基準は JIS X 8341-3:2016・WCAG 2.2（達成基準の番号は下に併記）。**ローカルデザインシステムは、この骨格（下の「規定値を下回らない」）を維持した範囲でしか変えてはならない。**

## 0. ローカルデザインシステムで変えてはいけないもの

ガイダンス「ローカルデザインシステム」より。ブランドの色・角・余白は変えてよいが、次は編集後も満たす。

| 基本デザイン | 編集後も満たすこと |
|---|---|
| カラー | テキストと背景 **4.5:1 以上**。枠線・ディバイダーなど非テキストと背景 **3:1 以上**。セマンティックカラーの色相と意味の結びつきは変えない |
| タイポグラフィ | 本文・UI は **16px が基準値**。**14px 未満は原則使わない**。読み物の本文の行高は **1.5 倍以上** |
| 余白 | 間隔値に規則性を持たせる。インタラクティブ要素の**ターゲットサイズを確保**する |
| エレベーション | 高さを持つ要素は、置かれる面に **3:1 以上**。影は 1 色でないので、要素に**ボーダー**を持たせて確保する |
| リンクテキスト | 色以外の装飾（下線など）と組む。青以外なら、コントラスト・色覚多様性・リンクだと分かることに配慮 |
| レイアウト | **リキッドレイアウト**。視覚的な配置と読み上げ順序を一致させる |

加えて、コンポーネントに備わる仕組みを外さない: **アイコンはラベルと組む**／**フォーカスインジケーターは変更してはならない**／強制カラーモードでも境界・状態が分かる実装を保つ。

## 1. コントラスト（1.4.3・1.4.11・1.4.6）

| 対象 | 必要な比 | 補足 |
|---|---|---|
| **テキスト・文字画像**（大きさに関わらず） | **4.5:1 以上** | WCAG は大きな文字（24px 以上・太字 18px 以上）を 3:1 に緩めるが、**DADS は使わない**。スライドの特大の文字も 4.5:1 |
| アイコン（ラベルと組むもの） | **4.5:1 以上** | リードアイコン・テールアイコンはテキストの一部になりうるため。非テキストとしてしか使わないと保証できる場合だけ 3:1 |
| 非テキスト（枠・罫・図形・グラフの面・ボタンの面） | **3:1 以上** | 隣接する色との間で。UI コンポーネントとグラフィカルオブジェクト |
| カードなどのコンテナの外周 | **3:1 以上** | 外側の背景に対して。**外周を必ず持つ**（影だけで境界を表さない） |
| フォーカスインジケーター | 3:1 以上 | それ自体が非テキスト（DADS の黄＋黒の二重はこれを満たす） |
| 適用除外 | — | 無効（disabled）の UI・純粋な装飾・重要でない写真の中の文字・ロゴとブランド名 |

守り方:

- **前景を決めたら背景も決める**。テキストの色を指定したら、その文字が載りうる背景色もすべて指定する（F24）
- **背景が白・黒以外のとき**（キーカラーの淡い地・写真・色の面）は、必ず測り直す。白の上で通った色が、淡い地の上で通るとは限らない
- **写真の上の文字**（カルーセルの仕様より）: 背景が一定でないときは**最もコントラストが低くなる箇所**で測る。写真・図版の上に文字を載せるときは、**文字に帯の背景を敷く**（または文字を縁取る）。図形・アイコンは 3:1 以上、足りなければ帯か枠線で確保する。画像の内側 2px ほどは枠線が重なるので、読み取るべき要素を置かない
- **グラフ・図解**: 目盛り線などが 3:1 を満たさないときは、値のすぐ近くに 4.5:1 のテキストを置く。凡例だけに頼らず、値と名前を直接書く。フォーカスしていない側が薄く見える図は、一部にコントラストを満たした文字を置く。インフォグラフィックは満たしにくいので、**同じ情報を文章でも用意する**（簡潔でなくてよい）
- **ドロップシャドウでコントラストは稼げない**。影が無くても成り立つように、ボーダーと面の色で 3:1 を確保する
- ブランドの色が足りないとき: 同じ色相で明度だけを動かす（[`../scripts/keycolors.py`](../scripts/keycolors.py)）。ロゴの色は対象外なので加工しない

測る: `python3 skills/dads/scripts/keycolors.py --contrast '#006f83' '#e9f7f9'`

## 2. 色だけに頼らない（1.4.1）・色覚多様性

- 状態・種類・重要度を**色の違いだけで区別しない**。形（塗り／枠／下線）・アイコン・ラベルの文字を足す
  - ボタンの重要度: プライマリー = 塗り、セカンダリー = アウトライン、ターシャリー = テキスト（下線）。色だけで階層にしない（アウトラインだけで階層を作るなら太さや二重線で変える）
  - **成功・エラー・警告は、アイコンとラベルを必ず添える**（注釈ブロック・ノティフィケーションバナー・チップラベル）。チップラベルは「色だけで意味を伝えない・色を使いすぎない」
  - リンクは色だけにせず**下線**など
  - グラフ・凡例は色以外（直接ラベル・パターン・形）でも区別できるようにする
- 色覚多様性（約 290 万人）: 赤と緑の識別が難しい人が多い。赤と緑だけの組み合わせを避ける。配色はカラーユニバーサルデザイン推奨配色セットを参考にする
- リンクの青と訪問済みの紫は見分けにくい。紫に少し赤みを足して明度差を作る
- 印刷・白黒表示でも読める（色数に制約のある環境）
- セマンティックカラーの意味は変えない（エラー＝赤・成功＝緑）

## 3. 文字（1.4.4・1.4.8・1.4.12・1.4.5）

- **大きさ**: 本文・UI は **16px 以上**が基準。14px は付随情報や領域の制約があるときだけ。**14px 未満は原則許容されない**。（スライドは遠くから見るので、スライド用の下限は [`slide-local.md`](slide-local.md) で上げている: 本文 24・注記 22・透かし 16）
- **行高**: 読み物の本文は**文字の 1.5 倍以上**。見出しなど大きな文字は 140% まで下げてよい。1 行だけの UI は 100%
- **段落の間**: 行ボックスの高さの 1.5 倍以上（文字の 2.25 倍以上）が望ましい
- **行の長さ**: 全角 40 字（半角 80 字）程度が目安。長い行は読み書き障害・視覚障害の人に負担。目次・概要・見出し構造などの工夫があれば超えてよい
- **イタリック・両端揃え・空白で位置合わせをしない**。日本語のイタリックは合成の斜体で読みにくい。両端揃えは文字間が空いて拡大ソフトで読めない。空白文字（全角スペース・`&nbsp;`）で位置を揃えない（スクリーンリーダーで言葉が壊れる）
- **文字を画像にしない**（ロゴタイプを除く）。閲覧者が書体や大きさを変えても読めるように。（スライドは PPTX の文字・図形を本物の文字で出す・画像に焼かない）
- テキストを 200% に拡大しても、読みやすさと機能が変わらないこと（画面）

## 4. アイコン

- **必ずラベルと組む**。アイコンだけの項目を作らない（視覚障害・意味の多義性・安定した情報伝達のため）
- ラベルと組むアイコンに代替テキストは付けない（`alt=""`。`aria-label` を付けない）
- ラベルがリンクなら、アイコンもリンク範囲に入れる（`<a>` を 2 つに分けない）
- やむを得ず単体にするなら、ラベル相当の代替テキストを付け、アクションを伴うなら **44×44px 以上**
- 色は背景に対して 4.5:1 以上
- アイコンで意味が分かれる操作は、ちがう見た目にする（リンクとアコーディオンをシェブロンの向きだけで区別しない）

## 5. 見る順・読み上げ順・フォーカス順（1.3.2・2.4.3）

- **視覚的な配置と読み上げ順序をできるだけ一致させる**。スクリーンリーダーの順序とタブ順は DOM の順序で、CSS の `order`・グリッド配置では変わらない。`order`・`grid-placement` は視覚的な並べ替えだけに使い、大きく外れるなら DOM の順序を直す
  - 例外として許される形: ボタンの並び（モバイルは縦積みで DOM の順、デスクトップは右がプライマリーで `row-reverse`）のように、レスポンシブで許容される範囲の不一致
- `tabindex` に **0 と -1 以外を使わない**（1 以上を使うならページ内のすべてのフォーカス可能要素に付ける）
- 見出しは**レベルを飛ばさない**。セクションの主題は見出しで、箇条書きや定義リストで見出しの代わりにしない。見出しがいらない文書（物語・発話録）に無理に付けない
- 箇条書きは本物のリスト（`<ul>`）にする（中黒・スペースで再現しない）。項番は文字として書く（`<ol>` と CSS カウンターを使わない）
- **スライド**: 上から下・左から右の見る順と、PPTX の部品の順（読み上げ・アニメーションの順）を合わせる。グリッドで左右に並べた箱は、左から右の順に出す。見る順と出る順が違う図は、順番を番号・矢印・文字でも示す

## 6. ターゲットサイズとフォーカス（2.5.5・2.5.8・2.4.7・2.4.13）— 画面

- **ボタンは 44×44px 以上**。大きさが足りないボタン（Small・X-Small）は上下に余白を足してターゲットを確保する。隣接するボタン・リンクと重ならないこと
- ボタン以外のリンクも 44×44px が望ましいが、**最低 24×24px**。インラインのリンクは、高さが 24 に満たなくても上下 4px ずつの余白があればよい
- **フォーカスインジケーターは変更しない**。黄（Yellow-300）と黒の 2 重構造。キーボード操作でどこにいるかが常に見えること。フォーカスを隠さない（スクロールトップボタンのような固定要素が覆わないように）
- すべての機能をキーボードだけで操作できる。キーボードトラップを作らない。ドラッグだけの操作を作らない（ファイルアップロードは必ずファイル選択ボタンを置く）
- カスタムコンポーネント（`<details>` を使わないアコーディオンなど）は、キーボード操作と WAI-ARIA の状態・プロパティを付ける（ARIA Authoring Practices Guide に従う）
- ページ遷移をもたらすボタンは、hover で指のカーソル（pointer）にしてよい

## 7. 無効・入力・メッセージ — 画面

- **無効（disabled）のボタン・フィールドを原則使わない**。タブフォーカスで届かず、なぜ押せないのかも分からない。押せない理由と有効にする条件を近くに書く。どうしても使うなら `aria-disabled` を使い、見た目も無効に見せ、近くに説明を書く
- 入力フィールド: **ラベル必須・プレースホルダーテキストを使わない**（コントラストが低い・入力中に消える）。条件や例は**サポートテキスト**に。編集不可（readonly）も原則使わず、地の文で見せる
- エラーテキスト: 具体的な内容と直し方を書き、冒頭に「＊」を付ける。要否ラベルは「※必須」「※任意」。エラーを **`aria-live`・`role="alert"` で割り込ませない**（`aria-describedby` で結びつける）
- `maxlength` を使わない・コピー＆ペーストを無効にしない・メールアドレスを前後に分割しない・値の変更だけで画面を予期せず変えない（3.2.1・3.2.2）
- モーダルダイアログは、ユーザーのボタン操作なしに出さない。フォームを入れない。完了通知や告知に使わない。アクション（OK・キャンセル）があるなら閉じるボタンを併用しない
- ノティフィケーションバナーは固定表示（`position: fixed`・`sticky`）にするとき、必ず「× 閉じる」を付ける。緊急時バナーは緊急性の高い情報だけ・長期間掲げない
- チェックボックスはテキストの左に置く（拡大表示でも見つけやすい）

## 8. 動き（2.2.2・2.3.3）

- 自動で動き続ける・切り替わる表現を避ける。DADS のカルーセルは**自動再生を持たず**（再生・停止の仕組みを持たず）、アニメーションもしない。ユーザー自身の操作で切り替える。変化盲（集中の範囲外の変化に気づけない）があるため、重要な情報をカルーセルに隠さない
- プログレスインジケーターは、画面全体の処理中だけ回る・動く（サークル・リニア）。一部分の処理中は動かない砂時計。画面の一部が動き続けて他に注視できなくなるのを避ける。スケルトン UI は使わない
- **スライド**: 動きは意味を足すためだけに使う。点滅（3 回/秒以上）を作らない。動きで出す内容は、止めた状態（PDF・ページの画像）でも全部読める形にする

## 9. 強制カラーモード・オーバーレイ

- 強制カラーモードでも要素の境界と状態が分かるように、コードスニペットの実装に従う
- オーバーレイシェードの上の要素にも**必ずボーダー**を付ける（透明でもよい）。シェードが無効になっても、ページに溶け込まない

## 10. スライドで守る早見（チェックリスト）

1. 文字はすべて 4.5:1 以上（特大の文字・薄い注記・透かしも）。地が白でないページは測り直す
2. 枠・罫・図形・グラフの面は隣接する色に 3:1 以上。箱（カード）は外周を持つ
3. 成功・エラー・警告・良し悪しは、色だけでなくアイコンとラベル
4. アイコンはラベルと組む（アイコンだけの項目なし）・4.5:1
5. 写真の上の文字は帯を敷く（最悪の箇所で 4.5:1）
6. 見る順 = 部品の順 = 出る順
7. 文字の下限（本文 24・注記 22・透かし 16）を割らない。行高は本文 150% 以上
8. 1 行は全角 40 字程度まで（遠くから見る資料は短く）
9. 図解・グラフは、値と名前を直接書く。必要なら同じ内容を文章（ノート・代替）でも
10. 文字を画像に焼かない

## 11. 画面で守る早見（チェックリスト）

1. ボタンとリンクのターゲットは 44×44px 以上（最低 24×24px）
2. フォーカスが見える（黄＋黒・変更しない）・キーボードだけで一通り操作できる
3. 文字 4.5:1・非テキスト 3:1・コンテナは外周あり・影に頼らない
4. 色だけで状態を表さない（ステータスはチップラベルの文字・アイコン）
5. アイコンはラベルと組む（単体なら代替テキスト＋44px）
6. 入力はラベル・サポートテキスト・エラーテキスト。プレースホルダー・disabled・readonly を使わない
7. 見出しのレベルを飛ばさない・リストはリスト・表はシンプルな構造
8. 200% に拡大してもレイアウトが崩れない（リキッドレイアウト）
9. 自動で動かない・点滅しない
10. DOM の順序 = 見た目の順序
