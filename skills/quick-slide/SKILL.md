# Quick Slide（会話から 1 冊・会話から直す）

会話の続きからスライドを作る入口。**画面から新しいスライドを作る経路は無い**ので、ここで原稿を整えて投入するところまでが
このスキルの仕事。投入したあと、台本係（このプラグインを載せた Claude Code か Codex をサブスク枠で呼ぶ）が台本を書き、
エンジンの検査に通し、描き係がエンジンで描く。進みはスライドの画面が実況する。
できたスライドは、会話からもページを指定して直せる（下の「5. 会話から直す」）。

## 鉄則

1. **サーバは自分で起こす。** 「Quick Slide を起動してから教えてください」と言わない。下のスクリプトが
   状態を見て、落ちていれば起こし、health を待つ（二重起動はサーバの錠が拒む）
2. **原稿を整えるのはこのスキル（あなた）の仕事。** サーバは会話を読めない。品質はここで決まる
3. **出た URL は必ず会話に残す。** 内蔵ブラウザで開けても、開けなくても、URL は本文に書く
4. **原稿本文を stdout・ログ・報告に貼らない。** 投入はファイル経由で行う
5. **会話で見つけていない数字は足さない。** 調べてまとめるときも、見つけた資料に書いてある数字だけを使い、出典を添える

## 手順

### 0. 最初の 1 冊の作り方を決める（2 つ）

頼まれ方で、構成を見せてから描くか、見せずにそのまま描くかを決める。

| 頼まれ方 | 進め方 |
|---|---|
| **人に見せる資料**（「提案資料にして」「発表のスライドを」「企画書に」「〇〇さんに見せる」「配る資料」） | **A. 構成を見せて、合意してから描く** |
| **自分が知るため**（「〇〇について調べて 5 ページぐらいでまとめて」「ざっと知りたい」「自分用に整理して」） | **B. 調べて、構成を見せずにそのまま描く** |

- 判定の語: 「調べて・まとめて・ざっと知りたい・自分用」→ B ／「資料・提案・発表・企画・〇〇に見せる・配る」→ A
- **迷ったら B**（描いたあとでもページを指定して直せるので、聞く手間の方が高い）
- 「構成を見せて」と言われたら A、「おまかせで」と言われたら B（構成を見せずに投入する。`--outline-fixed` は付けない）

#### A. 構成を見せて、合意してから描く

1. 会話の中身から**構成**を作り、会話に出す。1 ページずつ、次の形で書く（見出しは名札ではなく、そのページで言いたいこと 1 文）:

   ```markdown
   ## 1. 会議の時間は3年で1.4倍に増えた
   - 1 人あたり週 11.5 時間（社内の調べ）
   - 増えたのは定例と報告の会
   画像: なし

   ## 2. 25分を基本にすれば半分にできる
   - 3 つのルール: 25 分・議題は前日まで・決めたらその場で閉じる
   画像: 窓の近くで立って話す小さなチーム
   ```

   - 画像は「画像: なし」か「画像: 何の絵か」（構造・手順・数字は図で見せるので、なしが多くてよい）
   - 枚数を言われていなければ、話の量に合わせる（目安 5〜12 枚）
2. **合意を取る。** 直しを言われたら構成を直して見せ直す（ここではまだ描かない）
3. 合意した構成を、そのまま原稿のファイルに書く（冒頭に `# 仮タイトル`）。**`--outline-fixed` を付けて投入する**。
   台本係はページの数・順番・各ページの主張を変えず、表現・型・画像の枠だけを決める
4. URL を会話に書く（下の 4.）。`--wait` を付けたなら、できたページの見出しも返る

#### B. 調べて、構成を見せずにそのまま描く

1. 会話の側で調べる（Web 検索。読めた資料だけを使う）
2. 原稿を書く（下の 2. の形）。調べた事実には**出典**を `出典: 資料名（URL）` の行で添える（台本係が、そのことを
   述べるページの `source` に書く）。**数字は、読んだ資料に書いてあったものだけ**。見つからない数字は書かない・推計しない
3. 構成を見せずに投入する（`--wait` を付ける。`--outline-fixed` は付けない）
4. できたら、URL と、各ページの見出しを 1 行ずつ会話に返す（出力の `pages[].title`）。
   「直したいところがあればページの番号で言ってください」と添える

### 1. モードを選ぶ（あとから替えられない）

| モード | 作るもの | 向いているとき |
|---|---|---|
| `presentation`（既定） | 文字も図形も PowerPoint の部品として組んだ、**あとから直せて、クリックで動く PPTX**（エンジン html-slide） | 説明・報告・提案。数字や文言をあとで直す・話しながら見せる |
| `pitch` | 各ページを**画像生成で丸ごと描いた**資料（エンジン image-slide）。PPTX にも絵として入る | 印象で伝えるピッチ・企画のイメージ。絵の中の文字はあとで直せない |

迷ったら `presentation`。ユーザーが「絵で」「イメージで」「ワクワクする感じで」と言ったら `pitch`。
スタイルは `--style`（presentation: `standard` 既定・`visual`／pitch: `visual` 既定・`standard`・`infographic`＝全ページを 1 枚のポスターに）。
絵の画風を言われたら `--image-look photo|illustration|handdrawn`。絵を入れたくないと言われたら `--no-images`。

### 2. 会話を原稿にする

| | 残す | 落とす |
|---|---|---|
| 主張 | ユーザーの主張・結論・決定事項（誰が何を決めたか）。採用した案と、却下した案の**結論**（却下したという事実） | 撤回された案・採用されなかった提案の中身、言い直しの途中経過 |
| 事実 | 数値・日付・固有名詞・比較（単位、前年比、出典の言及まで）。会話に出た**そのままの値** | 会話に無い数値・事例・引用。**捏造しない**。補足が要るなら `[要確認]` と書く |
| 未決 | 未決事項・保留・反対意見は「未確定」と明示して残す | 曖昧なものを断定に変えること |
| 文脈 | 目的・想定読者・使う場面（語られていれば `--purpose` / `--audience` にも入れる）。「これはスライドに入れて」と明示されたもの | 挨拶・相槌・前置き・感情表現・雑談。「スライドにしたい」以前の無関係な話題。Quick Slide 自体の操作に関する会話 |
| 技術 | 要点を文章にしたもの。必要なら**短い**コード断片 | ツールの実行ログ、コマンドとその出力、スタックトレース、生の URL の羅列 |
| 秘匿 | — | 鍵・パスワード・トークン・個人情報・「載せない」と言われたもの。除いた箇所は `[秘匿]` と置く（黙って消さない） |
| 画像 | 本文に `[画像: 何の図か]` と書く（どこに絵を置くかは台本係が決める） | 画像を base64 等で本文に埋めること |

形式: Markdown。冒頭に `# 仮タイトル`（`--title` と一致させる）。見出しは**話題単位**であって章立ての提案ではない
（何枚でどう分けるか・どの型で見せるかは台本係が決める）。箇条書き主体で 1 項目 1 主張。
**A（構成を合意した）ときだけは、合意した構成をそのまま原稿にする**（`## N. 見出し` が 1 ページ。`--outline-fixed`）。
調べたことには出典の行（`出典: 資料名（URL）`）を添える。
話者を再現しない（「私」「あなた」「AI が言った」を書かず、第三者が読める文体にする）。
発言順ではなく論理順に並べ替えてよいが意味は変えない。**原稿は要点であり議事録ではない。**

原稿は一時ファイルに書く（会話に本文を貼り直さない）。

### 3. 投入する

```bash
python3 "${SKILL_DIR}/scripts/quick_slide_start.py" \
  --manuscript-file /path/to/manuscript.md \
  --title "仮タイトル" \
  --mode presentation \
  --purpose "この資料の目的" \
  --audience "想定読者" \
  --pages 8
```

`${SKILL_DIR}` はこのファイルのあるディレクトリ。スクリプトは Python 3 の標準ライブラリだけで動き、サーバの本体は
このプラグインの根（`${SKILL_DIR}` の 2 つ上）の `src/` から探す（`QUICK_SLIDE_REPO` か `--repo` で差し替えられる）。

| オプション | 意味 |
|---|---|
| `--manuscript-file` | 原稿（Markdown, UTF-8）。**必須** |
| `--title` | 仮の題。無ければ「無題のスライド（日時）」 |
| `--mode` | `presentation`（既定）／`pitch` |
| `--style` / `--image-look` / `--no-images` | 上の「モードを選ぶ」 |
| `--purpose` / `--audience` / `--style-note` / `--pages` | 会話で分かっている範囲だけ。分からないものは渡さない（`--pages` は枚数） |
| `--outline-fixed` | 原稿は会話で合意した構成（`## N. 見出し` が 1 ページ）。A のときだけ付ける |
| `--wait`（`--wait-timeout` 秒・既定 900） | 描き終える（か失敗する）まで待ち、ページの見出し（`pages`）を返す。B では必ず付ける |
| `--brand-id` | ブランドの UUID（名前では指定できない。分からなければ渡さない） |
| `--style-id` | スライドスタイルの UUID（設定の画面で登録したもの。分からなければ渡さない。`--style` と一緒なら `--style` が勝つ） |
| `--new-deck` | 同じ内容を送り直したときも、必ず新しいスライドにする（既定では、同じ会話から 10 分以内に同じ内容が届くと同じスライドを返す） |
| `--ensure-launch <launch_id>` / `--url` / `--browser-mode` | 下の「4.」 |
| `--dry-run` | 投入せず、サーバの起動と payload の要約だけ出す |
| `--where` | どこを本体として見ているか（サーバは起こさない） |

stdout の**最終行は JSON 1 行**。終了コードは 0=成功 / 2=入力の誤り / 3=起動できない・届かない / 4=処理の失敗。
成功時の主なキー: `url`・`deck_id`・`deck_title`・`mode`・`launch_id`・`message`。`--wait` のときは `result`（done / failed）・
`pages`（`no`・`title`）も入る。

### 4. URL を開き、開けたか確かめ、会話に書く

1. **内蔵ブラウザ（アプリの中のブラウザ）で `url` を開く。** 開けるのは会話しているアプリだけで、スクリプトからは開けない
2. **見せたらすぐ `--ensure-launch` を呼ぶ。**

```bash
python3 "${SKILL_DIR}/scripts/quick_slide_start.py" --ensure-launch <launch_id> --url "<url>"
```

   開けたかどうかは**サーバに開いた合図（attach）が届いたかでしか分からない**。この呼び出しが合図を待ち、来なければ
   外部ブラウザで開き、それでも来なければ「URL を開いてください」を返す（待つ秒数と順序はサーバの設定が決める）。

   | `route` | 起きたこと | 会話に何を書くか |
   |---|---|---|
   | `integrated` | 待っている間に画面が開いた | URL だけ |
   | `external` | 外部ブラウザで開いた | URL だけ |
   | `url_only` | どちらでも開けなかった | URL と、返った `message` |
   | `manual` | 設定が「開かず URL だけ」 | URL と、返った `message` |

3. **どの経路でも、URL は必ず会話の本文に残す。** `url` の起動トークンは 1 回しか使えないので、同じ URL を 2 か所で開かない

会話に書く文は JSON の `message` をそのまま使い、続けて URL を書く。台本を書いて描き終えるまで数分かかること
（ページはでき次第、画面に出る）を一言添える。

### 5. 会話から直す（ページを指定する）

「7・8枚目の見出しを短く」「3枚目の写真を夜に」のように頼まれたら、**ページを指定して**直す。全体の書き直しはまれ。

```bash
python3 "${SKILL_DIR}/scripts/quick_slide_start.py" --revise --pages 7,8 --note "見出しを短くして、数字を大きく" --wait
```

| オプション | 意味 |
|---|---|
| `--pages 7,8`（`7-9` も可） | 直すページの番号（画面の番号。非表示のページも数える）。省くとスライド全体への指示 |
| `--note` / `--note-file` | 何をどう直すか（利用者の言葉のまま。秘匿は書かない）。**必須**（`--attach` だけでもよい） |
| `--deck <ID>` | 直すスライド。省けば**この会話から作った一番新しいスライド** |
| `--remake` | 絵を直すとき、今の絵を土台にせず描き直す（「いくら言っても変わらない」「テイストを変えたい」とき） |
| `--attach <画像>` | 参考の画像（何度でも）。差し替える写真にも、絵を直す参考にもなる |
| `--wait` | 直し終えるまで待ち、ページの見出しと `suggestions` を返す |

- 文字・中身・構成を直すか、絵だけを直すか（エンジンの revise）は**台本係が振り分ける**（迷ったら文字・構成の直し）。
  指定外のページは 1 文字も変わらず、描き直されもしない
- 返った `suggestions`（ほかのページも直した方がよいという提案）は**当てられていない**。会話で利用者に伝えて、直すかを聞く
- 出力のキー: `status`（revising / revised / revise_failed）・`deck_id`・`job_id`・`url`・`target_pages`・`queued`・`message`。
  `--wait` のときは `pages`・`summary`・`suggestions` も
- **URL はいつも会話に残す**（`url` は起動のトークンの付かない、何度でも開ける URL）
- 前の姿に戻したい・ページを足す・並べ替える・隠す・複製するは、画面でできる（版スタックの前の版を押す・ページの間の「＋」・左の一覧を掴む・ページの「⋮」）

## まだできないこと

この版では、既存のスライドへの追加（`--append-to-deck`）・新しく作るときの画像の添付（`--attach` は `--revise` と一緒のときだけ）・
会話抜粋（`--transcript-file`）はできない。指定すると `not_ready_in_v2` と理由が返る。そのまま伝え、新しいスライドとして頼み直す。

## つまずいたとき

| 症状 | 見ること |
|---|---|
| `code: server_unavailable` / `server_start_timeout` | メッセージをそのまま伝える。データの置き場の `runtime/server.log` と `server.out` に理由がある |
| `code: server_unreachable` | Codex の砂場が手元（127.0.0.1）への通信を塞いでいる。`codex -c sandbox_workspace_write.network_access=true exec ...` で開ける |
| `code: repo_not_found` / `repo_invalid` | 本体が見つからない。`--where` で探した先を見る |
| `code: secret_like_content` | 原稿に秘密らしい文字列がある。**該当箇所を会話に引用せず**、`[秘匿]` に置き換えて投入し直す |
| `code: validation_error` / `not_ready_in_v2` | サーバの日本語の文がそのまま理由。言い換えずに伝え、渡した値を直す |
| `code: deck_required` / `deck_not_found`（`--revise`） | この会話から作ったスライドが分からない。`--deck` にスライドの ID（URL の `/slides/` の後ろ）を渡す |
| `code: pages_invalid` / `no_pages` | ページの番号が範囲の外・まだページが無い。返った `url` を会話に書き、番号を確かめてもらう |
| `code: wait_timeout` | まだ描いている。`url` を会話に書き、画面で進みを見てもらう（仕事は止まっていない） |
| `status: revise_failed` / `result: failed` | `result_message`（サーバの 1 文）をそのまま伝える |
| 画面に「ログインできていません」の帯 | 台本を書く CLI（`claude` は /login、`codex` は `codex login`）か、絵を描く Codex（`codex login`）のログインが切れている。帯の文のとおりに伝える |

## 秘匿

- 原稿・作風の一言に、鍵・パスワード・トークン・個人情報を入れない。除いた箇所は `[秘匿]` と書く
- 台本係とエンジンは**サブスクのログインだけ**で動く（サーバは子プロセスに API キーの環境変数を渡さない）
- 原稿本文・子プロセスの stderr を、報告やログや JSON に混ぜない。出力 JSON に会話の識別子の生値は載らない
