# Quick Slide の更新

[会話の入口の更新手順](../quick-slide/SKILL.md)を読み、まず同じプラグインの
`skills/quick-slide/scripts/quick_slide_update.py` で最新の版と更新方法を確認する。
更新処理はこのスクリプトを正本とする。手動の補足は [更新手順](../../docs/INSTALL.md#更新する)を参照する。
利用者が両方の更新を頼んだ場合だけ、Codex・Claude 両方を対象にする。

- 更新前に、登録済みマーケットプレイス・インストール先・現在の版・有効状態を確認する。
  このスキルの場所は読み込み済みの古いコピーかもしれない。更新後の CLI の結果から新しい場所を確認する。
- 登録された配布元と ref・インストールの scope を保つ。全マーケットプレイスを一括更新しない。
  配布元が不明なら推測で別のリポジトリを登録せず、必要な情報を尋ねる。
- 非公開配布元へ届かなければ、アクセス権・認証が必要と伝える。公開設定を変更したり、認証情報を文書に保存したりしない。
- ローカルフォルダの更新とインストール済みコピーの更新を区別する。ZIP の最新版がなければ、その取得先を確認する。
  Git 作業コピーに編集があれば上書きせず報告する。更新は fast-forward に限定する。
- 利用者の資料・設定・ログイン情報を削除しない。インストールキャッシュを手で書き換えない。
- 更新後は新しいコピーの `--where` と `--doctor` を実行する。新しい依存ソフトが必要なら
  [セットアップ](../quick-slide-setup/SKILL.md)に従う。更新だけの依頼で無関係な CLI を更新しない。
- サーバの版が古ければ、新しい版の入口が次回利用時に入れ替える。処理中の仕事は完了を待つ。
  更新のためにサーバを手で停止することを既定にしない。Codex から起動できない場合は、新しい入口の `--start-server` を案内する。
- 更新前後の版、実行結果、診断の結果、サーバの入れ替え状況、アプリの再起動など残る操作を返す。
  CLI の更新成功と、デスクトップアプリでの読み込み確認を区別する。更新できなかった場合は完了と報告しない。
