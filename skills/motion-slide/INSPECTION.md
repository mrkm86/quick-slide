# INSPECTION.md — motion-slide

> 共通項目は検品する側の基準にある。**ここには固有項目だけ書く。**
> 作成: 2026-10-06。

## 商品の型

**画面型**（クリックで拍が進む Web プレゼン）。成果物の実体:

```
<出力先>/index.html          # 本体（HTML 1枚。ブラウザで開く）
<出力先>/check/inspect.md    # 検品用の写し（check.py が書く）← 検品役が読むのはこれ
```

`inspect.md` には、場面ごとに 題・拍ごとに増えた画面の文字（出る順）・話す台本・機械の検査（はみ出し・切れ・重なり・泣き別れ）の結果が入っている。
⚠️ **中身は毎回違う。** 題材は呼ぶ側が決める。正解の文面は存在しない。

## 読者

| 読者 | 何ができないと困るか |
|---|---|
| **見る人**（社内のメンバー・客先） | 見出しを順に読むだけで、題材の要点と結論が分かる |
| **話し手** | 話す台本を読みながらクリックすれば、話と画面の変化が合う |

## 必須要素（欠けたら失格）

1. **元の題材に無い数・断定が無い。** 画面の数（件数・年数・割合）と断定（「〜できる」「〜は不要」）は、元の題材（記事・資料）にあるものだけ。図にするために足した例・ケースが、元に無い主張になっていない
2. **見出しが主張で書かれている**（「比較」「まとめ」だけの見出しが、表紙とまとめ以外に無い）
3. **時点と出典がある**（制度・数字・市場の話なら、最後の場面に「いつ時点の、何から作ったか」）
4. **機械の検査が NG 0・警告 0**（`inspect.md` の冒頭の行）
5. **話す台本が拍の数と合っている**（台本のある場面で、拍に台本が無い所が無い）

## 失格条件（あったら失格）

- 元の題材と**向きが逆**になった要約（「必要な場合がある」→「必要」など）
- 公開前・社内限りの題材なのに、外に出す前提の文言（URL の案内・「ご自由にお使いください」等）がある
- 1つの拍で2つ以上の主張が同時に増える（`inspect.md` の「増えた文字」に、別々の主張の文が2つ以上ある）
