# 0002. 動画はページの中の時計を止めて1コマずつ撮る。HyperFrames 向けに書き直さない

- **日付**: 2026-10-06
- **状態**: 採用
- **経緯**: 2026-10-06 の試し

## 決めたこと

- 動画は `scripts/record.py` で作る。`scripts/vclock.js` をページより先に差し込み、タイマー・rAF・`performance.now` を差し替え、CSS の動き（Web Animations）を止めて `currentTime` を時計に合わせ、1コマずつ撮る
- 台本とエンジンの動きの書き方（CSS のトランジション・タイマー）は変えない。発表用の HTML と動画は同じ `index.html` から出す
- 効果音はページが鳴らした記録（`MS.state.sfx`）とエンジンの `MS.renderSfx` で、BGM は HTML の `<audio id="bgm">` で、時刻どおりに重ねる

## 採らなかった案と、その理由

| 案 | 却下した理由 |
|---|---|
| Chrome の仮想時間（CDP `Emulation.setVirtualTimePolicy`）で刻む | 実測で CSS のトランジションが仮想時間に従わなかった（仮想時間を止めて実時間を2秒待つだけで不透明度 0 → 1） |
| エンジンの動きを GSAP のタイムラインに書き直し、HyperFrames で描き出す | 台本とフックの書き方が変わり、書いた台本を全部直すことになる。ページの時計を止める方法で、台本のまま撮れた。HyperFrames は Node と専用の Chrome（約200MB）が要り、入れた機体でしか動かない |
| 画面を実時間で録画する（Playwright の録画など） | コマ落ちが出る。音も入らない |

## 効いてくる制約

- 見た目に乱数を使わない（撮るたびに変わる）。LIVE の部品は既定の値で映る
- `.x` に書く `transition` には `opacity` を入れる（撮って見つかった・check の「パッと出る」）
- html-video の声・口パク・キャラと1本の HyperFrames 合成にはできない

## 見直す条件

- 声・キャラと同じ画面に合成したくなったら、HyperFrames 向けの書き出し（拍ごとの GSAP タイムライン）を検討する
- 撮るのにかかる時間（動画の約 3.5 倍）が問題になったら、コマの撮り方（JPEG の品質・並列）を見直す
