# 0001. 出口は HTML 1枚、台本は場面×拍の HTML、エンジンは build で埋め込む

- **日付**: 2026-10-06
- **状態**: 採用
- **経緯**: 2026-10-06 に Web プレゼンの分析から起こした

> 議論の経緯そのものは上の Issue にある。**ここには写さない**（二重管理で腐るため）。

## 決めたこと

- 出口は**外へ何も取りに行かない HTML 1枚**。エンジン・色・ロゴ・BGM は build が埋め込む
- 台本は **HTML**（`section.scene` × `data-beats`、出入りは `data-in` / `data-out` などの属性、動きは `MS.hook`）。JSON の台本と型は持たない
- 拍の見た目は**フックが毎回丸ごと決める（冪等）**。エンジンは拍が変わるたびにタイマー・線・飛んでいる文字を消してからフックを呼ぶ
- 道しるべ（パンくず・拍の点・章のレール・ここまでの言葉・一覧）・自動再生・効果音・BGM はエンジンが持ち、台本は属性を書くだけ
- 色は **html-slide のテーマ**（`themes/*.yaml`）から作る。正本を2つにしない
- 検査は Chrome で全拍を開いて数える（はみ出し・切れ・重なり・泣き別れ・道しるべとの重なり）。目で見るための一覧画像も出す

## 採らなかった案と、その理由

| 案 | 却下した理由 |
|---|---|
| html-slide のように JSON の台本と画面の型を持つ | Motion Slide の価値は場面ごとの図と動き（城の壁・枠が埋まる・波及する）で、型に収まらない。見本2本とも場面ごとに違う図だった |
| PPTX を出口にする | 拍を1枚ずつ平らにすると 48 拍が 48 枚になり、同じ画面はまとめてほしいと言われた（2026-10-06）。まとめるには html-slide の決まりに退場と強調が要る（保留） |
| WebApp に置いて配る（DB・ストレージ） | 作る側が律速で、需要がまだ分からない。まず1枚で配って反応を見る（最初の1枚で反応を見る段） |
| 効果音を音のファイルで持つ | Web Audio で合成すれば HTML が増えない |
| BGM を音楽生成のモデルで作る | MIDI で書いて macOS 内蔵の音源で鳴らせば、インストール無しで拍に秒単位で合わせられた |

## 効いてくる制約

- 台本の HTML は人（Claude）が場面ごとに書く。**機械が自動で組み立てる経路は無い**（無人の経路を作るなら、型の側を足す必要がある）
- 字体を埋め込まない（端末の字体）。HTML 1枚の大きさ（約 100KB）を守るため
- 公開前の記事・社内の数字を題材にした HTML は、外のサービスに出さない

## 見直す条件

- 同じ形の場面（比較の表・流れ図など）を3回以上書いたら、部品としてエンジンに足す
- 配った反応で WebApp（最新のリンク・閲覧の計測）が要ると分かったら、置き場を決め直す
