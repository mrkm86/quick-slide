# 0004. 場面ごとの拍の絵をキャッシュし、`deck` に「撮らない」口（`--no-shoot`）を足す

- **日付**: 2026-10-11
- **状態**: 採用
- **経緯**: 4〜5 場面・約 20 拍の台本で `deck` が約 1 分かかり、ほとんどが Chrome での拍ごとの撮影（1 拍 約 2 秒の待ち）だった。直したのは 1 場面でも全部撮り直していた。非表示・並べ替えのあとの組み直しにも撮影が付いてきた（docs/EDIT-PLAN.md の段 4）

## 決めたこと

### 場面ごとのキャッシュ（`scripts/shotcache.py`）

- 撮る（`deck`・Chrome を使う `check`）とき、場面ごとに**鍵**を作る。鍵が同じ場面は、置いてある拍の絵（`beats/sNN-bM.png`）・拍ごとの検査の記録・一覧のサムネイルを使い、Chrome で撮るのは鍵が変わった場面だけ。出力のファイル構成は変わらない（`slides/`・`thumbs.png`・`inspect.md`・`check/` は全場面ぶん。一覧画像と `inspect.md` は記録から毎回作り直す）
- **鍵** = SHA-256（次のすべて）:
  - 場面の JSON（`html`・`style`・`script`・`hook`・`talk`・`term`・`ch`・`beats`・`dur`・`thumb`・`class`・`attrs`…）
  - 共通部: 台本の `config`・`style`・`stage`・`script`、テーマの色とロゴ（組み立てた `index.html` に入ったもの。名前や相対パスの解き方に依らない）
  - エンジンの版: `engine/engine.js`・`engine/engine.css`・`scripts/check.py` の中身と、置くものの形の版（`shotcache.FORMAT`）
  - 撮るまでの待ち（`--wait`）と撮る大きさ（1920×1080）
  - 隣の場面から決まって画面に出るもの（`engine.js` の `chrome()` が計算するもの）: 場面の番号と総数・前の場面までの拍の数と総拍数（進み具合の帯と「n / N」）・「ここまでの言葉」（直近 `terms` 個と隠れた数）・章のレールの並び（同じ章の場面の題と、その中の位置）
- 場面の文脈を鍵に入れたので、前の場面の `term` を直すと、その場面と後ろの場面が撮り直しになる。末尾の場面の直しは、その場面だけ。拍の数を変えると、後ろの場面の「n / N」が動くので後ろも撮り直す。ここは見た目を優先して厳密にした
- 台本の題（`title`）は絵に出ないので鍵に入れない
- 置き場: html-slide の `cache.py`・`places.py` と同じ決め方（`MOTION_SLIDE_CACHE`、無ければ設定の `cache_dir`、無ければ macOS は `~/Library/Caches/quick-slide/motion-slide/`）。`<置き場>/scenes/<鍵>/`。出力フォルダごとの区画は切らず鍵で引く（`check` で撮った絵を `deck` が使える）。上限は設定の `cache_max_mb`（既定 1024・0 は消さない）で、超えたら最後に使った時刻の古い場面から消す（今回使った場面と 10 分以内に使われた場面は消さない）
- 撮るときの動きは今まで通り「場面へ直に飛び（`MS.go(場面, 拍 - 1)`）、1 つ進めて撮る」。前の場面を撮ったかどうかに依らないので、場面を飛ばして撮っても同じ絵になる（`check.py --only` と同じ道）
- JS のエラー・はみ出し・切れ（NG）があった場面は置かない（偶然の失敗を居座らせない）。警告だけの場面は置く（警告は記録に入っていて、`--strict` の判定は毎回かけ直す）
- 一覧（Esc / O）のサムネイルは、`build.py` で別に撮らず（Chrome をもう 1 回起動していた）、拍の絵（場面の `thumb`、無ければ最後の拍）から作って埋める。待ちは `--wait` になる（以前は 2.2 秒固定）

### `deck --no-shoot`

- 形の検査と `index.html`・`deck.html`・`build.json`・`deck-info.json` の組み立てだけを行い、**Chrome を起動しない**（1 秒前後）。`slides/`・`thumbs.png`・`inspect.md`・`check/` には触らない（前の回の絵のまま）
- 呼ぶ側が分かるように: stdout に `pictures: not-taken（…）` の行（撮ったときは `shots: 撮った場面 N・キャッシュから M`）、`build.json`・`deck-info.json` に `"pictures": {"taken": false, "reason": "no-shoot"}`・`"check": null`（撮ったときは `"pictures": {"taken": true, "shot": N, "reused": M}`）。`slides` の行は台本の場面どおりで、絵のパスは前の回のもの
- 一覧のサムネイルは、同じ鍵の場面のキャッシュ、無ければ前の `index.html` のものを使う（新しい場面はサムネイル無し）。Playwright が無くても動く
- `--no-cache` は、キャッシュを読まず全部撮り直す（撮ったものは置く）

## 採らなかった案と、その理由

| 案 | 却下した理由 |
|---|---|
| 出力フォルダごとの区画（html-slide の `cache.area`）に置く | `check` と `deck` で絵を分け合えず、出力フォルダを変えると全部撮り直しになる。鍵が内容そのものなので、区画で分ける意味が無い |
| 鍵を「場面の JSON と台本全体」にする | 1 場面の直しで全場面の鍵が変わる |
| 鍵に隣の場面の文脈を入れない | 「ここまでの言葉」・進み具合の帯・章のレールが古い絵が出る。速さより見た目を取る |
| 場面を順に進めたまま、キャッシュの場面だけ待ち・撮影を省く | 飛ぶのに比べて速くならず（飛んでも前の場面の状態に依らない）、場面を移るたびに前の拍へ戻る分だけ遅い |
| `--quick`（`check` の形だけ）に組み立てを足す | `check` は出力を持たない。出力を持つ `deck` に口を足すほうが、呼ぶ側の違いが小さい |

## 効いてくる制約

- 鍵はテーマ・ロゴ・エンジンの 3 ファイルを見るが、**端末の字体・Chrome の版**は見ない。字体や Chrome を入れ替えたときは `--no-cache` を付けるか置き場を消す
- 場面を飛ばして撮ると、`MS.go` が最初に渡す前の位置（`ctx.prev`）が連続して撮った場合と違う。`prev.S` を使う `hook` は拍 1 の絵が変わりうる（見本では無し）。違いが出たら、その場面は `--no-cache` で撮り直す
- 場面ごとの `@keyframes` は台本全体で名前が共有される（CSS の検査も許している）。同じ名前を別の定義で場面ごとに持つ台本は、鍵が場面の JSON だけを見るので、隣の場面の定義の変更を拾わない。名前は場面ごとに変える
