# 同梱の見本

プレゼン・ピッチ・モーションの見本（それぞれのモードの紹介）を 1 冊ずつ置く。サーバを最初に起こしたときに、普通のスライドとして入る
（タグ「見本」）。決めたことと理由は [`docs/adr/0006-bundled-samples.md`](../docs/adr/0006-bundled-samples.md)。

| フォルダ | モード | エンジン |
|---|---|---|
| `presentation/` | プレゼン | html-slide |
| `pitch/` | ピッチ | image-slide（絵は Codex で描く） |
| `motion/` | モーション | motion-slide |

## 見本 1 つの中身

| ファイル | 中身 | 直すか |
|---|---|---|
| `sample.json` | id・題・副題・目的・読み手・モード・スタイル（エンジンのスタイルの名前）・`overrides`・並び順 | 手で直す |
| `script.json` | 台本の正本（サーバが持つ形。台本係が書くのと同じ） | 手で直す |
| `built/` | 描いた台本・描いた回の控え（ページの画像・絵の控え・記録・発表の HTML）・目録 | **手で直さない**（`build.py` が書く） |

## 直して作り直す

1. `script.json`（と、必要なら `sample.json`）を直す
2. `python3 samples/build.py <見本>`（全部なら引数なし）
   - 台本の検査（ページの id・日本語の検査・エンジンの check）を通ってから描く
   - 中身が変わらないページの絵は前に作った控えから使い回す。ピッチは**変えたページだけ** Codex の枠を使う
   - `--fresh` は控えを使わずに全部描き直す。`--keep` は一時的なデータの置き場を残す（確かめる用）
3. `built/slides/` の画像を目で見る（絵の中の文字が台本どおりか・はみ出していないか）
4. `bash tests/run.sh`（`tests/test_samples.py` が、作り直し忘れ・作った機械のパスの混入・大きさの上限を確かめる）

作り直すと見本の版（`built/manifest.json` の `version`）が変わる。利用者の手元では、**入れたまま触っていない**見本のデッキだけが
次の起動で新しい版へ進む。直した見本のデッキはそのまま残り、「見本を入れ直す」を押すと新しい版が別のスライドとして入る。

## 守ること

- 見本の画像はリポジトリの履歴に残り続ける。作り直しはまとめて行い、ピッチの枚数は増やしすぎない
- 人名・社内の名前・顧客や他製品の名前を書かない（AGENTS.md）。`build.py` は作った機械のパスが残っていれば作らない
- `build.py` は、この機械のエンジンの設定（ロゴ・出力先など）を読まない。字体（Noto Sans JP）だけを、データの置き場の `fonts/` から写して使う
- プレゼンの見本の「型の数」は、エンジンの型の数と同じにする（エンジンが型を足すと試験が落ちる。直して作り直す）
