# P3（直す）のメモ

状態: P3 で決めたこと・仮置きにしたことの控え。ADR に切り出すまでの置き場。設計は `docs/DESIGN.md` §5.1–5.2・§8 の 5・6。

## 流れ

```
会話（--revise）・画面（ページ・選んだ数ページ・全体・＋・⋮・版スタック・並べ替え）
   └─ POST /api/decks/<id>/…  → 直しの仕事（jobs.kind=edit・request_json の op）と描いた回を 1 つ作る → すぐ答える
ワーカー（1 冊に走る仕事は 1 つだけ。次の仕事は前の仕事が終わったあとのいまの台本から始める）
  ① いまの台本（deck_heads）を読む。指定したページの id が無ければ、その仕事は理由つきで失敗
  ② op ごとに台本を進める（revise・insert は台本係。ほかは台本係を呼ばない）→ 新しい台本の版 → いまの台本にする
  ③ 作業フォルダ（decks/<デッキ>/work/）でエンジンを呼ぶ（deck → revise の順。絵だけの直しは revise だけ）
  ④ 作業フォルダの出力を runs/<回>/ へ控える（ハードリンク）→ ページの絵を取り込む → 画面の絵が替わる
```

## 決めたこと

### キャッシュを回をまたいで使う（P2 の直し）

- **エンジンはデッキごとに 1 つの作業フォルダ `decks/<デッキ>/work/` に描く**（`--out`）。台本は
  `decks/<デッキ>/scripts/engine.json`（いまの台本から非表示のページを抜いたもの）。image-slide の区画は `--out`、
  html-slide の区画は台本のフォルダで引くので、どちらも回をまたいで同じ区画になる（html-slide は P2 から `scripts/`）
- **描き終えた回は `runs/<回>/` に控える**（ページの画像・PPTX・PDF・サムネイルはハードリンク、記録は写す）。
  エンジンは出力を上書きで書くことがあるので、**呼ぶ前に作業フォルダの出力を消す**（`clear_outputs`）。控えの中身は変わらない
- **絵の控え** `runs/<回>/pictures/`: ピッチは区画の `slide-NN.png|json`（ロゴ前の絵と鍵）をページの id の名前で、
  プレゼンは生成の枠の `gen-<鍵>.png|json`。区画の絵はエンジンが名前の付け替えで入れ替えるので、控えは書き換わらない。
  区画が上限で消されても、控えから戻せる
- **ピッチの区画の付け替え**: image-slide は区画の絵を何枚目か（`slide-NN`）で持つ。鍵（描く指示の sha）は何枚目かを
  含まないので、差し込み・非表示・並べ替え・複製・分割のあと、エンジンを呼ぶ前に、前の並び（`work/layout.json`）から
  新しい並びへ付け替える（前の絵 → 複製元の絵 → 控えの絵の順。外れてもエンジンが鍵を見て描き直すだけ）。
  区画の場所はエンジンの記録（`cache`）から読み、まだ無いときはエンジンと同じ名前の付け方で求める
  （`pitch_area_for`。エンジンの `cache.area_path` と同じ答えになることを試験で見比べている）
- P2 で作ったピッチのデッキ（回ごとの区画）は、最初の直しのときに、その回の区画の絵を何枚目かで引いて新しい区画へ写す
- **同じページ（page_id）の前の回の絵とバイトまで同じなら、前の資産をそのまま使う**（直していないページの絵の URL を変えない）。
  照らすのは同じページの絵だけ。最初はデッキ全体から同じバイトの絵を探していたので、別のページに同じバイトの絵が
  あると（複製したページ・偽物の codex が同じ絵を返したページ）、直していないページの絵の URL が別のページの資産へ
  飛んだ（画面の試験が 3 回に 1 回落ちた。偽物の codex の包みも、並列に呼ばれると同じ印を描くことがあった）
- ページの絵のバイトは、同じ台本・同じ設定なら描き直しても変わらない: 10 ページの 1 冊を同じ台本で 4 回組み直し、
  両モード（プレゼンは Chrome の撮り直し、ピッチは区画の絵からの合成）とも全ページの PNG の sha256 が 4 回同じだった
  （2026-10-07・この機体）。だから「同じページで同じバイト」を資産を使い回す条件にする（取りこぼしの無い条件）
- 版スタックの「同じ姿」は、資産とは別の鍵（台本のページの中身・描いた絵の sha256。どちらもページごと）。
  ページ番号や章の通し番号のように、ページの中身が同じでも並びで PNG が変わることがあるので、版は増やさず、
  資産は新しくする（版の絵は一番新しい回の絵を出す）

### 台本係（直し）

- 指示文: 1 冊全体（並びと JSON）・直すページ（id・番号・直せる絵: ピッチは「あり」、プレゼンは描いた生成の枠の名前）・
  利用者の指示・添えた画像（`attachments/<名前>`。台本の `path` に書ける）・台本の決まり（エンジンの `deck-format.md`）
- 答えの形:

  ```json
  {"pages": [{"id": "p-7", "route": "script", "slides": [{"id": "p-7", "...": "..."}]},
             {"id": "p-8", "route": "image", "image": {"slot": "image", "note": "夜の景色に"}},
             {"id": "p-9", "route": "both", "slides": ["..."], "image": {"note": "..."}},
             {"id": "p-10", "route": "keep"}],
   "suggestions": [{"id": "p-6", "text": "..."}], "summary": "..."}
  ```

  - route: `script`（文字・中身・構成を差し替える）・`image`（絵だけ。エンジンの revise）・`both`（差し替えてから revise）・
    `keep`（全体への指示でこのページは関係ない）。**迷ったら script**
  - 分けてよいのは指示が求めるときだけ（1 つ目は元の id、増やすページは新しい id。その場に入れる）
  - `suggestions` は当てない。画面の帯（描き終えた回の 1 文）と、会話の `--wait` の答えに出す
- サーバの確かめ（`writer/patch.py`）: 対象外の id・2 回・route の誤り・1 つ目の id の付け替え・重なる新しい id・
  直せる絵の無いページへの image・プレゼンで枠が 2 つ以上なのに slot が無い・添えた画像以外の path・`_hidden` 等 →
  `NG:` の行にして書き直させる（回数は `worker.max_check_rounds`）。当てたあとはエンジンの `check`（`N枚目` に id を添える）
- **当てるのは指定した id だけ**。ほかのページは同じオブジェクトのまま書くので、台本の版のファイルでも 1 文字も変わらない
  （`scriptdoc.dumps` の 1 つの書き方。試験が版をまたいでページごとの文字を見比べる）
- 台本係の選び方は P2 と同じ（会話からの直しは会話の出所、画面からの直しはデッキを作った会話の出所）

### エンジンの revise の呼び方（確かめた中身）

| | image-slide | html-slide |
|---|---|---|
| 描くもの | そのページの絵（区画の `slide-NN`）1 枚だけ。ほかのページは鍵が古くても描かない | そのページの生成の枠 1 つ（`--slot`。枠が 1 つなら省ける）だけ |
| 出力 | PPTX・PDF・ページの画像・サムネイルまで組み直す（`finish`） | 描いたあと `deck` を流す（`cmd_deck`） |
| 微修正 / 作り直し | 既定は今の絵を土台に渡す・`--remake` で渡さない | 同じ |
| 前提 | ほかのページが全部描けていること（無ければ rc=2）| 微修正は今の絵があること |
| 直す前の絵 | 区画の `history/` | 区画の `history/` |

- revise は出力を組み直すので、**絵だけの直しは revise だけを流す**（あとから deck は流さない）。台本も変える直しは
  deck（変えたページだけ描く）→ revise の順
- 指示（`--note`）は台本係の `image.note`（無ければ利用者の指示）。`--remake` は画面の「元の画像を使わずに生成し直す」か会話の `--remake`。
  添えた画像は `--attach`

### 版と戻す

- 版スタックは、そのページの描き終えた回をまたいだ「姿」（台本のページの中身の sha256・絵の sha256）。同じ姿は 1 つにまとめ、
  番号は初めて出た順。絵の sha256 は描いた絵（ピッチは区画の絵、プレゼンはそのページの生成の枠の絵の並び）で取るので、
  組み直しの揺れ（Chrome の撮り方）で版は増えない
- 前の版を押す（`POST /adopt`・v1 と同じ形）＝「そのページをその姿に戻す」直し: その回の台本のページの中身に戻した新しい台本の版
  （非表示の印はいまのまま）＋その回の絵をエンジンが読む場所へ戻す（ピッチ: 区画の `slide-NN` に控えの絵と鍵、
  プレゼン: 区画の `gen-<鍵>` に控えの絵）→ deck → 控える。鍵が同じなのでエンジンは描かない
- `progress.candidates` はいつも空

### ページの操作

- 差し込み（台本係が指示に合うページを書く）・複製（新しい id `<元>-copy`。ピッチは区画の絵を写すので描かない）・
  非表示 / 表示・並べ替え。どれも新しい台本の版＋deck の回
- **非表示のページはエンジンに渡す台本から抜く**（`_hidden` は台本の版に残るので戻せる）。画面には灰色で残り、前に描いた絵を出す。
  画面の番号は非表示も数える（v1 と同じ）。PPTX には入らない。最後の 1 ページは隠せない
- infographic（全ページを 1 枚に描く）は、直す（台本の全ページが対象）だけ。差し込み・並べ替え・非表示・複製・版から戻すは断る
- ページの削除（`/remove`）は口を残して「まだ使えない」

### 画面（web/app）

- 画面のページはいまの台本の並び、絵は見せる回のもの。直している途中のページは「生成中」「待機中」
- ページのカードの左上の「選ぶ」で数ページを選ぶと、全体の指示の器の中に「選んだページ（7・8）」の欄が出る（選んでいる間だけ）
- 並び・ページの集合が変わったら（差し込み・複製・分割・非表示・並べ替えの回が終わったら）、書きかけが無ければ描き直す
  （あれば「構成が変わりました」と知らせるだけ）。自分の並べ替えは描き終えるまで待つ。描いた回が変わっただけでは知らせない
- 書き出しは P5 まで「まだ使えない」

### 会話（skills/quick-slide）

- 最初の 1 冊は 2 つ: 人に見せる資料 → 構成を会話で合意して `--outline-fixed`／自分が知るための「調べてまとめて」→ 見せずに
  `--wait`、できたら見出しを 1 行ずつ。迷ったら見せない。構成を守るかは台本係が数で確かめる（`## N.` の数と台本のページ数）
- `--revise [--deck] [--pages 7,8] --note … [--remake] [--attach …] [--wait]`。スライドを省けば
  この会話から作った一番新しいスライド（`POST /api/conversations/deck`。会話の識別子は HMAC にして引く）
- `--wait` は `GET /api/decks/<id>/jobs/<job>` を読む。URL はいつも返す（直しのときは起動のトークンの付かない URL）

## CLI の例

```bash
python3 skills/quick-slide/scripts/quick_slide_start.py --manuscript-file outline.md --title "…" --outline-fixed --wait
python3 skills/quick-slide/scripts/quick_slide_start.py --revise --pages 7,8 --note "見出しを短く" --wait
python3 skills/quick-slide/scripts/quick_slide_start.py --revise --deck <ID> --pages 3 --note "写真を夜に" --remake --attach night.png
```

## 確かめたこと（`bash tests/run.sh`）

- **本物のエンジン**で 10 ページの 1 冊（ピッチ・プレゼン）→ 7・8 枚目の直し: ほかのページは台本の版の文字が同じ・
  ピッチは偽物の codex が 7・8 枚目だけ呼ばれた・プレゼンはほかの枠の絵が同じ inode・PPTX の枚数と並び（ノートの話す台本）が
  画面の並びと同じ（`tests/test_p3_edit.py`）
- 絵だけの直し（revise だけ・微修正は土台の絵 1 枚を渡す）・両方（deck → revise）・版から戻す（絵だけ・台本も。描かない）・
  差し込み（足したページだけ描く）・複製・非表示・並べ替え・表示に戻す（描かない）・分割・2 つの直しの順番（1 冊に 1 つ）・
  消えたページ・台本係の答えの書き直し
- 2 回目のピッチの回で 1 ページだけ変えると、そのページだけ描く（キャッシュの区画を回をまたいで使う）
- 会話の入口: `--outline-fixed --wait`・`--revise --pages 7,8 --wait`（同じ会話のスライドを引く）を使い捨てのサーバで
- 本物のヘッドレス Chrome で、7・8 枚目を選んで 1 つ指示を送ると、読み込み直さずに見出し・絵・版スタックが替わり、
  ほかのページの絵は替わらない・例外が出ない（`tests/live/test_p3_select.py`）
- 部品: 台本係の答えの確かめと当て方・区画の付け替え・区画の名前がエンジンと同じ・構成の枚数が違うと書き直させる・
  絵を直す途中で止まった直しは続けない・同じデッキの仕事は重ねない（`tests/test_p3_units.py`）

## 偽物にしたもの

- 台本係（`tests/fakes/writer_common.py`）: 指示文の節（「直すページ」「ページを足します」「合意した「構成」」）を読み、
  指示の語で振り分ける（「絵だけ」→ image・「両方」→ both・「そのまま」→ keep・ほかは script・「分けて」で分割・
  「絵も変えて」で prompt も変える）。10 ページの台本（`FAKE_WRITER_PAGES=10`）
- 絵を描く codex: エンジンの偽物を `tests/fakes/fake_codex_varied.py` で包み、描くたびに違う絵にする
  （「絵だけ直した」「前の絵に戻した」を絵の中身で見分けるため）
- 本物の claude・codex は呼ばない（`--help` も呼ばない）

## 仮置き・まだのこと

- 直しの途中で止まったサーバ: 台本係の段は失敗、描く段は描くところから。ただし**絵を直す（revise）直しは続けずに失敗**
  （黙ってもう一度描かない）
- プレゼンで、区画の上限で生成の絵が消えたあとの微修正は、土台が無くて断られる（作り直しなら描ける）。控えから戻すのは版から戻すときだけ
- 新しく作るときの画像の添付・会話抜粋・既存のスライドへの追加は、まだ受けない（`not_ready_in_v2`）
- infographic のページの操作・版から戻すは断る
- 書き出しの配布（いまの回の PPTX・PDF）は P5。画面の書き出しボタンは押せないまま
- `lock_version` は受けるが照らさない（直しはページの id で重なるため）
