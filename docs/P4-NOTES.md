# P4（設定をエンジンへ）のメモ

状態: P4 で決めたこと・仮置きにしたことの控え。ADR に切り出すまでの置き場。設計は `docs/DESIGN.md` §2・§7 の P4。

## 頭: 設定の反映

### 再起動の要らない設定（仕事のたびに読み直す）

- サーバは起動したときの settings.json の印（mtime・大きさ・中身の sha256。`settings.file_fingerprint`）を持ち、
  **ワーカーが仕事を取る前**（と health・設定の画面を読むとき）に見比べる。変わっていれば読み直す（`QuickSlideServer.refresh_settings`）
- 読み直すのは `server`（待ち受け）以外の全部: `writer`・`worker`（同時に進める数・時間の上限・検査の回数）・`intake`・
  `launch`・`browser`・`default_brand_id`。台帳（Store）の設定も差し替えるので、取り込みの上限・既定のブランドも次の投入から効く
- **同時に進める数**（`worker.parallel`）も再起動なしで変わる。増やせばスレッドを足し、減らせば番号が数を超えたスレッドが
  手の仕事を終えてから休む（止めない。スレッドは残るが仕事を取らない）
- 読めないファイル（JSON が壊れている・値が通らない）は、前の設定のまま続け、理由を health の `settings.error` と
  設定の画面（この機械）に出す
- 試験のように設定をコードで渡して起動したサーバは、ファイルが変わるまでは渡された設定を使う

### 再起動の要る設定（待ち受け）と「再起動が必要」

- `restart_required` = ファイルの待ち受け（host・port・host_names）がいま動いている待ち受けと違う。画面で保存したときも、
  **手で直したときも**同じ（どちらもファイルを読んで見比べる。ファイルの監視で勝手に再起動はしない）。
  ポート 0（自動割当。試験）で動いているときはポートを見比べない
- 出す所: `GET /api/settings` の `server`（`restart_required`・`expected_url`・`running_jobs`・`restartable`・`settings_error`）と
  health の `settings`。画面は「この機械」に帯とボタン、ほかの画面は上の帯の横に「設定を効かせるには再起動が必要です」のリンク

### 再起動のボタン（`POST /api/server/restart` `{mode: "wait"|"now"}`）

`server/restart.py`。セッションのトークン・Host・Origin の検査はほかの状態を変える口と同じ。

1. 断る（何も変えない）: 形の違う mode（400）・常駐の `serve` でないサーバ（試験のスレッドの中。409 `restart_unavailable`）・
   もう再起動している（409）・settings.json が読めない（400 `settings_unreadable`）・待ち受けが「ぜんぶの口」や名前（400）
2. いま動いている待ち受けを **last-good** として `runtime/last-good-listen.json` に控える（起動できたときにも毎回書く）
3. 新しい仕事を受けない: 状態を変える口は `/api/server/*` のほか 503 `restarting`。ワーカーは待っている仕事を取らない
4. 202 で答える: `restart_id`・`running_jobs`（走っている仕事の数）・`expected_url`（新しい設定の 1 つ目の名前か
   アドレス＋ポート）・`same_url`・いまの `instance_id`
5. 別のスレッドで: `wait` は走っている仕事が終わるまで待つ（上限 30 分。超えたら今すぐと同じ）。後継
   `python -m quick_slide.server --home … serve --quiet --after-pid <自分> --restart-id <id>` を**新しいセッション**で起こしてから、
   自分は止まる。`now` は子プロセス（エンジン・台本係）をグループごと止め、**台帳に何も書かずに**抜ける
   （`pipeline.Abandoned`。`Context.call` が投げる）。走っていた仕事は「走っている」のまま残り、後継の起動時の掃除が
   P2・P3 と同じ戻し方をする（描く・取り込む段は続きから、書く段は理由つきで失敗。試験で確かめた）
6. 後継: 前のプロセスが終わるのを待つ（上限 90 秒）→ 新しい設定で起動。待ち受けが前と同じなら、ポートが空くまで
   15 秒まで試し直す。**起動できなければ**（bind できない・設定が通らない）settings.json の `server` の段だけを
   last-good に戻し（ほかのキーは触らない）、前の設定で起動し、`runtime/restart.json` に
   「新しい設定で起動できなかったので、前の設定に戻しました（理由）」を書く。health の `restart` がそれを出す。
   前の設定でも起動できなければ（ほかのアプリがポートを取ったなど）、その理由を書いて終わる
7. 画面（`core.js` の `SS.restartServer`）: 同じ URL の `/api/health` を 0.5 秒ごとに見る。インスタンスが替われば
   （同じ URL で起動した・前の設定に戻した）`?restarted=<id>` を付けて読み直す。URL が変わる再起動は、前の URL が
   応答しなくなってから 8 秒戻ってこなければ新しい URL（`expected_url` ＋いまのパス）へ移る。
   別のオリジンの health は CSP（`connect-src 'self'`）で読めないので、「前の URL が戻ってこない」を新しい設定で
   起動した印にする（戻ってくれば前の設定に戻したということ）。開き直した画面は health の `restart` を読み、
   前の設定に戻したなら理由を残る通知で、うまくいったなら「再起動しました」を出す

- 後継は CLI の `--host`・`--port` の上書きを引き継がない（ファイルの設定で起動する。上書きで起動していたなら
  `restart_required` が立っている）。`--static-root` は引き継ぐ
- 「この機械」の画面にポートの欄を足した（`POST /api/settings/server` の `port`。1024〜65535。省けば今の値）

## 本体: ブランド・スタイル・書式 → エンジン

決め方は `render/look.py`。**描く回を始めるときに 1 回**（作る・直すの仕事の最初）。止まった回を続けるとき（resume）は
読み直さず、控えた引数で描く。デッキはブランド・スタイルの改訂を指すが、そのブランド・スタイルに新しい改訂があれば
そちらへ進めてから使う（`decks.follow_deck_settings`。`lock_version` は上げない）。**設定を変えたら次に描く回から効く**。
保存しただけでは描き直さない。消したブランド・スタイルは、指していた改訂のまま。

### ブランド → テーマ（`palette.engine_theme`）

エンジンのテーマのキー（両エンジン共通）: `background`・`ink`・`primary`（必須）と `accent`・`muted`・`surface`・`font`・
`font_files`（任意）。エンジンは primary・accent から文字の色・面の色・淡い地を自分で作り、読めない組み合わせは描かずに
止める（rc=2）。だから**人が決めた色だけ**を渡し、算出はエンジンに任せる。

| ブランド（保存した配色） | テーマ | 理由 |
|---|---|---|
| 地の色（`base`。既定は白） | `background` | |
| `gray` の 2 段目（算出なら明度 0.25 = `#404040`。地との差が 7 に届かなければ gray・黒・白で一番差の大きい色） | `ink` | 算出の gray[1] がエンジンの既定の文字色と同じ。暗い地でも読める文字にする |
| 基本色（`primary`） | `primary` | 骨格の色 |
| 強調色（`accent`） | `accent`（基本色と同じなら書かない） | 書かなければエンジンが primary を使う |
| 面の色（`surface`） | `surface`（人が上書きしたときだけ。文字との差が 7 以上のときだけ） | 算出の面の色はエンジンが作る |
| 情報色（`info`）・成功/注意/エラー・主役色（淡/濃）・区切り線・`muted` | 渡さない | エンジンに役が無い・エンジンが作る。`muted` を渡すとエンジンは読めるかを直さずに使う |
| 字体（`fonts`） | 渡さない | エンジンは字体ファイルの在りか（`font_files`）が要る。既定の游ゴシックで組む |

- テーマの YAML は回の控え `decks/<デッキ>/runs/<回>/settings/theme.yaml` に書き、エンジンにはそのファイルを渡す
  （`--theme`）。記録（`runs.record_json` の `look`）にテーマの中身・sha256・ブランドの改訂も残す（再現）
- **付属のブランド「既定」はエンジンの既定の色**（白の地・`#404040`・シアン `#0DB4F2`）に替えた。何も選ばなければ、
  ブランドから作ったテーマがエンジンの `themes/default.yaml` と同じになる（P3 までの 1 冊と同じ色。試験で見比べている）。
  P1 の「既定（無彩色）」は名前も色も製品更新で替わる（`ensure_presets` が表の名前も替える）
- ブランドの色で読めない組み合わせになれば、html-slide の検査が `NG: テーマ … の色で読めない文字がある` で止まる。
  台本係が直せるものではないので、**書き直させずに**「ブランドの色の組み合わせでは読めない文字ができるため、描けません」
  （`failure_kind` は `brand`）で止める（灰色の地 `#777777` で試験している）

### ブランド → ロゴ・角・書式

| 設定 | エンジン |
|---|---|
| 使うロゴ（`logo.variant` の役割の画像） | `--logo <置き場の画像>`（PNG・JPEG だけ。**加工しない**。置き方・縮め方はエンジン） |
| 白いロゴ（役割 `logo_white`） | `--logo-white`（ピッチだけ。ロゴと縦横比が 2% 以内で合うときだけ。合わなければ渡さず、控えに理由） |
| ロゴの角（`logo.placement.corner`） | `--logo-position`（bottom-right・bottom-left・top-right） |
| フッタの文字（`footer.text`） | 台本の一番外の `footer`（`scripts/engine.json` に書くときに入れる。台本の版は変えない） |
| ページ番号（`format.page_numbers`） | 台本の一番外の `page_numbers` |
| 透かし（`format.watermark`） | `--watermark` |

- 検査（`check`）: html-slide はテーマ・スタイル・画風だけを受ける。image-slide はロゴ・透かしも受ける（ロゴの有無で
  描く指示の帯の頼み方が変わるので、検査も同じ引数で）
- 台本係には「theme・footer・page_numbers は書かない」と言う（ブランドが決める）。書いてきても、エンジンに渡す台本では
  ブランドの値で上書きする（フッタが空なら消す）
- ロゴの画像はブランドの保存のときに PNG・JPEG かを見る（WebP は 400 `logo_type`。エンジンが受けない）。
  前に保存した WebP のロゴは、描く回では置かずに控えに理由を書く

### 書式の置き場（決めたこと）

**書式（ページ番号・透かし）はブランドの中の `format` に持つ**（フッタはもともとブランドの `footer`）。
「書式を登録」のボタンは押せないまま（理由:「ブランドの編集画面の「書式」で設定します」）。

- 理由: 書式は 3 つの値だけで、ブランドと同じ単位で使う（同じ会社の資料は同じフッタ・透かし）。別の表・改訂・選ぶ口を
  作ると、デッキが指す改訂が 3 つになり、画面にも選ぶ所が要る。ブランドの改訂がそのまま「どの書式で描いたか」の控えになる
- 取り込みの `format_id`・`format_values`・`format_options` は「まだ使えない」のまま（v1 の形を残す）
- 透かしは 60 字・フッタは 120 字までの 1 行

### スタイル → エンジンのスタイル・画風・台本係

スタイルの改訂に足したキー: `engine_style`（`{presentation, pitch}`）・`image_look`・`style_note`。

| スタイル | 渡す先 |
|---|---|
| `engine_style[モード]` | `--style`（プレゼン: standard・visual／ピッチ: visual・standard・infographic。書いていない古いスタイルはモードの既定） |
| `image_look` | `--image-look`（省けばエンジンのスタイルの既定） |
| `style_note` | ピッチの `--style-note`。どちらのモードも台本係の「作風の一言」 |
| `emphasis_prompt` | 台本係の「書き方の方針（スタイル）」 |
| `tone` | 台本係の「文章の調子」（標準なら書かない） |
| `allowed_layouts` | 台本係の「使ってよい型」（おまかせなら書かない）。サーバも確かめる（下） |

- **使うパターン = html-slide の型の一覧**（`references/deck-format.md` の「型の一覧」を実行時に読む。`contenttypes.py`。
  写しは持たず、画面に出す短い名前だけを持つ）。保存の形は `["auto"]`（おまかせ＝すべて）か型の名前の並び。
  おまかせとほかの型は一緒に選べない。設定の画面の「使うパターン」の P1 の仮置き（おまかせ 1 つ）を、おまかせ＋23 の型の
  チェックに替えた（おまかせを選ぶとほかが外れ、型を選ぶとおまかせが外れる）。どちらのモードにも効く（台本の型は共通）
- 使ってよい型の外の型を台本係が書いたら、`NG: N枚目（id=…）の型 X は、このスタイルで使わない型` で書き直させる
  （回数は `worker.max_check_rounds`）。直しでは**書き換えたページだけ**を見る（前からあるページは問わない）
- 会話が `style`・`image_look`・`style_note` を言ったら、それが勝つ（回の引数の `overrides`。直しの回にも引き継ぐ）。
  `style` だけを言ったときは、それにあたる付属スタイルをデッキのスタイルにする（overrides には入れない。以後はその
  スタイルに従う）。`style_id` と `style` を両方言ったときだけ `style` を overrides に入れる
- 付属のスタイル（製品更新で名前も替わる）: 「説明・報告（standard）」（両モード standard）・「ビジュアル（visual）」
  （両モード visual）・「インフォグラフィック（ピッチ）」（ピッチ infographic・プレゼン standard。新しい付属）。
  自分用は「複写して作る」のまま
- **全ページを 1 枚に描くか（infographic）はデッキの最初の回で決まり、あとから替えない**（ページの数え方が変わるため。
  直しの回でスタイルが替わっても、前の回の描き方のまま描き、控えの `notes` に理由を書く）
- 取り込みは `style_id` を受ける（P1 では「まだ使えない」だった）。会話の入口は `--style-id`

## ブランドの編集画面（P1 のレビューの指摘を直した）

- 画面はブランドの画像を**全部**送る（前はロゴの画像だけを組み直して送っていた）。サーバも、ロゴでない役割
  （`optional`・`source`）は送られなければ前の改訂から持ち越す（`brands.merge_brand_assets`。ロゴの役割は送られたものが
  すべて＝外せる）。config のキーの持ち越し（P1）と同じ考え方
- ロゴは「使うロゴ」（いまの種類。無ければ背景透過）と「白いロゴ（任意）」の 2 つの枠。受けるのは PNG・JPEG だけ
- 「書式」の欄（フッタ・ページ番号・透かし）を足し、拡張設定は色だけにした
- 見本: ロゴの位置はエンジンの寸法の写し（`logo.preview_box`。右下・左下は下の文字の行の中心、右は本文の余白 120px、
  右上は上の余白の中）。フッタ・ページ番号・透かしの位置も同じ写し（`logo.chrome_boxes`。フッタは左下、ロゴが左下なら
  その右へ寄せ、ページ番号を出すときは番号の手前まで。ページ番号は中央下、透かしは中央下の端）。
  **エンジンで描いた本物の見本は出さない**（描くのに Chrome と時間がかかる。ふさがった角を逃がす動きも見本には出ない）

## 確かめたこと（`bash tests/run.sh`）

- **本物のプロセス**で再起動: 同じ URL で新しいインスタンス／ポートを変えたら答えの URL に新しいサーバ（前のポートは閉じる）／
  この機械に無いアドレス（TEST-NET の 203.0.113.7）なら前の設定に戻して前の URL で起動し、理由が health に出る・
  settings.json の `server` の段だけが戻りほかのキーは残る／「終わるのを待って」は走っている仕事（遅い偽物の台本係）を
  終えてから起動し直し、待っている間の投入は 503／「今すぐ」は描いている仕事を止め、後継が描く段から続けて終える
  （台本係はもう一度呼ばない）／断る頼みは何も変えない／試験のスレッドの中のサーバは 409
- 読み直し: 台本係の LLM を仕事ごとに読み直す・ワーカーの数（増やすとスレッドが増える）と検査の回数・壊れたファイルは
  前の設定のまま・手で待ち受けを直すと `restart_required`（台本係だけなら立たない）
- テーマ: 付属のブランドがエンジンの既定のテーマと同じ・accent は違うときだけ・info は渡さない・地と面の上書き・
  暗い地の文字・作った YAML を両エンジンの `check` が受ける（本物のエンジン）
- 引数（偽物のエンジンが受けた argv）: プレゼンに `--theme`・`--logo`・`--logo-position`・`--watermark`（白いロゴは渡さない・
  検査にロゴを渡さない）／ピッチに `--logo-white`・`--style`・`--image-look`・`--style-note`（会話の一言が先）・検査にも
  ロゴ／形の違う白いロゴは渡さない／ロゴ・透かし・フッタ無し。フッタとページ番号は `scripts/engine.json` に入り、
  台本の版には入らない
- スタイル: 付属の 3 つとエンジンのスタイル・使ってよい型と方針と調子が台本係の指示文に届く・外の型を書いたら直させる・
  誤った型の並びや値は断る・設定を変えたら次の回（描き直し）から効き、デッキが新しい改訂を指す・infographic のデッキは
  1 枚のまま
- **本物のエンジン**: html-slide（画像なし・Node と Chrome が要る）で、ブランドの基本色が HTML と PPTX の部品に出る・
  ロゴが左下（`!!logo-left`）に入り縦横比が同じ・フッタと透かしが入る／読めない色のブランドは台本係を 1 回だけ呼んで
  `brand` で止まる／image-slide（偽物の codex）でロゴ・白いロゴ・
  右上・透かし・作風の一言を受けて描き終える
- ブランドの画像: 編集画面の形の保存で、ロゴ以外の役割の画像が残り、外した白いロゴは外れる・WebP のロゴは断る・
  見本の下の部品の位置
- **本物のヘッドレス Chrome**: 手で直した待ち受け → 「再起動」→ 新しいポートの URL へ移って「再起動しました」／
  使えないアドレス → 前の URL のまま「前の設定に戻しました」の通知・ほかの画面にもリンク／ブランドの角・書式を画面で
  保存（見本に下の部品・差し絵の画像は消えない）／スタイルの型のチェック・見せ方・画風を画面で保存・おまかせに戻す。
  どれも JavaScript の例外なし
