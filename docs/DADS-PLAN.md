# デジタル庁デザインシステムに沿わせる計画（html-slide と Quick Slide の画面）

2026-10-10 作成。依頼は次の3つ。

- html-slide の型を、デジタル庁デザインシステム（以下 DADS）に沿わせる。
  - 見づらい型は直し、見やすい型を足し、見づらい型は外す。
  - 色・文字の大きさ・アイコンの使い方まで、すべて DADS に従う。
- 参照資料は再利用できる形にする。あとで motion-slide にも使えるようにするため。
- Quick Slide の画面そのものも DADS に沿って作り直す。

## 0. 前提と出典

- **正本**: DADS の公式サイトの Markdown 一括版（2026-10-08 版・145ファイル）を使い、全部に目を通す。
  - 一次情報は https://design.digital.go.jp/dads/
- **デザイントークン**: 公式の `digital-go-jp/design-tokens`（MIT）を使う。
- **アイコン**: DADS の Figma が使う Material Symbols（Apache License 2.0）を使う。
- **字体**: Noto Sans JP（SIL OFL 1.1）を使う。
- **出典の書き方**: 利用上の注意事項の 1-2 に従う。この仕組みは DADS のコンテンツを加工して作ったものなので、`skills/dads/README.md` に出典と加工した旨を書く。
  - DADS が作ったように見える書き方はしない。
  - スライドの画面には出典を出さない（DADS は画面パーツへの出典表記を求めていない）。
- **DADS の考え方**: DADS は「プラットフォーム型」で、使う側がブランドで定義し直して「ローカルデザインシステム」を作る前提になっている。
  - スライドはウェブページではないので、この計画では **スライド用のローカルデザインシステム** を定義する。
  - DADS の基準をそのまま使えるところはそのまま使う。スライドに要る拡張（遠くから見る大きな文字など）は、拡張とはっきり書く。

## 1. 置き場（再利用できる形）

`skills/dads/`（新設）を、どのエンジンからも読める参照の置き場にする。

```
skills/dads/
  README.md                 何が入っているか・出典と加工の表記・ライセンス一覧・使い方（html-slide / motion-slide / 画面）
  references/
    foundations.md          基本デザイン（色・文字・余白・角・影・アイコン・レイアウト・リンク）の要約。各節に元の URL
    components.md           コンポーネントの要約と、スライド・画面での対応づけ
    accessibility.md        アクセシビリティの要点（コントラスト・色だけに頼らない・アイコンはラベルと組む など）
    slide-local.md          スライド用ローカルデザインシステム（下の 2.）の仕様。motion-slide もこれを読む
  tokens/
    dads.tokens.json        公式トークン（MIT・そのまま）
    dads.css                公式トークンの CSS 変数（MIT・そのまま）
    slide.json / slide.css  スライド用ローカルデザインシステムのトークン（2.）
  icons/
    material-symbols.json   使うアイコンの部分集合（名前 → SVG の path・24 の格子）
    LICENSE-material-symbols.txt
  scripts/
    keycolors.py            ブランドの色から DADS のキーカラー（主・副・第3・地）を作る。標準ライブラリだけ
  LICENSE-dads-tokens.txt
```

## 2. スライド用ローカルデザインシステム（決めたこと）

キャンバスは 1920×1080。CSS px を 1 対 1 で使う。

### 文字

- 字体は Noto Sans JP（N=400・B=700）。
- 大きさは DADS の段だけを使う: 64・57・48・45・36・32・28・26・24・22・20・16。
  - `fit()` は連続値で縮めず、この段を1段ずつ下りる。grow（余白を埋める拡大）も段を上る。
- 行高も DADS の段だけを使う（100・120・130・140・150・160・170・175%）。
  - 見出し・48 以上は 140%。本文は 150〜160%。
- **スライドの拡張（遠くから見る大きさ）**: 表紙・章扉の題、大きな数字、主張の1文だけは 80・96・120・160・200 を使ってよい。
  - DADS の Display（48〜64）の上に、スライド用として足す。
- 役ごとの既定:
  - 見出し: 64B-140（図解の型の大見出しは拡張の 80B-140）
  - キッカー: 28B-150
  - 副題: 32N-150
  - 箱の題: 36B-140 か 45B-140
  - 本文: 32N-150 か 28N-150
  - 注記・出典・フッター: 22N-150
- **下限**: 本文 24、注記 22、透かし 16（DADS の下限 16 を割らない）。

### 余白

- 基準は 8。段は 8・16・24・40・64 の5つと、版の余白 120。
- 座標・大きさ・間隔は 8 の倍数にする（今の 36・44 などを直す）。
- 格子は12列。列 96・溝 48、合わせて 1680 = 12×96＋11×48。左右の余白は 120。

### 色

- DADS のプリミティブカラー（13段の色相）とニュートラル（solid-gray）を使う。
- 文字: solid-gray-800 `#333333`。補足: solid-gray-600 `#666666`。どちらも白の地で 4.5:1 以上。
- 罫線・枠など、地に接する線は 3:1 以上（solid-gray-420 `#949494` 以上）。飾りの面は対象外。
- **キーカラー**: プライマリー（地に対し 4.5:1 以上・文字にも使う）、セカンダリー・ターシャリー（同じ色相の明・暗）、バックグラウンド（同じ色相のごく淡い地）。
  - 既定のテーマ（シアン系・10/5 の決定を引き継ぐ）は、DADS のプリミティブの段をそのまま使う。
  - ブランドの色は、同じ色相で明度だけを動かしてキーカラーを作る（DADS「ブランドカラーがコントラスト要件を満たさない場合」の方法）。ロゴは加工しない。
- **セマンティックカラー**（成功・エラー・警告）: DADS の値を使う。色だけで意味を伝えない。必ずアイコンとラベルを添える（NG→OK の対など）。
- **グラフ**: 隣り合う系列・棒は 3:1 以上にするか、値と名前を直接書く。凡例だけに頼らない。

### 角・影

- 角丸は DADS の段: 0・8・12・16・24・32・full。カードは 16、写真は 8、札（チップ）は full。
- 影は DADS の elevation の値だけを使う。スライドは原則平ら（影なし）。
  - 浮かせる印（画像の番号の丸など）だけ elevation-2。
  - 影でコントラストを稼がない。

### アイコン

- Material Symbols（Outlined・太さ 400）に替える。今の45種は同じ名前の意味で引き継ぐ。
- 必ずラベルと組む。アイコンだけの項目は作らない。
- 色は地に対し 4.5:1 以上（ラベルと組む装飾的な使い方でも、文字と同じ扱いにする）。
- 置き方は DADS の4種のうち、スライドで使う2種に合わせる。
  - 箱の頭に置く「フロントアイコン」: カード・放射
  - 行の頭に置く「リードアイコン」: 箇条書き・対

## 3. html-slide の作業

1. **型の点検（27型）**: 見本の台本を描き、DADS の基準で1枚ずつ見る。基準は次のとおり。
   - コントラスト
   - 文字の下限
   - 読む順と見た目の順
   - 色だけに頼る表現
   - 詰まり
   - 写真の上の文字

   型ごとに「残す・直す・外す」を決める。足す型は DADS のコンポーネントから取る。候補は次の3つ。
   - お知らせの枠（notice-block）→ `notice`
   - 用語と説明（description-list）→ `deflist`
   - 手順の案内（step-navigation）→ `steps`
2. **基礎の差し替え**:
   - テーマと deck.py の色の作り方
   - 雛形の CSS
   - 文字の段（`fit`・grow）
   - 余白の段
   - 角・影
   - 字体（Noto Sans JP のファイルを設定の fonts で引く）
3. **アイコンの差し替え**: Material Symbols。PPTX に穴のある形（輪の中の点など）が正しく出るかも確かめる。
4. **型の手直し・追加・退役**:
   - 外す型は「退役」にする。台本の書き方（deck-format.md）・台本係・Quick Slide の型の一覧からは消す。
   - 過去のデッキを組み直せるよう、描く部分は残し、新しく使うと検査が注意を出す。
5. **周り**:
   - image-slide の型の対応
   - 台本係の決まり
   - catalog
   - 見本の台本
   - 試験
   - ADR 0020

## 4. Quick Slide の画面の作業

- `web/app` の CSS と JS を DADS に沿って作り直す。動きは変えない。
  - 色（キーカラーは DADS の青）
  - 字体（Noto Sans JP）
  - 文字の段
  - 余白
  - 角
  - 影
- 部品は DADS のコンポーネントに合わせる: ボタン（主・副・第3・大きさ）・入力・選択・チェック・ラジオ・お知らせの枠・通知の帯・タブ・表・カード・ダイアログ・パンくず・進み具合・札・区切り線・見出し。
- アクセシビリティ:
  - フォーカスの見た目（DADS のフォーカス色）
  - 押せる大きさ 44px 以上
  - コントラスト
  - アイコンはラベルと組む
- トークンは `skills/dads/tokens/dads.css` と同じ中身を画面に置き、試験で一致を確かめる。
