# Quick Slide v2 の設計（叩き台）

状態: 叩き台（2026-10-07）。8. の4つは決まった。決まったところから ADR に切り出す。

## 0. 構図

```
会話（スキル quick-slide） ─┐
                            ├─▶ サーバ（API は v1 の画面が呼ぶ形を保つ）─▶ DB（SQLite）とファイル
画面（web/app・v1 を踏襲） ─┘            │
                                         ├─ 台本係（ワーカー）: 原稿・設定・指示 → 台本（JSON）
                                         └─ 描き係（ワーカー）: 台本・設定 → エンジンを呼ぶ → 出力を取り込む
                                                                    │
                                              skills/html-slide（プレゼンモード）・skills/image-slide（ピッチモード）
```

- **エンジンは描くだけ。** 台本を受けて描き、書き出し、1枚を直す。状態を持たない（描いた絵のキャッシュを除く）。ストーリーも型の選び方も決めない
- **台本を書くのは台本係（と画面）。** 台本係はエンジンの決まりを理解した上で書く: 型（23種）と各型のキー、`talk` と段の数、画像の枠（prompt・path）、`_characters`、`_visual`、`_layout`。
  決まりの正本はエンジンの `references/deck-format.md`。台本係はそれを読んで使い、写しを持たない
- **台本の検査はエンジンに任せる。** 台本係は書いたら `check`（html-slide・image-slide とも）を通し、rc=2 の `NG:` を読んで直す（回数に上限）
- **台本係の LLM は Claude Code か Codex。** プラグインはどちらにも載るので、どちらでも書けるようにする。会話から来たときはその出所（取り込みの `origin.runtime`）と同じものを使い、設定（`writer: auto|claude|codex`）で固定もできる。CLI（`claude -p`・`codex exec`）をサブスク枠で呼び、従量課金 API は使わない
- **画像を描くのは Codex だけ。** Claude Code に入れた場合も、絵を描くには `codex` CLI と ChatGPT のログインが要る（導入の手順に書く）
- **画面は v1 を踏襲する。** サーバは v1 の画面が呼ぶ URL と、画面が読む項目をできるだけ保つ。v1 だけの考え方が出てくる所だけ画面を直す（6.）。画面を変えていくのはその後
- **台本は画面に見せない。** 利用者が触るのは指示文だけ（v1 と同じ）

## 1. 役割

| 担い手 | やること | やらないこと |
|---|---|---|
| エンジン | 台本 → HTML・絵 → PPTX・PDF・ページの画像・サムネイル。1枚の絵を直す（revise）。台本の検査（check） | 台本を書く・DB・版の管理 |
| 台本係 | 原稿・デッキの属性（目的・読み手・枚数）・スタイル・指示 → 台本を書く／直す。型と画像の枠の使い分けを決める | 描く |
| 描き係 | 設定 → エンジンの引数・テーマの YAML に変換して呼ぶ。出力（ページの画像・PPTX・PDF）を資産として取り込み、ページの版にする。進みを台帳に書く | 台本の中身を変える |
| サーバ | API・設定・ごみ箱・書き出しの配布・ワーカーの監督 | 描く・台本を書く |
| 画面 | v1 と同じ（ホーム・一覧・ごみ箱・スライドの画面・設定） | — |

## 2. v1 の考え方との対応

| v1 | v2 |
|---|---|
| 企画（`plan_pages`・ページごとの `layout_key`） | 台本（JSON）。ページの `type` がそれにあたる。台本は版で持つ（台本の版） |
| ページの版（`slide_versions`・1ページ1枚の PNG） | 描いた回のページの画像（`slides/slide-NN.png`）＋台本のそのページ。画面に出すのはこの画像 |
| 構成版（`deck_revisions`） | 台本の版＋採用した描いた回 |
| 生成のキュー（`batches`・`attempts`） | 描いた回（エンジンの1回の実行）と、ページごとの結果 |
| 修正指示 minor・remake | 文字・構成を変える指示 → 台本係が台本を直して描き直す（変えたページだけ描き直されるのはエンジンの仕事）。絵だけを直す指示 → エンジンの `revise`（minor＝今の絵を土台に・remake） |
| 書き出し（1ページ1枚の絵を並べた PDF・PPTX） | エンジンの出力をそのまま配る。プレゼンモードの PPTX は編集できて動く |
| ブランド（色・ロゴ・ロゴの四隅・フッタ） | テーマの YAML（primary・accent ほか）・`--logo`・`--logo-white`・`--logo-position`（右下・左下・右上）・台本の `footer` |
| ロゴの予約枠と検査（gate） | 要らない。ロゴの置き場はエンジンが決める（ふさがっていれば逃がす・ステッカー） |
| スタイル（強調・トーン・ダイヤル・使うレイアウトパターン・作風） | エンジンのスタイル（standard・visual・infographic・カスタム YAML）＋画風（`--image-look`）＋一言（`--style-note`）。使うレイアウトパターン → 台本係が使ってよい型の一覧 |
| 書式（画面には未提供） | ページ番号・透かし・フッタ |

モードはデッキを作るときに決め、後から替えない（プレゼン＝html-slide・ピッチ＝image-slide）。替えたいときはデッキを作り直す。

## 3. データの置き場

`QUICK_SLIDE_HOME`（既定 `~/.quick-slide/`）の下。v1 のデータの置き場とは分ける。

```
~/.quick-slide/
├── db/quick-slide.db
├── decks/<デッキ>/
│   ├── scripts/<版>.json          台本の版
│   └── runs/<描いた回>/            エンジンの --out（slides/・deck.pptx・deck.pdf・thumbs.png・build.json など）
├── assets/                         持ち込みの画像・ロゴ・添付
├── engines/<スキル>/config.yaml    エンジンの設定（単体で使うときと同じ）
├── config/  runtime/  .trash/
```

描いた絵のキャッシュはエンジンのもの（`~/Library/Caches/quick-slide/<スキル>/`）。描いた回の出力フォルダごとに区画ができ、上限を超えると古い区画から消える。

## 4. DB（v1 から作り直す）

v1 の 34 表のうち、エンジンと関係ない所（ブランド・スタイルの改訂、デッキの管理、取り込み、起動、資産、ごみ箱、出来事の台帳）は形を引き継ぐ。
企画・ページの版・生成のキューは次に置き換える。

| 表 | 中身 |
|---|---|
| `scripts` | 台本の版（デッキ・版の番号・台本の JSON のパス・誰が書いたか＝台本係／画面／会話・元の指示） |
| `runs` | 描いた回（デッキ・台本の版・モード・エンジンに渡した引数・状態・始まり／終わり・rc・出力フォルダ） |
| `run_pages` | 描いた回のページごとの結果（ページの番号・台本のページの id・画像の資産・状態・警告） |
| `page_ids` | 台本のページの同一性（並べ替え・複製・非表示をまたいで同じページを指すため） |

## 5. 流れ

1. **会話から**: スキル `quick-slide` が会話を原稿に整えて `POST /api/intakes`（v1 と同じ形）→ 台本係が台本を書く → `check` → 描き係が描く → 画面の URL を会話に返す
   - 画面の開き方は v1 の3段をそのまま使う: スキルが URL を会話に出し、会話しているアプリ（Codex・Claude のデスクトップ）が内蔵ブラウザで開く →
     画面が開いたらサーバに合図（attach）が届く → 来なければサーバが外部ブラウザで開く → それでも来なければ URL を案内する。URL はいつも会話に残す。
     内蔵ブラウザを開けるのはアプリの側だけで、サーバは開けたかを合図で知るだけ。Claude のデスクトップで開けるかは P2 で実機で確かめる
2. **画面の修正指示**: ページかデッキ全体への指示 → 振り分け（文字・構成なら台本係、絵だけなら revise）→ 描き係 → 新しいページの版
3. **書き出し**: 採用している描いた回の PPTX・PDF を配る（作っていなければその形式だけ作る）

## 6. 画面で直すところ

調べた結果、v1 の画面のうち次がページごとの生成に結びついている。描き係が同じ項目を返せるかで、直す量が決まる。

| 画面の部分 | v2 での扱い（案） |
|---|---|
| ページごとの進み（作成中・待ち・失敗）と4区分の件数 | image-slide はページを並列に描くので、ページごとの進みを返せる見込み（要確認）。html-slide は画像の枠を描く間だけ |
| 版スタック・採用・見比べ | 描いた回ごとのページの画像を版として返す。採用は「そのページはどの描いた回の絵を使うか」 |
| minor・remake の可否（`can_minor`） | image-slide は revise の土台があるか。html-slide は画像の枠があるページだけ |
| 止まっている帯と再開（Codex の枠切れ） | エンジンの rc=4 と枠切れの待ちを同じ帯に出す |
| ページの差し込み | 台本係に「この後ろに1ページ」と頼む |
| ブランドのロゴの予約枠（四隅・予約矩形） | 四隅 → `--logo-position` の3つ。予約矩形の表示は外す |
| スタイルの「使うレイアウトパターン」 | エンジンの型の一覧（html-slide の catalog）に替える |
| 1ページ＝1枚の画像の前提（コピー・保存） | ページの画像（`slides/slide-NN.png`）があるのでそのまま使える |

## 7. 進め方（段）

| 段 | 中身 | できたら確かめること |
|---|---|---|
| P1 土台 | サーバの土台（起動・二重起動の防止・静的配信・セッション・起動トークン・エラーの形）・DB の仕組み・画面の丸写し。ホーム・一覧・設定が開く | 本物のブラウザで画面が開き、例外が出ない |
| P2 会話から1冊 | intake → 台本係 → check → 描き係（両モード）→ スライドの画面にページの画像が出る | 原稿1本から両モードで1冊できる |
| P3 直す | 修正指示の振り分け・revise・版と採用・差し込み・並べ替え・非表示 | 画面から文字と絵を直せる |
| P4 設定をエンジンへ | ブランド → テーマ・ロゴ、スタイル → エンジンのスタイル、書式 | 設定を変えると次に描く回に効く |
| P5 書き出しと仕上げ | エンジンの出力を配る・ごみ箱・導入の手順（puppeteer・Chrome・字体） | 配った機体で動く |

## 8. 決めたこと（2026-10-07）

1. **モードは切り替えない。** デッキを作るときに決め、替えたいときは作り直す
2. **台本は画面に見せない。** 利用者が触るのは指示文だけ
3. **台本係の LLM は Claude Code か Codex**（配るのでどちらもありうる）。画像を描くのは Codex だけ
4. **ポートは 7801**（v1 と並べて動かさない）。データの置き場は v1 と分ける（`~/.quick-slide/`）
