# 0016 依頼・直しの指示に書かれたページの本文の画像を使う（頼まれたときだけ・出典を書く）

- 日付: 2026-10-14
- 状態: 採用
- 関係: `docs/adr/0008-edit-kinds.md`（画像は利用者が渡したときだけ）・`docs/adr/0002-create-from-screen.md`（依頼から作る）

## 背景

画面の入力欄に「（記事の URL）これを 10 枚にして。画像も本文中のものを使って」と頼んでも、記事の画像は使われなかった。
下調べ係はページの文章だけを原稿にし、台本係には「画像の path は書かない（手元にある画像は無い）」と言っていたため、
台本係は代わりに挿絵や生成の枠を書いた。ADR 0008 では、Web の画像は画像そのものの URL を指定されたときだけ取り込むとしていた。

## 決めたこと

- **ページの URL を渡して「画像も使って」のように頼まれたときは、そのページの本文の画像を使ってよい**（利用者の判断。2026-10-14）。
  画像を使ってよいかは、頼んだ人が判断する
- 集めるのは、依頼・直しの指示に**ページの URL と「画像・写真・図・イラスト」などの言葉が両方ある**ときだけ
  （`page_images.wanted_urls`）。使うかどうかは台本係が指示から決める（求めていなければ使わない）
- サーバがページの HTML を取り、本文（`<article>`・`<main>` があればその中）の画像を、図の説明・代替テキスト・近くの見出しと
  一緒に拾う（`srcset` は一番大きいもの。ロゴ・アイコンらしい名前・`data:`・SVG は除く）。取り込みは URL の貼り付けと
  同じ決まり（`server/image_fetch`。公開のアドレスだけ・転送先も確かめる・大きさの上限）。PNG・JPEG・WebP で、短い辺が
  240 以上、動かない画像だけを、1 つの指示につき 10 枚まで、台本のフォルダの `attachments/page-<鍵>` に置く
- 台本係には「使ってよい画像」として、path・何の画像か・出典（ページの名前と URL）を渡す
- **使った画像のページには必ず出典を書く**: photo・figure・gallery・quote なら caption、ほかの型はページの source に
  「出典: <ページの名前> <URL>」
- 効く場所: 画面の入力欄の依頼から作るとき（`pipeline.write_script`）・直し・ページを足す（`worker/edit.py`）。プレゼンだけ

## 理由

- 「この記事をスライドにして、画像も使って」は、ページを渡した人が中の画像の扱いも決めている頼み方。画像の URL を
  1 つずつ貼らせるのは手間が大きい
- 出典を書けば、どこから持ってきた画像かがスライドを見た人にも分かる

## 却下した案

| 案 | 却下の理由 |
|---|---|
| URL を渡されたら、頼まれなくても画像を使う | 画像を使ってよいかは頼んだ人が決める。頼まれていないのに持ち込まない（利用者の選択） |
| 下調べ係（LLM の Web 取得）に画像の URL も集めさせる | 取得の中身に画像の URL が残るとは限らず、確かめにくい。HTML を読めば決まった手順で拾える |
| 出典を書かない | 他人のページの画像を使うので、どこからかを残す（利用者の選択） |

## 残したこと

- 会話から原稿で作るときの、原稿の中の URL（会話側が画像を渡す道で足りるかを見てから）
- ピッチ（image-slide）での使い方
