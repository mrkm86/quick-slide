# 0004 ブランドを ZIP でエクスポート・インポートする（チームや組織で同じブランドを配る）

- 日付: 2026-10-12
- 状態: 採用
- 関係: `docs/adr/0003-brand-preview-engine-colors.md`・`src/quick_slide/brand_package.py`

## 決めたこと

ブランド 1 つを ZIP に書き出し、別の Quick Slide で読み込めるようにする。

### ZIP の形（`brand_package.py`・形式の版 1）

```
brand.json         {"format": "quick-slide-brand", "version": 1, "id", "name", "exported_at", "config",
                    "assets": [{"role", "label", "file", "sha256", "media_type"}]}
assets/<役割>.png   ロゴの画像（PNG か JPEG。役割は logo_normal・logo_white・logo_transparent・logo_symbol）
```

- 入れるのは **設定（色・フッター・ウォーターマーク・ロゴの位置・字体の名前）とロゴの画像だけ**。字体のファイルは入れない
  （配布の権利が絡む）。ロゴでない役割の画像（差し絵など）も入れない
- ブランドの ID（UUID）をそのまま入れる。読み込む側で「同じブランドか」を見分けるのに使う

### 書き出し

- `GET /api/settings/brands/<id>/export` → `application/zip`（ファイル名は `qs-ブランド-<名前>.zip`。`brand_package.filename` が決め、画面はサーバが返した名前で保存する）
- ファイル名は **人が見分けるためだけ**に付ける。読み込むときはファイル名を見ない。受け渡しで `(1)` が付いたり改名されたりしても読める。
  種類を見分けるのは中の `brand.json` の `format`（今後テンプレートを配るときは別の `format` と `qs-テンプレート-<名前>.zip` にする）
- 画面: 一覧の各行のメニュー（︙）の「エクスポート」。一覧の上の「インポート」（画面の言葉はエクスポート・インポート。改名の項目も「名前を変更」）。**付属のブランドは書き出さない**（ID が全員同じで、配る意味が無い。複製してから書き出す）

### 読み込み（2 段）

1. `POST /api/settings/brands/import/check`（ZIP のバイト列）→ 中身の要約と、同じ ID のブランドの有無と、選べる道。**何も保存しない**
2. `POST /api/settings/brands/import?mode=replace|add[&expected_revision_id=…]`（同じ ZIP を送り直す）→ 保存

| 同じ ID のブランド | 選べる道 | 結果 |
|---|---|---|
| 無い（別の機械） | 読み込む | **同じ ID のまま**作る（次に同じブランドの新しい ZIP を読めば上書きを選べる） |
| 自分のブランドがある | 上書きする／別のブランドとして追加／やめる | 上書き＝**新しい改訂**（前の改訂は履歴に残る。ロゴでない画像は持ち越す）。追加＝新しい ID・名前に「（インポート）」 |
| 付属のブランド・削除済み | 追加する／やめる | 新しい ID で作る |

- 上書きは、確かめたときの改訂（`expected_revision_id`）と今の改訂が違えば断る（別の画面で直された内容を黙って消さない）
- 設定の中身は保存と同じ決まりで確かめる（`validate_brand_config`・`brand_preview`）。画像は設定画面の画像と同じ検査を通して登録する
  （`store_image`）。画像の登録はデータベースの取り引きの外で先に行う（あとで断られても、記録とファイルが食い違わない）

### 他人から受け取った ZIP として読む

- ディスクへ展開しない。決まった名前（`brand.json`・`assets/<役割>.png|jpg`）だけを、上限を超えて読まない読み方で読む
- 断るもの: ZIP でない・暗号化・知らない名前（上の階層を指す名前を含む）・個数の超過・展開後の大きさの超過・不自然な圧縮率・
  一覧に無いファイル・ハッシュ値の不一致（画像の書き換え）・形式名や版の違い・ID や名前の形の誤り
- 理由は画面にそのまま出せる日本語の文で返す（`package_invalid`）。読み込みは状態を変える要求なので、セッションのトークンが要る

## 却下した案

- **複数のブランドを 1 つの ZIP に**: 配る単位がわかりにくくなる。必要になったら版 2 で足す
- **読み込みを 1 回の要求で済ませる（選択をあとから送る）**: サーバに ZIP を一時的に置く必要があり、置き場の掃除と期限を持つことになる。
  2 回送っても ZIP は小さい
- **同じ ID なら黙って上書き**: 別のチームが同じブランドを直していた場合に、手元の変更が消える
- **ファイル名（`qs-` で始まる、など）で読み込む ZIP を絞る**: 名前は誰でも変えられるので守りにならず、改名された正しい ZIP を断ってしまう。
  守るのは中身の検査（上の「他人から受け取った ZIP として読む」）
- **このアプリが書き出した ZIP だけを署名で見分ける**: 組織の中で鍵を配って管理することになる。中身をすべて疑って確かめる今の読み方で足りる
- **独自の拡張子（`.qsbrand` など）**: OS で開けない・メールで止められやすい。`.zip` のままにする
- **字体のファイルも入れる**: 字体の配布の権利が絡む。名前だけを入れ、ファイルは各自の機械の設定で引く
