# 0026 起動確認を待ちきれなかった子は、終了させてから失敗を返す

## 採用

`quick_slide.server start` の既定の待ちは30秒とする。停止・状態確認は10秒のまま、
明示した `--timeout` はどのコマンドでも優先する。会話の入口の起動待ちも既に30秒である。

起動を確認できなかったときは、その `start` が起こした子を組ごと止め、子の終了を待ってから
`start_failed` を返す。`child_exit_code` は終了後の値とする。先に起きていた別のサーバには触れない。
起動途中は `server.json` がまだ無い場合もあるため、停止には控えの PID ではなく起こした子を使う。

再起動の実プロセス試験は、起動結果の `ok` を確かめてから先へ進む。失敗時には `server.out` と
`server.log` の末尾を出す。後片付けは停止結果を確認し、応答できないサーバは強制終了して終了を待つ。

## 理由

Windows CI では10秒で起動を確認できず、あとから起動したサーバが試験の置き場をつかんだまま残る
失敗が起きた（#19）。待ちを増やすだけでは、再び上限に達したときの置き去りを防げない。

## 却下

待ち時間だけを延ばす: 起動がさらに遅い場合や起動途中で止まった場合に子が残る。

子を残して失敗を返す: 呼び出し側が失敗後にやり直したり置き場を片付けたりする時点で、状態が確定しない。
