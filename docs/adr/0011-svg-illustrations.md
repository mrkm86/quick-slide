# 0011 プレゼンの挿絵は SVG で書き、サーバが挿絵のスキルで PNG にしてから html-slide に渡す

- 日付: 2026-10-13
- 状態: 採用
- 関係: `skills/illust/docs/adr/0001-svg-illustrations.md`・`docs/adr/0008-edit-kinds.md`・`docs/adr/0010-images-follow-the-machine.md`

## 背景

プレゼンで空気・場面・たとえを伝える絵は、これまで画像生成（Codex）しか手が無かった。Codex が無い機械では絵を入れられず、
直しの「何を直しますか？」でもプレゼンの「挿絵」を出していなかった。試作（アイコンを組み合わせる A・単純な形で描く B を
3 場面ずつ）で、台本係と同じ LLM が書いた SVG の挿絵が資料に使える出来になると分かった（2026-10-13）。

## 決めたこと

- 台本係は、プレゼンの画像の枠に `image: {"svg": "<svg viewBox=…>…</svg>"}` で挿絵を書ける。生成（`prompt`）・持ち込み
  （`path`）と並ぶ 3 つ目の出どころ。Codex は要らないので、生成できない機械でも書ける
- 書き方は挿絵のスキル（`skills/illust`）の手引き `references/authoring.md`。台本係への「台本の決まり」に足す
  （`engines.py` の `contract_docs`）。配色はこの回のテーマの主役の色から作って渡す（`writer/prompt.py` の `illust_rule`）。
  viewBox の比は枠の形（縦長 960×1080・横長 1600×900）に合わせる
- **台本の版は SVG のまま**持つ。エンジンに渡す直前（検査・描く）に、サーバが挿絵のスキルの `illust.py png` に通して PNG にし、
  `scripts/illustrations/<SVG の鍵>.png` に置いて枠を `path` に替える（`render/illustrations.py`）。同じ SVG は描き直さない
- 描けない挿絵（スキルの `NG:`）は、ページの id を付けて台本係に返し、書き直させる（検査の NG と同じ道）
- Chrome は html-slide の `browser.py` が知っている在りかを渡す（エンジンの探し方が正本）。無ければスキルが自分で探す
- 直しの「何を直しますか？」で、プレゼンにも「挿絵」を出す
- html-slide は変えない（画像の枠はいつもどおりファイルを受ける）。PPTX の中では 1 枚の絵になる

## 理由

- 挿絵は html-slide と motion-slide の両方で使う。素材づくりなので、エンジンではなく独立したスキルに置き、サーバが呼ぶ
  （エンジンはほかのスキルを呼ばない・素材はファイルで受ける）
- 台本の版に SVG を持てば、ページの版の切り替え・複製・直しでも挿絵が中身と一緒に動く。PNG は作り直せる控え
- 書いた SVG は外から来た文（原稿に混ざった指示）の影響を受けうる。スキルが描いてよい形だけに絞ってから Chrome に渡す

## 却下した案

| 案 | 却下の理由 |
|---|---|
| 台本係が PNG の path を書き、別の道で PNG を作る | 台本と絵が離れ、版の切り替えや複製でずれる |
| html-slide に SVG を受けさせる | エンジンを変えることになり、PPTX に SVG を置けない問題は残る |
| 挿絵ごとに台本係に描き直させる手順（撮って見せる）まで今回入れる | 試作の出来で足りる。粗が目立てば足す |

## 残したこと

- モーションの場面に挿絵を置く道（スキルの `clean` で絞った SVG を場面の HTML に置く）
- 図形のまま PPTX に入れて、PowerPoint で直せるようにする道
- 本物の台本係が、どのページに挿絵を選ぶか・どんな出来になるかを、実際の原稿で確かめる
