# 0012 非表示のページも絵を描き、画面では薄く出す（下見の絵）

- 日付: 2026-10-14
- 状態: 採用（プレゼン。ピッチ・モーションはこれまでどおり）
- 関係: `docs/adr/0011-import-pptx.md`（取り込んだ PPTX の非表示のスライドは、非表示のページのまま入る）

## 決めたこと

非表示のページは「未生成」の空の枠ではなく、**絵を描いておき、一覧では薄くグレーアウトして中身が見えるようにする**
（利用者と決めた・2026-10-14）。発表・書き出し・枚数には、これまでどおり入れない。

1. **描く**: 描く回（プレゼン）が終わったあと、非表示のページだけをエンジンで絵（PNG）だけ描く（`worker/pipeline.draw_hidden_previews`）。
   新しい絵は生成しない（`--no-fill`。描いてある生成の絵はキャッシュから使う）。中身の sha256 が前の下見と同じページは描き直さない。
   描けなくても回は失敗にしない（そのページは「未生成」のまま）
2. **持つ**: 下見の絵は描く回のページ（`run_pages`）に入れず、別の表 `page_previews`（1 ページに 1 枚・移行 0010）に持つ。
   資産の参照（完全削除・ごみ箱）にも数える。複製でも写す
3. **出す**: スライドの画面は、非表示のページに絵が無ければ、中身の sha256 がいまのページと同じ下見の絵を出す。
   見た目は前からある非表示のページの見せ方（灰色・半透明）

## 理由

- 取り込んだ PPTX には非表示のスライドが多い（実物の 116 枚で 10 枚）。中身を確かめてから戻すか決めたい
- 描く回のページに混ぜると、カードの枚数・「完成」の数・発表・書き出しが非表示のページを数えてしまう。別の表なら、
  いまの描く回の決まり（描いたページ＝見せるページ）を変えずに済む
- html-slide は数秒で描ける。生成の絵を新しく描くと Codex の枠を使うので、下見では描かない

## 見送ったこと

- **エンジンに「絵だけ描いて PPTX・PDF には入れないページ」を足す**: PPTX・PDF・サムネイル・発表の HTML の全部に例外が要る。
  非表示のページだけの台本をもう 1 回描く方が、エンジンの決まりを変えない
- **ピッチ・モーションも描く**: ピッチは 1 枚ずつ Codex で描くので、見せないページに枠を使う。モーションは全部の拍を開いて確かめるので数分かかる
