# 0005 ピッチは Codex がある機械でだけ選べる（軽い確かめで札を押せなくし、作成の依頼も断る）

- 日付: 2026-10-13
- 状態: 採用
- 関係: `docs/adr/0002-create-from-screen.md`・`skills/image-slide/SKILL.md`（`auth --quick`）

## 決めたこと

ピッチ（image-slide）は全ページを `codex` CLI で描く。Codex が無い・ログインしていない機械では作り始めても描く段で止まるので、
**作り始める前に分かるようにする。**

- **確かめはエンジンに聞く。** `image_slide.py auth --quick` を足した。codex が見つかるか（`IMAGE_SLIDE_CODEX`・設定の
  `codex_bin`・PATH。探し方の正本はエンジン）と、ChatGPT のログインの記録（`$CODEX_HOME/auth.json` が ChatGPT のログイン）が
  あるかだけを見る。**子プロセスを起こさない**（実機で 0.1 秒ほど）。終了コードは `auth` と同じ（0 / 4）
- **サーバ** は `QuickSlideServer.kind_refusals()` で形式ごとの「いま作り始められない理由」を持つ。答えは 10 秒だけ覚える
  （`KIND_CHECK_SECONDS`）。Codex を入れた・ログインしたら、サーバを起こし直さなくても画面を読み直せば使える。
  聞けなかったとき（起動できない・時間切れ）は使える扱い（描く前の確かめ `check_prerequisites` が拾う）
- `/api/vocabulary` の `deck_kinds[]` に `available`（真偽）と `reason`（使えない理由の日本語。使えるなら空）を足した
- `POST /api/intakes` はその形式が使えないなら **409 `engine_unavailable`** で断り、デッキを作らない。画面は札を押せなく
  しているが、会話の入口（`quick_slide_start.py --mode pitch`）も同じ口に来るので、サーバでも断る
  - 入力の誤り（400 `validation_error` など）は先に言う。検査（`store.intake_mode`。何も書かない）を通ってから Codex を確かめる
- **画面** は使えない札を残したまま押せなくする（点線の枠・選んでいない札より薄い灰色・「使えません」）。理由は札の下に文で出す
  （スマホは札が小さく説明を畳むので、札の中には入れない）。前に選んで覚えていた形式が使えないなら、使える最初の形式を選ぶ

## 却下した案

- **描く前の確かめ（`auth`）をそのまま使う**: `codex login status` を走らせ、トークンが古いと Codex を 1 回呼んで更新する。
  画面を開くたびに走らせるには重く、サブスクの枠も使いうる
- **サーバが自分で codex を探す**（`shutil.which` と `auth.json`）: 探し方（環境変数・エンジンの設定の `codex_bin`）の正本が
  2 か所になる。サーバはエンジンの中身を持たない決まり（`engines.py`）
- **札ごと隠す**: なぜピッチが無いのかが分からない。入れれば使えることも伝わらない（利用者の選択、2026-10-13）
- **本体があるかだけを見る**: ログインしていない機械でも選べてしまい、描く段で初めて止まる（利用者の選択、2026-10-13）

## 残したこと

- 確かめはピッチの**作り始め**だけ。できあがったピッチのデッキのページを直す・組み直すときは、いままでどおり描く前の
  確かめ（`auth`）が止める
- プレゼン（html-slide）も画像の枠に Codex を使うが、要るかどうかは台本次第でエンジンが決める（`deck` の rc=4）ので、札は止めない
- ログインの記録はあってもトークンが切れている場合は、確かめを通る。描く前の確かめで「`codex login` して」と止まる
