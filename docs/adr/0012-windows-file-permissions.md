# 0012 Windows では 0600 に頼らず、置き場のアクセス権を診断で確かめる

- 日付: 2026-10-13
- 状態: 採用（診断の確かめは Issue #1 の W7 で入れる）
- 関係: Issue #1 の C3・W6・W7、ADR 0006（`oscompat.py`）

## 決めたこと

mac・Linux では、秘匿するファイル（`config/hmac.key`・`runtime/server.json`・ログ・Codex の隔離ホームの `auth.json`）を
0600、置き場のフォルダを 0700 で作り、本人だけが読めるようにしている。Windows の `chmod` は読み取り専用の印を
変えるだけで、この約束は効かない（`chmod(0o600)` の後も mode は 0o666）。Windows では次のように守る。

- **`chmod` の呼び出しはそのまま残す。** Windows では読み取り専用の印を付け外しするだけで、害は無い。OS で書き分けない
- **置き場は利用者のプロファイルのアクセス権（ACL）を継承する。** 既定の置き場（`%USERPROFILE%\.quick-slide`）は、
  本人・SYSTEM・Administrators だけが読める。mac の「ホーム ＋ 0700、ただし root は読める」と同じ強さ
- **診断（`quick_slide_setup.py --doctor`）が確かめる**（W7 で入れる）:
  - 置き場の ACL に、Everyone（`S-1-1-0`）・Users（`S-1-5-32-545`）・Authenticated Users（`S-1-5-11`）の読み取りが無いこと。
    名前でなく SID で比べる（日本語版の Windows ではグループ名が訳されている）
  - 置き場が OneDrive の同期先の中に無いこと（原稿や画像がクラウドへ出ていく）
  - 当たれば警告する。起動は止めない（止めると、利用者が自力では抜けられない）
- **試験**: 0600 を確かめる試験と、`chmod` で読めない・書けないファイルを作る試験は、Windows では理由を書いて飛ばす

## 採らなかった案

- **icacls で継承を切り、本人だけに絞る（既定で）**: バックアップの道具や管理者の調べが読めなくなる。途中で失敗すると、
  自分でも開けないフォルダが残り、利用者には直せない。診断が「他人が読める」と判定したときに、同意を取ってから
  行う直し方としてだけ残す
- **ファイルを作るたびに ctypes で DACL を付ける**: 書き込みの経路すべてに手が入るわりに、プロファイルの ACL を
  継承するのと比べて守れる範囲が増えない
- **Windows では `chmod` を呼ばない（OS で書き分ける）**: 呼んでも害が無いので、書き分けるだけ分岐が増える

## 影響

- mac・Linux の動きは変わらない
- Windows の秘匿は、置き場をどこに置くかで決まる。`QUICK_SLIDE_HOME` を共有のフォルダや OneDrive の中に向けると
  守れないので、診断がそれを言う
