# 0035 デッキが「ブランドなし」を自分で持つ（取り込んだ資料）

- 日付: 2026-11-19
- 状態: 採用
- 関係: `docs/adr/0011-import-pptx.md`（取り込み）・`docs/adr/0032-remove-deck-rebuild.md`（設定を替えて組み直す操作の撤去）

## 決めたこと

- デッキに「ブランドなし」の印を持たせる（`decks.brandless`。移行 0014）。**取り込んだ PPTX のデッキはブランドなし**で作る
- ブランドなしのデッキは、どの回でも（取り込み・直し・ページを足す・描き直し）ロゴ・フッタ・ページ番号・**透かし**を足さない。
  色は PPTX のテーマ（取り込みが書けたときだけ。足したページは元の資料の色に寄る）
- 見るのはデッキの印。描いた回の引数 `imported` は取り込みの回にだけ付くので、これまでは直しの回でブランドのものが足された
- 複製はブランドなしを引き継ぐ。0014 より前に取り込んだデッキとその複製は、3 つの手掛かりで埋め戻す: 取り込みの回を持つ・
  台本に取り込んだページ（型 `html`）を持つ・そこから複製をたどれる（直したあとの複製は、写した回に取り込みの印が無い。
  複製元を完全に消した複製は、複製元を指していない）
- 0014 より前に、直してブランドのロゴなどが付いた回は、そのまま残る（発表・書き出しは、描いてある回をそのまま出す）。
  次にどこかを直すと全ページを組み直すので、そのとき消える。移行では描き直さない（起動のたびに重い仕事を走らせない）
- 画面・API のデッキの `brand` は、ブランドなしのとき `null`。一覧をブランドで絞っても、ブランドなしのデッキは出さない
- `decks.brand_revision_id` は NOT NULL のまま残す（ブランドなしのデッキでは使わない）

## 理由

- 取り込む資料は、配られた様式・決まった営業資料のように、もう仕上がった見た目を持つ。直しただけで別のロゴが付くと使えない
- 「取り込んだか」を回ごとに渡すと、渡し忘れた口で壊れる（実際に、直しの回で全ページにロゴが付いた）。デッキが持てば、
  どの口も同じ 1 か所を見る
- 透かしも足さない。配られた様式に、こちらのブランドの「社外秘」が載るのは意図と違う（0011 では透かしだけブランドのままだった）

## 却下した案

| 案 | 却下の理由 |
|---|---|
| `brand_revision_id` を NULL にできるようにする | 表の作り直しと、ブランドを引くすべての所の書き換えが要る。印の列を足すだけで同じ意味になる |
| 取り込むときに「ブランドを載せるか」を聞く | 初めての人は選べない。会話からの取り込みでも聞くことになる |
| 元の資料にロゴ・フッタがあるかを調べて自動で決める | 見分けを誤ると、配られた様式にこちらのロゴが載る |
| 直しの回の引数にも `imported` を渡す | 口が増えるたびに渡し忘れる。複製・描き直し・ページを足す口のどれも同じ手当てが要る |

## 残したこと

- ブランドを付けたいとき: 「ブランドを指定して複製する」を足す（色も変わるので、全ページを描き直す別の資料として作る）
- 元の PPTX のページ番号は固定の文字として写る。ページを足す・並べ替えると番号がずれる
- PPTX がテーマを使わず、図形に直接色を付けている資料では、足したページの色が元のページと揃わない
