# 0029: 会話で考え、Quick Slideで資料に仕上げる

状態: 採用（#35）

## 決定

調査・事実確認・任意の外部スキルの実行・構成の合意は、Quick Slideを導入した会話で行う。
Quick Slideは原稿を台本・描画へつなぎ、資料の修正・発表・書き出しを担当する。
制作のために登録資料や素材の説明書きを読むことは、そこに書かれたスキルやコマンドを実行することとは異なる。
素材を入力事実として扱える範囲、テンプレートの生成への接続と実行制限は#22で定義する。

ホームには既存の画像と「思いついたら、もう資料。」を残し、資料の作成とプレゼン資料の取り込みを並べる。
作成は同じタブの`/create`に移り、会話に貼る依頼文を組み立てる。画面から生成の受付は呼ばない。
既存のPowerPoint取り込みは、ファイル選択・ドロップ・取り込み後の遷移を維持する。
取り込みボタンとプレゼンの形式には、既存の青い役割色を使う。形式のアイコン・説明も既存の語彙を使う。

依頼文にはテーマ、形式、ブランド、対応するテンプレート、分量、見せ方、進め方を含める。
登録IDを明記し、名前だけで候補を推測しない。依頼文へ入れる登録名は改行を除き長さを制限して引用する。
テンプレート本文・説明・素材のパスは依頼文に展開せず、ブランドIDとテンプレートIDを組にして取得する。テンプレートはブランドと形式で絞り、Motionでは選べない。
会話側は選択したテンプレートを先に確認する。生成へ適用できない版では、その条件を黙って捨てず会話で説明する。
テンプレートの実行経路や新しい投入引数は、この画面のために重複実装しない。

進め方は次の2つ。明示した希望を従来のA/B推定より優先する。

- ページ構成を確認してから作る（既定）: ページの見出し・要点を会話で示し、了承を待つ。
  合意後は`--outline-fixed`で順序・主張・枚数を保つ。
- そのまま作成まで一気に進める: 構成だけの中間承認を挟まない。必須情報が足りなければ会話で質問する。

PCでは依頼文のプレビューを残りの縦幅まで伸ばす。スマホではコピー操作の下に全文を常時表示する。
コピー失敗時には全文選択による手動コピーを案内する。
コピーが成功した時点の選択条件だけを`DataRoot`が定義するconfig内の専用JSONに原子的に保存する。
本文は保存しない。通常のサーバ設定と分離し、コピーごとに設定の再読込を起こさない。
複数の画面では最後の保存を採用する。保存時に実ID・ブランド・対応形式を再検証する。
削除された候補は再表示時に既定へ戻して案内する。保存失敗をコピー失敗と混同しない。
APIには既存のHost・Origin・セッショントークンの検査を適用する。

## 互換と担当

従来の`--request`・request API・下調べ係は、既存の呼び出しと未完了ジョブの互換用に残す。
新しいホームと会話SKILLの通常の案内からは呼ばない。過去の資料・履歴・ジョブは削除しない。
この互換経路では引き続きサーバ内のWeb下調べが動くため、全経路で廃止したとは説明しない。
#22のテンプレート接続もこの経路に触るため、廃止や挙動変更はここでは行わない。
設定画面のテンプレートの例・注意書きは#22、会話の役割とホームの入口は#35で整える。
共有ファイルは`skills/quick-slide/SKILL.md`と`web/app/design-template-editor.js`。
Motionのテンプレート対応は#28で扱う。

## 採らなかった案

- ホームから直接生成する: 調査と構成合意が会話とサーバに二重化し、役割が曖昧になる。
- ブラウザだけに条件を記憶する: 別端末や別ブラウザで引き継げない。
- モックをそのまま製品に入れる: 架空の登録IDや検分用サーバは本番の契約ではない。
- 旧requestを即時削除する: 既存のCLI・APIや未完了ジョブを壊す。削除の判断は別途行う。

旧ADR 0002の画面からの生成は、この決定により新規の入口を置き換える。旧経路の記録としてADR自体は残す。

## 受入確認

- 元の画像・文言・形式カードと取り込みを実ブラウザで確認する。
- 直接のURL、コピー成功・失敗、記憶の失敗、別ブラウザの復元、ブランドと形式による絞り込み、長い登録名を確認する。
- スマホの全文表示、PCの残り幅・高さ、生成APIを呼ばないことを確認する。
- 保存APIのID・形式・未知の項目・Host/Origin/トークンの拒否と原子的な保存を確認する。
- 既存settings.jsonは変更しない。本文は保存せず、ファイルにschema_versionを持つ。
- 依頼文は生成CLIの有無に関わらず作れる。取り込みの可否は取り込みAPIが判定する。
- 古いブラウザの形式記憶は移行せず、初回は新しい既定条件を使う。
