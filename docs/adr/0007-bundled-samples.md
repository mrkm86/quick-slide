# 0007 見本のスライドを同梱し、最初の起動で入れる（消してよい・入れ直せる・作り直して更新できる）

- 日付: 2026-10-13
- 状態: 採用
- 関係: `samples/`・`src/quick_slide/samples.py`・`samples/build.py`・`src/quick_slide/db/migrations/0008_samples.sql`

## 決めたこと

入れてすぐ、3 つのモード（プレゼン・ピッチ・モーション）がそれぞれ何に向いているかを見られるように、
**モードごとに 1 冊の見本**（そのモード自身の紹介）を同梱し、最初の起動で普通のデッキとして入れる。

### 同梱の形（`samples/<見本>/`）

```
sample.json          手で書く: id・題・副題・目的・読み手・モード・スタイル（エンジンのスタイルの名前）・overrides・並び順
script.json          台本の正本（手で直すのはここ）
built/               samples/build.py が書く（手で直さない）
  manifest.json      {"format": "quick-slide-sample", "format_version": 1, "id", "version", "mode", "engine",
                      "script_sha256", "args", "pages": [{no, key, warnings, picture_sha256}], "files": {パス: sha256}}
  script.json        描いた台本（script.json と同じ中身。違えば試験が落ちる＝作り直し忘れ）
  run/               描いた回の控えのうち、画面・発表・書き出し・直しに要るもの
```

- `run/` に入れるのは: ページの画像（`slides/`）・絵の控え（`pictures/`）・エンジンの記録（`deck-info.json`・`build.json`）・
  テーマの控え（`settings/theme.yaml`）・発表の画面の HTML と画像（`present/deck.html`・`present/assets/`・`present/index.html`）・
  モーションの HTML 1枚（`index.html`）
- **入れないもの**: PPTX・PDF（書き出すときに作る。下の「残したこと」）・サムネイル一覧・検査の画像（`check/`）・ログ・
  検品の文（`inspect.md`）・書き出しの部品（`parts/`）・**字体のファイル**（配布の権利。名前とパスの形だけ）
- 記録の中の置き場（データの置き場・デッキ・回のフォルダ・キャッシュの根っこ）と id は、作るときに目印（`{{HOME}}`・`{{RUN_DIR}}`・
  `{{CACHE}}`・`{{RUN_ID}}` など）に置き換え、入れるときに入れる機械の値へ戻す。JSON は文字列の値だけを置き換える（Windows の
  パスでも壊れない）。**置き換えたあとに絶対パスが 1 つでも残っていたら、作るのをやめる**（作った人の機械のパスを配らない）
- 見本の版（`version`）は中身の sha256。作り直せば変わる

### 入り方

- サーバの起動（`serve`・`start`）で、DB を開いたあと・ワーカーを起こす前に `samples.sync` を呼ぶ。失敗しても起動は止めない（ログに残す）
- 記録は 2 つの表（`0008_samples.sql`）:
  - `samples_seen`（見本の id → 初めて入れた時刻）: **一度入れた見本は、消されても起動のたびに入れ直さない**
  - `sample_decks`（デッキ → どの見本のどの版か・入れたときの台本と回）: 更新と「入れ直す」の判定に使う。完全に削除すると行も消える
- 入れたデッキは普通のデッキ（付属のブランドと、見本の `style` にあたる付属のスタイル）。タグ「見本」を付ける。
  直す・複製する・ごみ箱へ送る・書き出すは、ほかのデッキと同じ

### 更新（見本を作り直して配ったとき）

| 手元のその見本のデッキ | 起動のとき | 設定 › 見本 の「入れ直す」 |
|---|---|---|
| まだ一度も入れていない（新しく足した見本） | 入れる | 入れる |
| 入れたまま触っていない（台本も回も入れたときのまま）・版が古い | **新しい版へ進める**（同じデッキに新しい台本の版と回を足す。前の姿は版スタックに残る） | 同じ |
| 直した・並べ替えたなど（台本か回が増えた） | 触らない | 新しい版を**別のデッキとして**足す |
| ごみ箱にある・完全に削除した | 触らない | 新しい版を別のデッキとして足す |
| 最新の版のまま残っている | — | 何もしない（「入っています」） |

- 名前の変更・ピン留め・アーカイブは「触った」に数えない（中身が入れたときのまま）

### 作り直し（`samples/build.py`）

1. 一時的なデータの置き場でサーバを立てる（本物のエンジン。台本係は呼ばない）
2. 前に作った `built/` があれば、それを**同じ取り込みの道で**入れる（ピッチの絵・プレゼンの生成の枠の絵が控えに入る）
3. `script.json` を検査（ページの id・日本語の検査・エンジンの `check`）してからいまの台本にし、描き直し（`render`）の仕事で描く。
   **中身が変わらないページの絵は控えから使い回す**（ピッチは鍵が合えば Codex を呼ばない。変えたページだけ枠を使う）
4. 見せる回から `built/` を作り直す（目印への置き換え・残ったパスの検査・sha256）
- エンジンの設定は、一時的な置き場に**字体（Noto Sans JP）だけ**を書いたものを使う。作る人の機械の設定（ロゴ・出力先など）は読まない。
  字体は作る人のデータの置き場の `fonts/` から写す（無ければ游ゴシックなどの代わりの字体で組まれる）

## 却下した案

- **台本だけを同梱し、最初の起動で描く**: ピッチは Codex のログインとサブスクの枠が要り、入れた直後には描けないことが多い。
  プレゼン・モーションも Chrome で数十秒かかり、導入の手順が済むまで何も見えない
- **PPTX・PDF も同梱する**: 書き出しは見せる回に無ければその場で描き直して作る（`export_routes`）。配る大きさと履歴を増やしてまで持たない
- **起動のたびに、消された見本も入れ直す**: 消した人の意思に反する。戻したい人は設定から入れ直す
- **見本を作り直したら、触ったデッキも上書きする**: 利用者が直した中身が消える。別のデッキとして足す
- **見本のデッキを特別な種類（読み取り専用）にする**: 直す・書き出すを試せない。普通のデッキにしてタグで見分ける
- **作る道具がエンジンを直に呼んで出力を並べる**: 控え（`pictures/index.json`・発表の HTML・版の鍵）の作り方をもう一度書くことになり、
  入れたデッキを直したときの振る舞いが普通のデッキとずれる。サーバの描く道をそのまま通す
- **作る人の機械のエンジンの設定をそのまま使う**: ロゴや出力先など、配ってはいけない値が描いた結果に入りうる

## 残したこと

- **ピッチの見本の書き出し（PPTX・PDF）は Codex が要る。** 書き出しは描き直しの仕事を通り、ピッチの描き直しは描く前に
  Codex のログインを確かめる（ADR 0005）。絵は控えから使い回すので枠は使わないが、ログインしていない機械では止まる。
  ページの画像（ZIP）はそのまま書き出せる
- プレゼン・モーションの書き出しと発表は、ほかのデッキと同じく Chrome などの導入が済んでいる必要がある
- 見本の画像はリポジトリの履歴に残る。作り直すたびに大きさが増えるので、作り直しはまとめて行う
- 発表の画面の字体は、入れる機械のデータの置き場の `fonts/` に同じファイルがあれば使い、無ければ OS の字体で出す
