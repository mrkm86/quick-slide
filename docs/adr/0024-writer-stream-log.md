# 台本係の途中経過を保存する

## 状態

採用。

## 背景

大きなモーションの原稿で台本係が時間切れになっても、最後にまとめて受け取る JSON だけでは、応答が始まったか、どこまで書けたかを確認できなかった。

## 判断

Claude Code は `--output-format stream-json --verbose --include-partial-messages` で呼び、各呼び出しの作業フォルダに `events.jsonl` を保存する。新規ファイルは標準エラーの控えと同じ 0600。台本係の初稿は各 run の `writer/round-N/`、修正・下調べも既存の呼び出しごとの置き場を使う。指示文を別途保存しない。

標準出力は受信した分をすぐ読み、UTF-8 の途中のバイトを保持して復号し、都度ファイルを flush する。小さい応答も終了やバッファの満杯を待たずに残す。時間切れ・中断でも受信済みのイベントは保持する。

成功の判断は終了コードと最終 `result` のまま。途中のテキストや完成前の JSON を台本として採用せず、自動再開もしない。認証・利用枠・時間切れの分類も維持する。逐次出力の旗がない古い CLI は更新を案内する。

## 採らなかった案

- 場面ごとの並列生成: 場面間の整合と再開の設計が必要。まず出力が原因かを記録で調べる。
- 原稿量からの時間上限の変更: 原因と必要時間がまだ分からないため、既存の設定を維持する。
- 終了時だけ出力を保存: 実行中の観測ができず、突然の終了で控えを失う。

## 調べ方と制約

`events.jsonl` の `stream_event` 内の `content_block_delta`（`delta.type` が `text_delta`）には書きかけの本文、`assistant` には完了したメッセージ、`result` には最終結果が入る。初期化イベントだけなら本文がまだ受信されていない。出力がないことだけで原因を断定しない。本文が長い場合はイベントと最終結果に重複して残るため、控えの容量も増える。控えには生成した台本や下調べの内容が含まれるので、公開の報告にそのまま貼らない。

CLI の仕様: [Run Claude Code programmatically](https://code.claude.com/docs/en/headless#stream-responses)。
