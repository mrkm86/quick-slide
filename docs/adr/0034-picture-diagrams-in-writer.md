# 0034 台本係と直しで、絵で描く図解を使う

- 日付: 2026-11-19
- 状態: 採用
- 関係: html-slide の ADR 0031（絵で描く図解）・ADR 0008（直しの種類）・ADR 0010（画像は機械に従う）・ADR 0033

## 決めたこと

html-slide の「絵で描く図解」（画像の指定に `labels`。図の中の文字も Codex が描く）を、サーバから使う。

- **作るとき**: プレゼンで、絵を生成できるとき（`images` が真）だけ、台本係の「守ること」に 1 行足す。全体の構成図・システムの構成・
  画面のイメージは絵で描く図解にし、1 つの資料で 2〜5 枚を目安にする。数字・比較・手順のページには使わない
- **直すとき**: 直しの「図解」の選択肢に「絵で描く」を足す。プレゼンで、絵を生成できる機械にだけ出す（`edit_kinds.offered`）。
  「何枚目を図解にして」は、この選択肢か、指示の文で頼む
- **日本語の検査**: 図の中に描く文字（`image.labels`）は表示される文字なので、絵文字などの検査に掛ける（画像の `prompt`・`alt` は今までどおり調べない）
- ピッチ（各ページを丸ごと絵で描く）とモーション（画像を持たない）には出さない
- **頼むだけにしないで、サーバが確かめる**
  - 直しで「絵で描く」を選んだのに、答えが絵で描く図解になっていなければ書き直させる（`worker/edit.py` の `picture_problems`）。
    台本を書き換える答え（`route: script`）で、直したページに `prompt` と `labels` のある枠があること。今ある絵の描き直し
    （`route: image`・`both`）は、文字を描かせない元の指示のまま直すことになるので受けない

## 理由

図解の要るページは、資料を出したあとに「このページを図解にして」と追加で頼むことになる。まずその道を通し、
台本係が初稿の時点で判断できるようにもしておく。生成できない機械では頼めないので、出さない。

## 見送ること

- **絵を生成しない資料・機械で、台本係が生成の画像の枠を書いたときに止める検査**。いまは台本係への指示だけで、書かれると描くときに
  Codex を呼びに行く（生成できない機械では、そこで止まる）。絵で描く図解に限らない、前からある抜け。台本のキーを見比べる検査を
  試したが、絵を描き直すかどうかは枠の実際の形（見出しの行数・キャプションなど）で決まり、台本だけでは決められなかった
  （見逃しと、描き直しの要らない直しを止める誤りの両方が出た）。エンジンの検査に「まだ描いていない生成の枠があれば止める」を足すのが
  筋だが、検査のときと描くときで、描いた絵の置き場が同じに見えるかを確かめてから、別の変更として入れる

- 図をいつ使うかの基準の精査（2〜5 枚は仮の目安。使ってみて詰める）
- 描いた図の文字を、機械で一覧と照らす検品
- 図だけを描き直す画面の操作（いまは、直しの指示で `labels`・`prompt` を直して描き直す）
