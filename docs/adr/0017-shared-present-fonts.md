# 0017 発表の字体はデッキごとに、中身を共有して控える

- 日付: 2026-10-14
- 状態: 採用
- 関係: #31・`paths.py`・`render/workspace.py`・`server/static.py`・`samples.py`

## 決めたこと

発表の字体はデッキの `present-fonts/` に、中身の sha256（64桁）と拡張子を名前にして一度だけ写す。
場所は `DataRoot.present_fonts_dir` で決める。各回には `present/fonts.json` を置き、従来の配信用の名前
（元のパスの sha256 の先頭16桁＋拡張子）から、共有した中身の名前への対応を残す。

- Windows の OS の字体へハードリンクを張れなくても、同じ字体を回ごとに複製しない。
- 元の字体へのハードリンクは使わない。同じパスの字体が更新されても古い回の中身を保ち、更新した字体は別名で控える。
- URL は従来どおり回ごとの `fonts/<名前>`。配信はその回の目録が指す、このデッキの字体に限る。
  目録・字体とも symlink を辿らず、中身の名前・拡張子・デッキの境界を検査する。未参照の共有字体は配らない。
- 保存は一時ファイルを使い、完成した内容をその中身の名前へ公開する。一時ファイル名を回の間で共有しない。
- 見本を入れるときも同じ保存処理を使う。字体と目録は見本の配布物に含めず、入れる機械で作る。
- デッキの複製には、写した回の目録が指す共有字体も引き継ぐ。元デッキを完全削除しても複製先は表示できる。
- デッキの完全削除で共有字体も消える。使われなくなった字体の世代は、それまでは残す。

## 互換性

以前の `present/fonts/` の控えは従来どおり配る。既存の回は起動時に移行・削除しない。
新たに描く回と、新たに入れる見本から共有保存を使う。この変更だけでは既存の重複した控えの容量は減らない。

## 採らなかった案

- **回ごとにハードリンクして、失敗したら写す**: Windows の OS の字体で毎回写しになり、容量が増え続ける。
- **元のパスのハッシュだけで共有する**: 字体の更新が同じ名前を上書きし、古い回の表示を変える。
- **全デッキで共有する**: デッキの削除で使われなくなった字体を判定する仕組みが要る。
  デッキごとの共有なら、削除と複製の境界を既存の運用に合わせられる。
- **symlink で回から共有字体を指す**: Windows で作れる条件が限られ、配信の symlink 拒否も弱める必要がある。
- **既存の回を起動時に一括移行する**: 容量は減るが、既存の控えを書き換える範囲が広い。今回の修正には含めない。
