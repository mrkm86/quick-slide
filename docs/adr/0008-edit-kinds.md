# 0008 直すときは「何を直すか」を先に選ぶ（文字・図解・挿絵・画像）

- 日付: 2026-10-13
- 状態: 採用
- 関係: `docs/EDIT-PLAN.md`（修正の画面）・`docs/adr/0009-no-style-settings-screen.md`

## 決めたこと

修正の欄の上に「何を直しますか？」を置き、**文字・図解・挿絵・画像**の 4 つから選ぶ。選ぶと、その種類の選択肢が出る。
**文字以外は書かなくても送れる**（選んだ方針がそのまま指示になる）。補足の欄は、書きたい人のための任意の欄として残す。

| 種類 | 何をするか | 選ぶだけで決まる方針 |
|---|---|---|
| 文字 | 言い回し・見出し・本文を直す | 短くする・言い切る・やさしく・数字を先に（いくつでも） |
| 図解 | 中身を図にする | おまかせ・流れ・関係・比較・数字（1 つ） |
| 挿絵 | 中身を表す動かない絵を入れる | なし |
| 画像 | 生成した画像か、利用者が渡した画像を入れる | 生成する・渡した画像を入れる（1 つ） |

- **モードでできることだけを出す。「できません」とは出さず、出さない。** 出す種類と選択肢はサーバが決め（`edit_kinds.py`）、
  デッキの答え（`GET /api/decks/<id>` の `edit_kinds`）で渡す。画面は渡されたものだけを並べる

  | | 文字 | 図解 | 挿絵 | 画像 |
  |---|---|---|---|---|
  | プレゼン | 出す | 出す（図解の型に替える） | 出す（SVG で描いて画像の枠に置く。ADR 0011） | 出す |
  | ピッチ | 出す | 出す（描き直しの方向） | 出す（描き直しの方向） | 出す |
  | モーション | 出す | 出す（場面の中の HTML・SVG） | 出す（HTML・SVG の静止画） | **出さない**（画像を持たない） |

- **機械でできないものも出さない。** Codex が無い（ピッチを作り始められない）機械では、画像の「生成する」を出さない
- 作るときの「画像を使わない」（`images: false`）は見ない。直しで画像を使えるかは機械で決める（`docs/adr/0010-images-follow-the-machine.md`）
- **画像は、利用者が渡したときだけ使う。** フリー素材の検索はしない
- **画像を渡す入口は「＋」の 1 つ**（貼り付け・ドラッグ&ドロップも同じ）。画像の URL は欄に貼り付けるだけで、サーバが
  取りに行き、選んで送った画像と同じ検査を通して登録する（`POST /api/images/fetch`）。取り込めなければ文字のまま残し、
  理由を小さく出す
- 渡した画像が「スライドに入れる」画像か「参考」の画像かは、選んだ札で決まる（画像 → 渡した画像を入れる なら入れる、
  ほかは参考）。画像の札に「入れる」「参考」と出す。画像ごとに切り替える操作は置かない
- 種類を選ばずに書いて送るのは、これまでどおり使える（会話からの直しもこの形）
- 札にはアイコンを付け、「何を直しますか？」の横に「？」の説明を置く（説明は、そのスライドで出す種類の文から組む）
- 「作り直す」（今の絵を土台にしない）は、「今の絵をもとに直す」の切り替え（オン・オフ）で見せる。土台にできる絵が無いページでは、切り替えも理由の文も出さない（選ぶものが無いため）
- 台本係には、種類と選択肢から作った文を「直すもの」の節で渡す。利用者が書いた文は「指示」の節のまま
- 1 ページ・選んだページ・デッキ全体のどれでも同じ欄。デッキ全体で図解を選ぶと「図にすると伝わるページを図解にする」になる

### URL の取得

- `http`・`https` だけ。行き先が公開のアドレス（`ipaddress` の `is_global`）でなければ断る。転送先も同じ検査をする
  （サーバが自分自身や社内の機械を叩かされないため）。社内の画像は、手元に落としてから添える
- 大きさ・形式・画素数の上限は、画像を選んで送るときと同じ（`settings_routes.decode_image`）
- 取りに行くのは URL を貼り付けたときの 1 回だけ。取った画像は置き場に登録し、URL は覚えない

## 理由

- 自由な文だけだと、何をしてほしいのかが台本係に伝わりにくく、利用者も何ができるのか分からない。種類を先に選べば、
  直しの意図がはっきりし、書く手間も減る
- モードごとにできることが違う（プレゼンは型で組む、ピッチは丸ごと描く、モーションは画像を持たない）。できないものを
  見せて断るより、出さない方が迷わない（利用者の選択、2026-10-13）
- Web で探した画像は、資料に使ってよいかが分からない。渡された画像だけを使えば、使ってよいかは渡した人が決められる
  （利用者の選択、2026-10-13）

## 却下した案

| 案 | 却下の理由 |
|---|---|
| フリー素材の画像庫から探して候補を出す | 使用条件の確かめと出典の表示が要り、外とのつながりも増える。渡された画像だけで足りる（利用者の選択） |
| できない種類も出して、押せなくして理由を添える（ADR 0005 の作り始めの札と同じ） | 直しはモードを替えられないので、理由を読んでも打つ手が無い。出さない方が迷わない（利用者の選択） |
| 種類の選択を必須にする | 会話からの直しと、種類に収まらない指示（「この順を入れ替えて」など）が送れなくなる |
| 画像の札の中に「手持ちの画像」「URL を指定」の入口を別に置く | 「＋」と入口が 2 つになり、どちらから渡すのか分からない（利用者の指摘） |
| 画像の生成に画風（写真風・イラスト風）を選ばせる | プレゼンの画風は資料全体で 1 つ（`--image-look`）で、枠ごとに替える仕組みが無い |

## 残したこと

- 会話からの直し（`quick_slide_start.py` の直しの口）は、種類を渡す口をまだ持たない（文で頼めば同じことができる）
