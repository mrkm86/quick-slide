# 0001 版は切り替えるだけ（ページの `_pin`）

- 日付: 2026-10-11
- 状態: 採用
- 関係: `docs/EDIT-PLAN.md` の C・html-slide の ADR 0024

## 決めたこと

「版を選ぶ…」→「この版にする」（`POST /api/decks/<id>/adopt`）は、**描き直さずに、その版の成果物を指し直す**。
新しい版はできない。押した瞬間に画面が替わる。

### 印（pin）

- 台本のそのページを**前の版の中身に戻し**、`_pin: "<その版を描いた回の id>"` を書く（`scriptdoc.with_restored`）。
  中身を戻すのは、次に指示で直すときの土台にするため
- `_pin` は `_hidden` と同じ扱い: エンジンに渡す台本から抜く（`engine_view`）・中身の sha256 に入れない
  （`content_sha`）・台本係には見せず、書かせない（書けば NG）
- 印が効くのは、指す回が同じデッキの描き終えた回で、そのページの絵があり、中身が台本のいまの中身と同じときだけ
  （`pins.resolve`）。外れた印は無いものとして扱う（そのページはふつうに描く。複製したデッキの台本に残る印もこれ）
- 印の寿命:

| 操作 | 印 |
|---|---|
| 版の切り替え | その版の回を書く（別の版を選べば上書き） |
| 指示で直す（文字・構成）・分ける | 外れる（直したページは台本係の答えで置き換わり、印は持ち越さない） |
| 絵だけ直す（revise） | 外れる（`without_pins` で明示的に外す） |
| 複製 | 写しは持たない（元は持ったまま） |
| 非表示・並べ替え・差し込み・描き直し（render） | 残る |
| 組み直し（rebuild・設定を替える） | 全部外れる（利用者が頼んだ描き直しなので、新しい版ができてよい） |

### 当て方

- 直しの仕事が待っていない・走っていないときは、**その場で台本に当てる**（`edit_routes.route_adopt` →
  `_apply_now`。段 2 の非表示・並べ替えと同じ道）。答えのページはもう切り替えた姿（`pinned: true`・使用中の版・
  その版の絵）。続けて組み直し（`render` の `reason: tidy`）を 1 つ入れ、発表用の HTML と書き出しを揃える
- 直しの仕事があるときはこれまでどおり仕事にし、ワーカーの `restore` が同じ印を書く

### 画面（`page_view.pages_view`）

- 印のあるページは、印の回のそのページの行（絵）を出し、使用中の版はその回を含む姿。組み直しの後は、新しい回の
  そのページも同じ絵（下の持ち込み）なので、同じ姿にまとまる（版は増えない）
- ページに `pinned`（印が効いているか）と `export_note`（下の「部品の無い版」のときだけ文。ほかは null）を足した

### 描くとき（`pipeline.render_and_import`。組み直し・直し・書き出しのための描き直しのどれでも）

| エンジン | 描く前 | 描いた後 |
|---|---|---|
| image-slide | 印の回の絵（`pictures/<id>.png`）を区画に置き、`deck --keep <そのページ>` で描かせる。ブランドの色・スタイルが変わって描く指示の鍵が合わなくても描き直さず、その絵で PPTX・PDF まで組む（image-slide の ADR 0017） | 何もしない（絵の sha256 は区画の絵で取るので、同じ版にまとまる。ページの画像はいまの帯・番号で組んだもの） |
| html-slide | 生成の枠の絵を印の回の控えから区画へ戻す | ページの画像・絵の控え・発表の区切りの在りかを印の回から持ち込む。書き出しはページごとの部品から組み直す（下） |
| motion-slide | 何もしない（場面のキャッシュで、エンジンが変わっていなければ撮り直さない） | ページの画像を印の回から持ち込む（HTML 1枚は中身から組む） |

持ち込んだページの行は、印の回の行と同じ絵の sha256・同じバイトの画像（資産も同じものを使う）になる。

### 書き出しの部品（html-slide）

- どの回も、描いた後に**ページごとの書き出しの部品**を回のフォルダの `parts/` に残す: `parts/<ページの id>.json` に
  PPTX の部品（エンジンの `deck --parts` の出力を 1 枚ずつに分け、画像は `parts/img/` にハードリンク）と、その回の
  `deck.pdf` の何ページ目か（`render/workspace.snapshot_parts`）
- 印のあるページに部品があれば、組み直しの回の書き出しを部品から組む: 印のページは印の回の部品、ほかはこの回の部品を
  並べ、エンジンの `assemble` で `deck.pptx`（python-pptx）と `deck.pdf`（回ごとの deck.pdf からページを抜いて並べる）を
  書き、回の控えを入れ替える。持ち込んだ部品は新しい回にも残す（次にこの回の版を選んだときの元になる）
- 組めなかったら、エンジンの書き出しのまま（全ページいまの作り）にし、持ち込んだページの部品は残さない
- 発表（`present_view`）: html-slide の各ページに `html`（{url, section}）を足した。印のページは印の回の HTML の区切り
  （回の `pictures/index.json` の `present`）。画面は回ごとに仕切り（iframe）を最初にまとめて開き、ページごとに見せる
  仕切りを替える（`present.js`）。区切りの在りかが分からないページが混ざれば、これまでどおり全部ページの絵で出す
- 発表（モーション）: HTML 1枚は中身から組むので、印の場面も見せる回の HTML 1枚の中にある。見せる回の台本がいまの台本と
  同じなら、全部の場面を見せる回の HTML 1枚で拍ごとに見せる（ページの絵だけが印の回のもの）。組み直す前（見せる回が
  古い）だけ、ページの絵で出す

### 部品の無い版（この仕組みの前の回）

- 画面と発表はその版の絵で出す（発表の HTML の区切りは、その回の deck.html にあれば使う）
- 書き出しだけ、そのページをいまの作りで描いたもの（組み直しの回のエンジンの出力）を使う。ページに
  `export_note`「書き出しでは、今の作りで描き直します」を出す。組み直しの回にも、そのページの部品は残さない
  （絵と食い違うので）

### PDF のページを抜いて並べる道具

pypdf は入れない。html-slide に標準ライブラリだけの `pdfpages.py` を足した（Chrome の印刷の形だけを読む）。
理由と見送った案は html-slide の ADR 0024。

## 理由

- これまでの「戻す」は、その版の中身をいまのエンジンと設定で描き直していた。エンジンが変わっていると絵が変わり、
  版スタックに新しい版ができた（v1 を選んだのに v4 が増えた）。全ページの描き直しなので数秒〜1 分かかった
- 選んだ版の成果物はもう回のフォルダにある。指し直すだけなら待たない

## 見送ったこと

- **DB に印の列を足す**: 移行が要る。印は台本の版に入れれば、版の履歴と一緒に残り、戻せる（`_hidden` と同じ）。
  画面は台本の版のファイルを読むが、版は書き換えないので版ごとに覚える（`pins.ScriptPins`）
- **組み直しでも印を残す**: 組み直しは設定を替えて全体を描き直す頼みなので、印を残すとブランドやスタイルを替えても
  そのページだけ古いままになる
- **image-slide でもページの画像を張り替える**: ページの画像には帯・ページ番号・ロゴを重ねてある。並べ替えで番号が
  変わると古い番号の画像になり、同じ回の PPTX・PDF とも食い違う。絵（区画の絵）を同じにすれば、版は同じにまとまる
- **発表で、回の違うページをページの絵で出す**: 段ごとの再生が消える。回ごとの仕切りで足りる

## 残っていること

- 複製したデッキの台本に残る印は効かない（元のデッキの回を指すため）。直せば消える
