# モーションの台本を場面ごとに書く

## 状態

採用。ADR 0024 の途中経過の保存に続く、台本生成時間の短縮。

## 背景

原稿が大きく、多くの場面に SVG や複数拍の動きがある資料を1回の応答で書くと、最初の台本ができる前に時間切れになる。最初から書き直すため、完成した部分も残らない。

## 判断

モーションの初稿を、共通設計と場面ごとの実装に分ける。プレゼン・ピッチと既存台本への修正は従来どおり。

1. 原稿と既存の台本の決まりから、題・config・見た目の方針、各場面の id・題・拍数・内容を決める。場面数の指定や固定した構成を守る。
   構成係には実装の手引きを渡さず、コードを出させない。主役・額縁・繰り返す造形は寸法・SVGの形・配置の短い記述で固定する。共通設計の段階で全場面の実装を考え込まないよう、出力も小さくする。
2. 全体の原稿と同じ共通設計を各呼び出しへ渡し、対象の場面1つだけの HTML・CSS・JS・talk を書く。共通部の変更や他の場面の参照を許さず、要素 id は場面 id の接頭辞で分ける。
3. 完成順に関係なく設計の順番で結合し、従来の日本語の検査、形の検査、全拍の検査へ進める。途中結果を公開の台本やページにはしない。

場面の並列数は1資料あたり最大8。`worker.parallel` は資料や編集の仕事の同時数で、場面の並列数とは分ける。台本係・下調べ係のCLI全体に共通の上限8を設け、複数資料が同時に書かれても総数を8以下に抑える。待機中も停止の合図を受け、CLIを起こさず中断できる。CLIの実行時間の上限は、枠を得て実行を始めてから数える。この総数はサーバープロセス単位で、別プロセスで起動した検証サーバーとは共有しない。描画エンジン内のCLIの並列は従来どおりエンジンが管理する。各 CLI 呼び出しに既存の `writer_timeout_seconds` を適用する。認証・利用枠・時間切れなどが起きたら未着手の呼び出しは取り消し、実行中の場面の結果は保存してから失敗を返す。サーバの停止合図は全呼び出しへ渡す。

## 保存と再開

保存先は `DataRoot.motion_draft_dir` に集約し、デッキと取り込みごとに分ける。生成方式の版・バックエンド・指示文（原稿、依頼、属性、エンジンの決まりを含む）のハッシュで区切り、共通設計のハッシュでも場面を分ける。原稿や設計の異なる場面を混ぜない。JSON は0600の一時ファイルから置き換え、壊れたファイルは再生成する。指示文そのものの控えは新設しない。

時間切れなどで台本ができなかった依頼は、既存の「生成を再開」で同じ取り込みを使い、保存済みの共通設計と完成場面を読み、足りない場面だけを書く。場面の控えは結合後のエンジン検査に通るまで未検査。検査で場面の id またはページ番号を特定できる場合は、該当場面だけを再生成する。章のレールの題が長い場合は、後続場面にも同じ題が表示されるため、短い表示名だけを別の小さな応答で作り、HTML・動き・話す台本を保持する。ほかのNGが併存すれば、その場面だけを書き直す。共通部や範囲不明の指摘は設計から直し、全場面を再生成する。画面には構成中／保存済み場面数を表示する。

各回の CLI のログは、その run の `writer/round-N/plan/` と `writer/round-N/scenes/<id>/` に残す。途中結果には生成した内容が含まれるため、そのまま公開の報告に貼らない。

## 採らなかった案

- 時間上限だけを延ばす: 書き直しの損失と1応答の大きさは変わらない。
- 全場面を一斉に生成する: 利用枠と同時実行数を抑えられない。
- 原稿を場面別に切り捨てて渡す: 場面間の文脈や、原稿に書かれた造形・動きの希望を失うため、全体を渡す。
- 検査で止まるたび資料全体を書き直す: 問題のない場面まで待ち直しになる。

## 制約

応答回数と入力トークンは増える。共通設計の生成時間は直列で必要。場面間の見た目や内容の一貫性は自動検査だけでは保証できず、実物の目視確認が必要。検査や描画そのものの所要時間は今回短縮しない。
