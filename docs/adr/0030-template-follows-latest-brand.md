# 0030: テンプレートは最新のブランドに追随する

状態: 採用（2026-10-18、#22）。実装は別途。

## 決定

ブランドを親とし、新しい資料の投入時に、その親の最新改訂を選ぶ。
テンプレートが過去の版でも同じ。選択・同一判定・snapshot 保存は投入の同じトランザクション内で行う。
テンプレート保存時の `brand_revision_id` は保存の記録として残し、投入するブランド版の指定には使わない。
色などブランドの範囲はテンプレートに書かない。組み合わせに違和感があれば利用者がテンプレートを直す。

投入時にはブランド設定・資産とテンプレートを snapshot に固める。
完成済み・待機中の資料、直し・差し込み・資料の複製・再開はその控えを使い、最新へ解決し直さない。
新しいブランドを使うには新しい資料として投入する。テンプレートの複製は資料の複製とは異なり、次の投入時に最新の親を選ぶ。

同一判定には投入時のブランド改訂 ID と内容ハッシュを含める。
ブランドだけが更新された場合も次の投入は別になる。保存済みの snapshot・identity・改訂行は書き換えない。

## 理由

ブランドの変更を各テンプレートへ保存し直す操作を不要にする。
一方、受付後の資料は投入時の条件を守り、処理の待ち時間や後日の修正で見た目が変わらないようにする。

## 採らなかった案

- テンプレート保存時のブランド版を使い続ける: 親の更新が新しい資料に反映されない。
- ワーカー開始時や直しのたびに最新へ進む: 待機中・完成済み資料の条件が変わる。
- ブランドの値をテンプレートへ複写する: 親と子で設定が二重化する。

## 検証

ブランドのみの更新前後で新規投入の identity が変わること、同一改訂なら送り直しを再利用することを確認する。
待機・直し・差し込み・複製・再開は古い控えを保持する。保存時ブランド版の履歴と旧 snapshot のハッシュ検証も維持する。
詳細は [変更設計](../design-template-static-resources.md) §2。
