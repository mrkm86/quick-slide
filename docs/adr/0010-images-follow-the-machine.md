# 0010 生成の画像を使うかは機械で決める（「画像を使わない」は作るときだけ）・図解をできるだけ入れる

- 日付: 2026-10-13
- 状態: 採用
- 関係: `docs/adr/0005-pitch-needs-codex.md`・`docs/adr/0008-edit-kinds.md`

## 背景

デッキには、作るときの「画像を使わない」（`deck_attributes.images: false`。会話の `--no-images`）がある。画面には出ず、
作ったあとに見る場所も変える場所も無い。台本係への指示に「画像の枠を使わない」が入るだけで、**直しでも効き続ける**ため、
直しで「画像を入れて」と頼んでも、理由が見えないまま断られていた（同梱の見本は 3 冊ともこの設定）。

一方で、Codex が無い機械で、画像を使う設定（既定）のままプレゼンを作ると、生成の画像の枠を描く段で「Codex にログインできて
いません」と止まり、デッキ全体が失敗していた（2026-10-13 に確かめた）。Claude だけを使う人は、画面からプレゼンを作れなかった。

この設定に意味があるのは、実質「Codex で画像を生成するかどうか」だった。渡された画像を入れるのに Codex は要らない。

## 決めたこと

- **作るとき**: この機械に Codex が無い（ピッチを作り始められない。確かめ方は ADR 0005 と同じ）なら、プレゼンは自動で
  生成の画像なし（`images: false`）で作る。図・形・アイコンで組む（表紙・章扉は図形で飾る）。「絵は入れないで」と言われた
  ときも、これまでどおり同じ扱い
- **直すとき**: 生成の画像を使えるかは、デッキを作ったときの指定ではなく、**頼んだときの機械**で決める（直しの頼みに
  `can_generate` を控え、台本係に渡す描き方の `images` をそれで置き換える）
  - 生成できるとき: 生成の枠を書いてよい。ただし、指示が画像を求めていないページに新しく足さない
  - 生成できないとき: 生成の枠を新しく書かない。渡された画像は `path` で入れてよい
- 「画像」の札は、作ったときの指定に関わらず出す（モーションは除く）。「生成する」は Codex があるときだけ（ADR 0008）
- **図解をできるだけ入れる**: 作るときの台本係への指示に、構造・手順・比較・数字・仕組み・関係は文字の箇条書きにせず図にする
  （プレゼンは図解の型、ピッチは図として描く、モーションは HTML・SVG の図）と書き、表紙・締めを除く半分以上を目安にする
  （`writer/prompt.py` の `DIAGRAM_RULE`）

## 理由

- 利用者が覚えておく設定を増やさない。「画像を使うか」は直すときに札で選べば足りる
- 作るときに止まる失敗は、機械の事情から先に分かる。分かっているなら避けて作る方がよい
- 図解は伝わりやすさに効く（利用者の判断、2026-10-13）。型の目録には図解の型が揃っていて、Codex も要らない

## 却下した案

| 案 | 却下の理由 |
|---|---|
| 「画像を使わない」を設定として見せ、オン・オフを替えられるようにする | 覚える設定が増える。意味は「生成するか」で、機械で決まる |
| 「画像を使わない」デッキには画像の札を出さない | 見えない設定で札が消え、理由が分からない（一度入れて取り消した） |
| Codex が無い機械では、プレゼンを作り始めさせない（ピッチと同じ） | 生成の画像が無くても、図解の型で十分な資料が作れる |

## 残したこと

- Codex がある機械で作り、生成の画像の枠を持つデッキを、Codex の無い機械で描き直すと、これまでどおり描く段で止まる
- 図解を半分以上にする目安が、実際の台本でどう効くかは、本物の台本係で確かめる
