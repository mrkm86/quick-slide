# 0020 バージョンの付け方・リリース・新しいバージョンのお知らせ

- 日付: 2026-10-14
- 状態: 採用
- 関係: `CHANGELOG.md`・`docs/RELEASING.md`・`tools/release.py`・`src/quick_slide/updates.py`・`server/update_routes.py`

## 決めたこと

### バージョン

- **SemVer**（`MAJOR.MINOR.PATCH`。プレリリースは `-rc.1` など）。前のバージョンのデータや設定のまま使えなくなる変更は MAJOR を上げる
- バージョンを書く場所は 3 か所だけ: `src/quick_slide/__init__.py` の `__version__`（正本）と、プラグインのマニフェスト
  `.claude-plugin/plugin.json`・`.codex-plugin/plugin.json`。上げるのは `tools/release.py prepare`。揃っているかは
  `tests/test_version.py` が見る（それまで `__version__` は `2.0.0a2`、マニフェストは `2.0.0` で食い違っていた。`2.0.0` に揃えた）
- タグは `v<バージョン>`。GitHub のリリースの本文は `CHANGELOG.md` のそのバージョンの節（`tools/release.py notes`）

### お知らせの流れ

```
ホームを開く ─→ GET /api/update（このサーバ）─→ GitHub の releases/latest（6 時間覚える）
                    │
                    └─ 新しいバージョンがあれば、ホームの頭に 1 行「Quick Slide X が公開されています」→ 変更点（GitHub）・更新のしかた
```

- **画面は外へ出ない**（CSP の `default-src 'self'`）。問い合わせはサーバがする
- 確かめる先は `https://api.github.com/repos/<公開リポジトリ>/releases/latest`。下書きとプレリリースは入らないので、
  **お知らせが出るのは正式バージョンの GitHub Release を作ったときだけ**
- 答えはサーバのメモリに 6 時間覚える。失敗したら 30 分は問い合わせない（画面を開くたびに叩かない）。
  失敗しても前の答えがあればそれを `stale` で返し、無ければ何も出さない。お知らせのために画面を壊さない
- 送るのは決まった URL への GET 1 つと、User-Agent のバージョンの番号だけ。データの置き場の中身は送らない
- お知らせは**控えめな 1 行**（青い点と小さな文字。枠のある通知の帯にはしない）で、**閉じられない**（更新するまで出し続ける）。
  目立たせないことで、うるさくしない
- 1 行の中: 「変更点」（GitHub のリリースの頁）・「更新のしかた」（設定 › 更新 へ）
- 設定 › 更新: いまのバージョン・最新のバージョン・変更点へのリンク（GitHub）・更新のしかた（会話で頼む／ターミナルのコマンド）・切り替え・「今すぐ確かめる」
- **変更点の本文はアプリに写さない**（GitHub のリリースの頁で読む。画面を軽くし、Markdown を組む部品を持たない）。
  サーバの答えには本文（`notes`）を入れたままにする: 会話の更新で、スキルが変更点を短く伝えるのに使う
- 止める: 設定 › 更新 の切り替え（`settings.json` の `updates.check`）か、環境変数 `QUICK_SLIDE_NO_UPDATE_CHECK=1`
  （環境変数が勝つ。画面は理由を出し分ける）。既定はオン
- 試験は外へ出ない: サーバは `update_fetch` を渡されたときだけ問い合わせる（常駐の `serve` だけが渡す）。
  `tests/run.sh` は環境変数でも止める

### 会話から更新する（「Quick Slide を更新して」）

- スキル quick-slide の `quick_slide_update.py`。引数なしは確かめるだけ（いまのバージョン・最新のバージョン・変更点・何を流すか）、
  `--yes` で更新する。スキルは変更点を見せて**利用者に聞いてから** `--yes` を流す
- どのアプリのプラグインかは、このプラグインが読まれている場所で決める（`<アプリ>/plugins/cache/<マーケットプレイス>/<プラグイン>/<バージョン>/`。
  Claude Code は `CLAUDE_CONFIG_DIR`・既定 `~/.claude`、Codex は `CODEX_HOME`・既定 `~/.codex`）。マーケットプレイスの名前も
  その場所から取る。流すのは Claude Code: `claude plugin marketplace update` → `claude plugin update`、
  Codex: `codex plugin marketplace upgrade` → `codex plugin add`
- 流したあと、置き場に新しいバージョンのフォルダ（`<…>/<プラグイン>/<新しいバージョン>/`）が入ったかを確かめる。入っていなければ「更新した」と言わない
- フォルダから読まれている（開発中の写し・ローカルのマーケットプレイス）ときは何も流さない（git を勝手に動かさない）
- CLI が見つからない・失敗したときは、コマンドを会話に書いて利用者のターミナルで流してもらう。Codex は `~/.codex` に書くので、
  砂場の外で走らせる承認を求める
- 頼まれた確かめなので、設定の切り替えと `QUICK_SLIDE_NO_UPDATE_CHECK` は見ない（それらは自動の確かめだけを止める）

### 古いバージョンのサーバの入れ替え

- 常駐のサーバは止めるまで前のバージョンのまま動く。会話の入口（`quick_slide_start.py` の `ensure_server`。投入・直し・取り込み・
  `--start-server` のすべてが通る）が、**自分より古いバージョン**のサーバを見つけたら、`stop` してから `start` する（新しいバージョンで起動する）
- 入れ替えないとき: 処理中の作業がある（health の `worker.busy`。古いバージョンのまま使い、次の機会に入れ替える）・Codex の砂場の中
  （止めても起こせない）・自分が同じか古いバージョン（Claude Code と Codex に違うバージョンが入っていても、行ったり来たりさせない）
- 起きたことは出力の `server.version_swap`（`{from, to, replaced}`）に出す
- 前に置いていた 設定 › 更新 の「サーバを止める」はやめた（入れ替えが自動になったため）

### 外へのリンク（画面の決まりの例外）

画面は新しいウィンドウを開かず、外のサイトを指さない（DESIGN「ウィンドウは 1 つ」・`tests/test_screen_static.py`）。
例外は GitHub のリリースの頁へのリンク（ホームの 1 行と 設定 › 更新）だけ。**同じウィンドウで開く**（`target` を付けない。
戻るでこの画面に戻れる）。行き先はサーバが公開リポジトリのリリースの頁（`https://github.com/<リポ>/releases/tag/…`）に
限って返す（GitHub の答えの `html_url` がそれ以外なら、タグから組み直す）。

## 却下した案

- **閉じられる通知の帯**（よくある形。閉じたらそのバージョンは出さない）: 最初はそうしたが、閉じると更新を忘れる。
  閉じられない代わりに控えめにした（利用者の判断）
- **変更点の本文をアプリの中に出す**: 最初はそうしたが、リンクで足りる（利用者の判断）。本文を組む部品と、その試験を持たずに済む

- **npm の registry に問い合わせる**（npm で配る道具によくあるやり方）: Quick Slide は npm で配っていない。配り先は GitHub のリポジトリ
- **main の上のバージョンのファイルを読む**（raw.githubusercontent.com）: Release を作らなくても main に入れた時点で知らせが出る。
  手早いが、リリースの区切りと本文が無くなる。「リリースを切った」ことを知らせの合図にしたいので採らない
- **ブラウザから直接 GitHub を読む**: CSP を緩めることになる。サーバ経由なら答えを覚えて、問い合わせの数も抑えられる
- **CalVer**（`YYYY.M.D`）: マニフェストがもう `2.0.0` で、互換が壊れる変更を番号で伝えたい
- **確かめるのを止められないようにする**: 公開すると、利用者のサーバが自動で外へ通信する。止める手段を設定と環境変数の 2 つ用意した
- **答えをディスクに覚える**: サーバは常駐で、再起動は稀。メモリで足りる（置き場を増やさない）

## 残っていること

- 更新のコマンドは、公開した GitHub のマーケットプレイスで確かめていない（手元の Git のフォルダはどちらのアプリも Git の出どころとして
  受けないため、公開前には試せない）。Claude Code のコマンドは `claude plugin --help` と公式の文書に合わせた。
  Codex の `codex plugin add` が新しいバージョンを入れ直すかは、公開してから確かめる
- デスクトップアプリ（Claude の Code タブ・Codex のアプリ）の会話から `claude`・`codex` の CLI が見えるかは、文書に無い。
  見えなければ `manual` でターミナルのコマンドを渡す
