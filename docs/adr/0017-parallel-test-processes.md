# テストを別プロセスで並列実行する

## 判断

サーバ・画面の `tests/run.sh` は unittest の discovery で全件を発見し、モジュールごとに別プロセスで実行する。既定は 4 並列。`-j 1` で直列、`-j N` で並列数を指定する。`-v` と `-k` も使える。

各プロセスの一時領域、エンジンのキャッシュ、Codex の隔離ホームを分ける。発見した件数と子がロードした件数が一致しなければ失敗にする。クラス全体の skip は unittest の扱いを保つ（testsRun には入らない）。失敗したプロセスの出力を表示し、ほかのモジュールも最後まで実行する。

テストケース内の順序や並列動作、Chrome の起動方法、固定待ちは変えない。エンジン単体の run.sh は今回の対象に含めない。

## 理由と却下した案

同じプロセスのスレッドでテストを並列実行すると、環境変数やモックが干渉するため採らない。ケースごとの別プロセスは import と起動の負担が増えるため、モジュール単位にする。全件の実測で 2 並列は約 484 秒、4 並列は約 292 秒となり、失敗はなく既存の skip も同じだったため、既定は 4 並列にする（4 並列の測定ではランナーの検証 3 件も加わった）。

テストの省略やブラウザ試験の置き換えは行わず、検証範囲を保つ。
