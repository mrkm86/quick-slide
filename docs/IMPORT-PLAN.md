# 既存の PPTX を取り込む計画

2026-10-13 作成。状態: 作っている（「聞きたいこと」は 4 つとも利用者と決めた・2026-10-13）。

## ねらい

- 手元の PPTX を Quick Slide のプレゼン（html-slide）のデッキにする。画像・色・配置はできるだけそのまま写す
- アニメーションは、HTML の決まり（`skills/html-slide/references/contract.md`）と発表の画面で出せる範囲に写す。出せないものは写さず、何を落としたかを取り込みの報告に残す
- 入口は3つ: 画面（ホームで形式「プレゼン」を選んでいるときだけ出る「PPTX を取り込む」ボタン）・会話の CLI（`quick_slide_start.py --import`）・エンジン単体（`html_slide.py import`）
  - **画面と会話の CLI は、どちらもサーバの口 `POST /api/imports` を通す**（デッキ・版・描いた回を台帳に残すため）。エンジン単体の `import` は、スキルだけで使うとき（サーバなしで PPTX → 台本 → `deck`）の口

## 決めること（案）

### 1. 取り込んだページの持ち方: 決まりに沿った HTML をそのまま持つ新しい型 `html`

台本のページに `{"type": "html", "html": "<section data-slide …>…</section>", "imported": {...}}` を置く。中身は絶対配置の HTML で、
画像は持ち込みの画像（`path`）として置く。エンジンはこの型を組まずに通し、あとはいまの道（check → 描き出し → PPTX・PDF・ページの画像、発表の画面の段の再生）に乗る。

- 採る理由: 位置・色・画像をそのまま持てる。PPTX は今の描き出し係（`extract.mjs` → `pptx_writer.py`）で書けるので、文字も図形も編集できるまま。発表の画面も今の再生の部品で動く
- 却下: **型（29種）に起こし直す**（LLM で中身を読んで当てはめる）。見た目が Quick Slide のものに変わり、「忠実に」に合わない。後で「このページを型で組み直す」直しとして使う（下の 6.）
- 却下: **ページを画像に焼く**（LibreOffice で PNG）。見た目は一番近いが、文字を直せず、アニメーションも無くなる。LibreOffice を配る機体に要求することになる。写せない部品だけを画像にする逃げ道としては残す（下の 3.）
- 台本の中に HTML を入れる（ファイルを分けない）のは、モーションの場面と同じ形にして、台本の版・複製・戻すの仕組みをそのまま使うため

### 2. 変換はエンジン（html-slide）の入口 `import`

`html_slide.py import --pptx <file> --out <フォルダ>` → `<フォルダ>/script.json`（`html` 型のページの台本）・`images/`・`theme.yaml`（PPTX のテーマの色と字体）・`import-report.json`（写せなかったもの）。

- エンジンは状態を持たない・ほかのスキルを呼ばない、の決まりのまま（ファイルで受けてファイルで返す）
- 依存は今の4つ（python-pptx・lxml・Pillow・PyYAML）だけで読む。新しいパッケージは足さない
- 1枚は 1920×1080 の座標に写す（EMU → px は 1px = 6350 EMU。16:9 の 13.333in ならそのまま）
- **16:9 でないデッキ（4:3・A4 など）は、高さ（か幅）を 1080（か 1920）に合わせて中央に置き、余った左右（か上下）を背景で埋める**（利用者と決めた・2026-10-13。違和感が無いことを優先）。
  出力の PPTX も 16:9 になる。埋め方は、余りに見えないように:
  - 単色の背景 → 同じ色を section 全体に
  - グラデーションの背景 → 同じ向き・同じ色で section 全体に広げる
  - 画像の背景 → 16:9 を覆う大きさに広げて置く（上下か左右が少し切れる）。中身はもとの位置のまま中央に
  - マスターの飾りが端に付いている（帯・線など）ときは、端に付いた飾りだけ幅を余りまで伸ばすかを I1 の見比べで決める（はじめは伸ばさない）

### 3. 写すもの（対応表）

| PPTX | 写し方 |
|---|---|
| 背景（単色・グラデーション・画像） | section の背景色。画像の背景は、一番奥に全面の `img` を置く（決まりは `background-image` を止めているため） |
| マスター・レイアウト | 継承をたどって解く（プレースホルダーの位置・字の大きさ・色、`showMasterSp`）。マスターの飾り図形もページごとに描く（出力の PPTX ではマスターの構造は無くなり、各ページの図形になる） |
| 色 | テーマの色（`schemeClr`・`clrMap`）と `lumMod`・`lumOff`・`tint`・`shade`・`alpha` を計算して RGB に |
| 図形 | よく使う形（四角・角丸・楕円・線・矢印・三角・五角形・山形（矢羽根）・吹き出しなど 30 前後）は SVG の path に。ほかの形は、自由な形（`custGeom`）と同じく path に起こせなければ四角で代え、報告に出す |
| 塗り・線 | 単色・透明度・線の太さ・破線。グラデーションは2色まで（3色以上は近い2色に寄せて報告） |
| 文字 | テキストボックスの余白・上下の寄せ・折り返し・自動調整（`normAutofit` の縮小率）・箇条書きの記号と番号・段落の字下げ・行間・段落の前後・字間・太字・斜体・下線・色・字体 |
| 字体 | 字体の名前は PPTX にそのまま書く。画面と PDF では、その字体がこの機械に無ければ近い日本語の字体で描く（改行の位置は PowerPoint と違いうる） |
| 画像 | 切り抜き（`srcRect`）・透明度・グレースケール。形で切り抜いた写真は、丸と角丸だけ写す。SVG の画像は PPTX に入っている PNG の控えを使う |
| グループ | 子の座標を解いて、グループのまま1つの単位にする |
| 表 | セルの塗り・文字・セルの結合。罫線はセルごとに線で描く |
| グラフ | 中に控えてある数値から、棒・折れ線・円を SVG で描く（グラフの部品としての編集はできなくなる）。ほかのグラフは PPTX の控えの画像か、無ければ空の枠で報告 |
| SmartArt | 描いた結果（`dsp:drawing`）の図形を写す |
| 回転・反転 | 図形は path の点を回して写す。文字は今の部品の `rot` を使う。画像の回転は決まりを広げる（下の 4.） |
| ノート | `<aside class="notes">` |
| 動画・音 | 表紙の画像（ポスター）だけ置き、報告に出す |
| EMF・WMF・縦書き・数式・OLE | 控えの画像があればそれを置く。無ければ空の枠で報告 |

### 4. 決まり（contract.md）の広げ方（エンジンの ADR を書く）

- **取り込んだページだけ、止める検査を一部ゆるめる**: 文字のはみ出し（字体の違いで起きる）・スライドの外へのはみ出し（PPTX では外にはみ出した飾りがよくある）・ノートの［クリック］の数（PPTX のノートに［クリック］は無い）を、rc=2 ではなく警告にする
- **画像の回転**（`transform: rotate()` だけ）を通し、PPTX の `rot` に書く。それ以外の `transform` は今までどおり止める
- 段落ごとのアニメーションのために、1つのテキストボックスを段落ごとの要素に分けて書く（決まりは変えない）

### 5. アニメーション

| PPTX | 写し方 |
|---|---|
| 開始の効果: 表示・フェード | `fade` |
| ワイプ | `wipe-right` などの向き |
| スライドイン・フライイン・浮き上がり | `rise` |
| ズーム・拡大 | `pop` |
| ホイール | `wheel` |
| その他の開始の効果 | `fade` で代え、報告 |
| クリック時 / 直前の動作と同時 / 直前の動作の後 | 新しい段 / 同じ段の `data-delay` 0 / 同じ段で前の長さぶんの `data-delay`。最初の効果が「同時」「後」なら段 0（画面に入ったら出る） |
| 段落ごと（`bldP`） | 段落ごとに段を付ける |
| 強調・軌跡 | 写さない（報告） |
| 終了の効果（クリックで部品が消える） | 写さない。その部品は出たままにし、あとから出る部品と重なるページを報告に出す（利用者と決めた・2026-10-13） |
| 画面の切り替え | `fade` か `none`。ほかの切り替え（モーフを含む）は `fade` にする（html-slide の ADR 0023） |
| 自動で進む時間 | 写さない |

### 6. 取り込んだあと

- **投入**: `POST /api/imports`（本文は PPTX のバイト列そのまま）。今の本文の上限（16 MiB）では足りないので、この口だけ上限を別にして、ディスクへ流して受ける（案: 200 MiB）。
  答えは `POST /api/intakes` と同じ形（`deck_id`・`url`・`deck_url`）。仕事は「台本係」の代わりに「取り込み」（エンジンの `import` → check → 描き係）。
  元の PPTX は、取り込みが失敗したときの取り直し用に、デッキの資産として中に残す（画面には出さず、書き出しにもしない）
- **直す**: 文字を直す（台本係が `html` 型の HTML の文字だけを書き換える。位置は動かさない）・画像を差し替える（`img` の差し替え）。図解にする直しは「型で組み直す」になり、見た目が Quick Slide の型に変わることを画面で言う
- **ページを足す**: 型のページで足す。色と字体は取り込んだ PPTX のテーマ（`theme.yaml`）で組むので、元のページと並べても浮かない
- **ブランド**: 取り込んだデッキには既定でロゴ・フッタを足さない（元の PPTX にもう入っている）。透かしとページ番号は今までどおり選べる
- **書き出し**: 描いた回の PPTX・PDF だけを配る（いまの道）。元の PPTX は書き出しに出さない（利用者と決めた・2026-10-13）
- **発表の画面**: 今の html-slide の部品で、段ごとに再生する

### 7. 画面（ホーム）

- 作成の欄の形式で**「プレゼン」を選んでいるときだけ**、「作成」ボタンの横に「PPTX を取り込む」ボタンを出す。ピッチ・モーションに切り替えたら隠す（取り込みはプレゼンにしかならないため）
- ボタンを押すとファイルを選ぶ窓（`.pptx` だけ）。作成の欄へのドラッグ&ドロップも、プレゼンを選んでいるときだけ受ける
- 選んだら、依頼の文は使わずに `POST /api/imports` へ送り、デッキの画面へ移る（進みはそちらで「取り込んでいます」と出す）。ブランドの選びは出さない（6. のとおりロゴを足さないため）
- 出すかどうかはサーバの語彙で決める（形式ごとに「取り込める」を `deck_kinds` に持たせる）。画面に「プレゼンなら」と書き込まない

### 8. 安全

PPTX は外から来たファイルとして扱う: zip の展開の大きさと数の上限・rels の行き先がパッケージの外に出ないか・外部の画像（`TargetMode="External"`）は取りに行かない・XML の実体参照を解かない（lxml の `resolve_entities=False`・`no_network`）・マクロ（.pptm）と OLE の中身は読まない。
抜き出した文字には、原稿と同じ秘密らしい文字列の検査をかける（直すときに台本係の LLM に見せるため）。

試験は、python-pptx でその場で作った PPTX（図形・文字・画像・アニメーションを1つずつ）で走らせる。
集めた実物のデッキはリポジトリに入れない（配る物なので）。見比べはリポジトリの外の作業場（`../quick-slide-v2-scratch/` など）で行う。

## 試すデッキに入っていてほしいもの

- 会社・テンプレートのマスターを使ったもの（背景画像・ロゴ・飾り図形がマスターにある）
- 写真が多いもの（切り抜き・丸く切り抜いた写真・透過 PNG・SVG のアイコン）
- 表とグラフ（棒・折れ線・円）が入ったもの
- SmartArt・矢羽根・図形を組み合わせた図解
- 箇条書きを段落ごとに出すアニメーション・「直前の動作の後」でつないだアニメーション・終了の効果
- 4:3 のデッキ（左右の埋め方を見比べる）
- 日本語の字体（游ゴシック・メイリオ・BIZ UD など）と英語の字体が混ざったもの
- それぞれ、PowerPoint（か Keynote）で書き出した PDF も一緒に（見比べる元にする）
