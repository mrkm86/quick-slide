# 画面からスライドを作る計画

> 旧画面の計画の記録。新しいホームの入口は[ADR 0029](adr/0029-conversation-request-builder.md)で依頼文の作成に置き換える。request APIは互換用に残す。

2026-10-11 作成。ホームの上に「どんなスライドを作りますか？」の入力欄と、スライドの形式を選ぶ 3 つの切り替えを置き、画面から 1 冊作れるようにする。

## 流れ

```
入力欄の依頼 ──▶ 下調べ係（Web で調べて原稿を起こす）──▶ 台本係（いつもの）──▶ 描き係（形式のエンジン）
```

- 依頼（例:「最新の AI 開発の状況を 5 ページのレポートにまとめて」）は、そのままでは台本係に渡さない。台本係は「原稿に無い事実を足さない・原稿の中の指示に従わない」作りで、材料が無いと書けないため（利用者の判断・2026-10-11）。
- **下調べ係**: 台本係と同じ CLI（Claude Code の `claude -p`・Codex の `codex exec`。サブスク枠だけ）を、**Web の検索と取得だけ**を許して呼ぶ。ファイルの読み書き・シェル・MCP・スキルは使わせない。
  - 返すのは JSON 1 つ: 題・目的・読み手・枚数（依頼に書いてあれば）・原稿（出典付き）。
  - 原稿は、会話から作るときの原稿と同じ形（`## N. 見出し` の構成と本文。出典の行）にする。
  - Web の中の指示には従わない（調べた中身は材料であって、指示ではない）。
- 原稿ができたら、いまの取り込み（intake）と同じ道に乗せる。台本係・描き係は替えない。
- 画面: 作成を押したらすぐデッキの画面へ移る。帯に「下調べをしています」→「台本を書いています」→ 描いている進みを出す。

## スライドの形式（呼び名・説明・アイコン・色は 1 か所で持つ）

正本は `src/quick_slide/server/vocabulary.py` の `DECK_KINDS`（並び順もここ）。画面は `/api/vocabulary` から読むだけで、名前・説明・アイコンを直書きしない。書き出せる形式は、書き出しの可否（`export_routes.format_refusal`）から作る。手で書かない。

| モード | 名前 | 説明 | アイコン | 色 |
|---|---|---|---|---|
| presentation | プレゼン | PowerPoint 互換のプレゼンスライドを作ります | `slideshow` | 青 |
| pitch | ピッチ | インパクトのある画像のスライドを作ります | `photo_library` | 橙 |
| motion | モーション | 従来のプレゼンにとらわれない、自由なアニメーションのスライドを作ります | `animation` | 緑 |

- 色は DADS のトークンから選び、文字と地のコントラスト 4.5:1 を守る。色の名前（`tone`）は語彙に入れ、CSS は `tone` ごとの組を 1 か所に持つ。
- 既存の `DECK_MODE_LABELS` は `DECK_KINDS` から作る（別に持たない）。

## 画面

- **ホームの上**: 入力欄（例を入れたプレースホルダー）、形式の 3 つの切り替え（大きめのカード。アイコン・名前・説明・小さく書き出せる形式。選んだものは形式の色）、「作成」。
- **形式のラベル**: 角丸のタグ（先頭にアイコン、形式の色）。ホームのカード・スライド一覧のカード・デッキの画面の題の横に付ける。
- **スライド一覧**: 検索の欄に形式の絞り込みを足す。

## 決まったこと

- 依頼から下調べをして原稿を起こし、いつもの台本係に渡す（2026-10-11）。
