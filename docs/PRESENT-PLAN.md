# 発表の画面（見せる用）の計画

2026-10-11 作成。Quick Slide の機能として、デッキを見せるための画面を足す。エンジンの機能ではない。

## 決まったこと

- URL は分ける: `/slides/<デッキの ID>/present`。何ページ目から始めるかは `?p=<番号>`。
  - 名前を `/presentation` にしないのは、デッキの種類の「プレゼン（presentation）／ピッチ」と混ざらないため。
- 対象は html-slide・image-slide・motion-slide。今回作るのは html-slide と image-slide。motion-slide は計画だけ（下の段4）。
- 見せる用の画面だけを作る。発表者用の表示（手元に次のページ・ノート）、Keynote のような機能、話す台本の表示は作らない。

## 発表の画面（3エンジン共通の外枠）

- 黒い地に 16:9 のスライドを画面いっぱいに収める。余りは上下か左右の帯。
- 進む: クリック（画面の右側）・→・スペース・Enter・PageDown・スマホの左スワイプ。
- 戻る: 画面の左側のクリック・←・PageUp・右スワイプ。
- Home・End で最初と最後。O か一覧ボタンでページの一覧を出し、そこへ飛ぶ。F で全画面。Esc で編集の画面へ戻る（一覧を開いているときは一覧を閉じる）。
- 下に進み具合（3 / 13）。しばらく触らなければ操作の表示とマウスの矢印を隠す。
- スマホ:
  - 横向きは全画面。縦向きはスライドを幅いっぱいにし、下に操作。
  - タップとスワイプで進む。画面を消さない（Wake Lock。使えなければ何もしない）。
- 編集の画面からの入口: 上の帯に「発表」ボタン、各ページの ⋮ に「ここから発表」。
- 非表示のページは飛ばす。見せる版は、編集の画面でいま見せている版。
- アクセシビリティ:
  - 操作のボタンにはラベルを付ける。
  - いまのページを読み上げに知らせる。
  - 動きを減らす設定（prefers-reduced-motion）では効果を省く。

## エンジンごとの中身（差し替えられる作り）

外枠は「ページの数・いまのページ・次へ・前へ・そのページの段の数」だけを知る。中身はエンジンごとの部品が受け持つ。

- **image-slide**: 見せる版のページの PNG を順に出す。段は無い（1ページ1段）。
- **html-slide**:
  - deck.html を仕切りの中（`sandbox="allow-scripts"` の iframe。`allow-same-origin` は付けない）で開く。Quick Slide 側の再生スクリプトを入れ、段（`data-step`）ごとに要素を出す。
  - 効果（`data-fx`: rise・fade・pop・wipe・wheel）・遅れ（`data-delay`）・ページの切り替え（`data-transition`）・画面をまたいで残すもの（`data-keep`）は、`skills/html-slide/references/contract.md` の決まりを CSS で再現する。
  - 回ごとに deck.html と画像を残す（いまは作業フォルダに最新の1つだけ）。版を戻しても、見せている版の HTML を出せるようにする。
  - 字体は、手元のファイルのパス（file://）からサーバの配信のパスに書き換えて配る。
  - 仕切りの中の文書には、ページの中のスタイルを許す安全設定を付ける。Quick Slide の API・セッションには触れない。
  - 回の HTML が無い古い回は、ページの PNG で代わりに出す（image-slide と同じ）。
- **motion-slide**（段4・今回は計画だけ）: 自前の再生エンジンを持つ HTML 1枚を、仕切りの中でそのまま動かす。外枠の進む・戻る・一覧とは postMessage でつなぐ。

## エンジンごとの動きの決まり（利用者の方針・2026-10-11）

- **html-slide**: HTML で表現できない動き（PPTX の変形 morph など）は、最初からスライドに使わない。PPTX と発表の画面で同じに出せる効果と切り替えだけを使う（html-slide の ADR 0023）。
- **motion-slide**: PPTX にすることはほぼ考えない。分かりやすさを優先し、HTML の表現（スクリプト・CSS の動き・その場で触れる部品・音）を全部使ってよい。発表の画面は motion-slide の HTML をそのまま動かし、外枠は進む・戻る・一覧の合図をつなぐだけにする。
- **image-slide**: ページ送りだけ。

## 段4: motion-slide（作った・2026-10-11）

**仮の扱い**: デッキの種類（モード）として「モーション（motion）」を足した（作るときに選ぶ。あとから替えない）。種類ごとの違いは `engines.py` の `Engine` と `motion.py` に閉じ込めてあり、**デッキの種類の持ち方（1 つのデッキに 3 種を持つ等）は午後に利用者と決める**。論点: ①1 デッキ内でページ（場面）ごとに種類を変えられるか ②台本の持ち方（今は `slides` に場面を入れ、エンジンに渡すときだけ `scenes`）③書き出しの形（今は種類ごとに PPTX・PDF か HTML 1枚）④スタイル・ブランドの効き方（motion はテーマとロゴだけ）。

作ったもの: 発表の部品 `motionAdapter`（`web/app/present.js`）・橋渡し `web/app/present-motion-frame.js`・配信 `/present/<デッキ>/<回>/index.html`（CSP は `present_routes.motion_csp`）。外枠のページ＝場面・段＝拍。外枠の面は重ねず、中がタップ・スワイプ・キーを受ける（二重に進まない）。一覧・全画面・Esc・End は外枠のもの（中の一覧は出さない）。以下は作る前の計画（記録）。


1. **Quick Slide のエンジンとしてつなぐ**: 置き場を `skills/motion-slide` に移し、Quick Slide の「エンジン」の一覧に足す。台本係に motion-slide の台本（場面×拍の HTML）の決まりを渡し、描き係に `build.py`・`check.py` を呼ばせる。モードとスタイルの扱い、画像の枠の扱いも決める。
2. **回ごとの保存**: 出力の `index.html`（1枚に全部入り）と、一覧の絵を回のフォルダに残す。ページの PNG は `check.py` の場面ごとの絵から作る。
3. **発表の画面の部品**: 仕切りの中で `index.html` を開く。motion-slide の `MS.state`（場面・拍）を postMessage で外枠に渡し、外枠の進む・戻る・一覧の合図を中へ送る。キー操作は、仕切りの中が受けたら外枠では受けない（二重に進まない）。
4. **安全設定**: motion-slide は中にスクリプトを持つので、仕切りの中は `allow-scripts` だけにして、外へは何も取りに行かせない（motion-slide は「外へ何も取りに行かない HTML 1枚」なので、そのままで合う）。効果音・BGM は、利用者の最初の操作の後だけ鳴らす。
5. **編集の画面**: 場面を1ページとして並べる。直すのは場面ごと。

### motion の限界（場面の複製・2026-10-11）

複製の id の付け替えは、よくある書き方（id を受け取る API の引数・セレクターの API の引数・HTML の参照属性・CSS）を対象にした付け替えで、文字列をつないで id を作る書き方などは追わない。付け替えた後はエンジンの check が id の重なりを止める（場面の複製は台本係を呼ばないので、止まったときは複製した場面を直す指示で直す）。実装は `src/quick_slide/motion.py` の `duplicate_scene`。

## 読み込みを軽くする（2026-10-14）

写真の多い取り込んだデッキ（116 枚）で、開いてから最初のページが出るまで待たされた。中の文書が全ページの画像（128 MB）を最初にまとめて読み、
しかも開くたびに読み直していた。

- **同じ画像は 1 つ**: html-slide の取り込んだページの画像の名前を、ページの番号を入れずにファイルのパスで決める（全ページのロゴが 95 個 → 1 個。128 MB → 42 MB）
- **見るページから読む**: サーバが中の文書の `<img src>` を `data-qs-src` に移して配り（`present_routes.frame_document`）、再生スクリプトが
  出すページと前後（先 2・後 1）の画像をすぐ読む。残りは読み終えたあとに 1 ページずつ後ろで読む（めくるときに待たない）
- **回の控えは覚えさせる**: `/present/<デッキ>/<回>/` の画像と字体は `Cache-Control: private, max-age=604800, immutable`（回の id ごとの置き場で、
  描き終えたら変わらない）。中の文書（deck.html）と API はこれまでどおり `no-store`
- 実測（mac01・116 枚）: 開いてから最初のページが出るまで約 0.5 秒
