# 修正の画面とページの操作の計画

2026-10-11 作成。次の 3 つを一緒に直す。

- **A. 待たせない**: ページを隠す・並べ替える・版を戻すと、待ち時間が長い（モーションで約 1 分）。描き直さなくてよい操作では描き直さない。
- **B. 修正の画面**: 「直す」を押したときだけ修正の欄を出す。どのデッキのどのページを直しているかを分かりやすくする。版と記録は各ページのメニューにしまう。
- **C. 版は切り替えるだけ**: 前の版を選んでも、新しい版を作らない。数秒以内に切り替える。

## いまの作りと、困っていること

### 遅い理由

- どの直し（非表示・並べ替え・複製・版の戻し・指示での直し）も、`create_edit` で「回」を 1 つ作る。その回でエンジンがデッキ全体を描き直す（`worker/edit.py` → `pipeline.render_and_import`）。
- 通り道が 1 本で済み、どの回も完全な一式（ページの PNG・発表用の HTML・書き出し）になる。その代わり、1 ページ隠すだけでも全ページ分の仕事が走る。

実測（この機体の DB・2026-10-11）:

| エンジン | 操作 | 時間 |
|---|---|---|
| html-slide | 版の戻し（14回） | 平均 4.7 秒 |
| html-slide | 組み直し（29回） | 平均 7.2 秒 |
| motion-slide | 非表示 | 56 秒 |
| motion-slide | 組み直し | 65 秒 |
| image-slide | 記録なし | 未計測 |

- html-slide は、挿絵をキャッシュから使う。それでも全ページの HTML を組み直し、Chrome で 1 枚ずつ PNG に撮っている。
- motion-slide はキャッシュが無い。全場面の全拍（このデッキで約 20 枚）を撮り直し、拍ごとに 1.8 秒待つ（`--wait` の既定 1800ms）。

### 版を戻すと新しい版ができる理由

デッキ 5ef7fd91 の 2 ページ目の記録:

| 回 | 操作 | 中身 | 絵（PNG） | 版 |
|---|---|---|---|---|
| 1 | 最初 | 元の中身 | dfd2… | v1 |
| 2 | 指示で直す | 直した中身 | 8101… | v2 |
| 9 | 組み直し（DADS の後） | 直した中身 | 1315… | v3 |
| 13・18 | v1 に戻す | 元の中身 | **f4a1…** | **v4（新しくできた）** |

- 版を戻すと、その版の**中身**を、**いまのエンジンと設定で描き直している**。
- v1 は DADS の前のエンジンで描いた絵なので、描き直すと見た目が変わり（dfd2 → f4a1）、別の版として数えられる。
- 利用者から見ると、「v1 に戻したのに v1 の絵にならず、v4 が増えた」になる。

### 修正の画面

- PC は右のパネルがいつも出ている。タブ（このページ・デッキ全体）・直す欄・ページの版・記録が並ぶ。
- スマホは、下から出る板に同じものが全部入る。どのスライドを直しているかが見えない。

## 方針

1. **描かない直し**: 非表示と並べ替えは、台本の版を 1 つ進めるだけにする。回は作らず、エンジンも呼ばない。
2. **版の切り替えは、持っている絵を指し直すだけ**: 版ごとの成果物（ページの PNG・発表用の区切り・書き出しの部品）を残しておく。切り替えたら、そのページはその版の成果物を使う。描き直さないので、新しい版はできない。
3. **画面はその場で替える**: 押した瞬間に替え、サーバの返事を待たない。失敗したら元に戻し、理由を出す。
4. **組み立ては後で**: 発表と書き出しは、いまの台本と、各ページが指している版の成果物から組む。組み直しが要るときだけ、そのときに組む。
5. **修正の欄は、直すときだけ出す**: 普段はスライドの列だけにする。「直す」を押したら、PC は右に、スマホは下半分に出す。中身は「対象・テキストの欄・画像・送信」だけにする。
6. **撮った絵を使い回す**: motion-slide にも場面ごとのキャッシュを入れる。変わった場面だけを撮る。

## B. 修正の画面

### 普段

- 修正の欄は出さない。PC は左のサムネの列とスライドの列だけ。スライドの列は余った幅を使う。
- 右のパネルの開閉を覚える仕組み（`localStorage` の `qs-deck-panel`）はやめる。いつも閉じた状態で開く。

### 「直す」を押したとき

> 2026-10-13 追記: 欄の上に「何を直しますか？」（文字・図解・挿絵・画像）を足した。モードでできるものだけを出し、文字以外は書かなくても送れる（`docs/adr/0008-edit-kinds.md`）。
> 同日: 1 ページの直しは、**送っても欄を閉じない**（答えは欄の中の 1 行）。見出しの ‹ ›・Alt+←→・スマホは絵の左右スワイプで前後のページへ送れ、元のスライドの強調とサムネの印もついてくる。送ったあとに自動で次へは進まない（利用者の選択）。選んだページ・デッキ全体は、これまでどおり送ったら閉じる。
> 2026-10-14: 直したページの見出しの横に版の札（v2・v3…）を出す（v1 は出さない）。直し終えて版が上がったら「更新」と添えて主役の色で目立たせ、次にそのページを直すまで残す。修正の欄の見出しにも（v2）と出す。
> 同日: 「作り直す」は「＋」のメニューと札をやめ、「今の絵をもとに直す」の切り替え（オン・オフ）にした。土台にできる絵が無いページでは切り替えも理由の文も出さない。「＋」は画像を添えるだけ。

対象は「1 ページ」「選んだページ（チェックで選ぶ）」「デッキ全体」の 3 つ。どれも同じ欄を使い、見出しだけが変わる。

- **見出し**: デッキの名前（小さく）と、対象（「3 / 12 ページ　ゴールまでの道筋」「2・5・7 ページ」「デッキ全体（12 ページ）」）。
- **対象の絵**: 1 ページのときはそのページの絵。選んだページのときは小さな絵を並べる。
- **入力の 1 行**（チャットの入力欄と同じ並び）: 左に「＋」、真ん中にテキストの欄、右に送信。欄の高さを抑える（1〜2 行で始まり、書くと 6 行まで伸びる）。
  - 「＋」のメニュー: 「画像を添える」と「今の絵を使わずに作り直す」（オン・オフ）。オンのときは欄の上に「作り直す」の札を出す。絵の無いページでは、いまと同じく固定して理由を添える。
  - 画像は欄への貼り付け・ドラッグ&ドロップでも添えられる（いまと同じ）。添えた画像は欄の上に小さな札で出す。
- **出さないもの**: タブ、ページの版、記録、見比べ。
- **対象のスライド**: 列の中で枠を付けて強調し、見える位置に送る（PC）。

### 複数ページをまとめて直すとき

**選ぶ**:
- 各ページの題の左のチェックで選ぶ。選んだページは、スライドに枠を付ける（PC・スマホとも）。
- 選ぶと上に帯が出る:「3 ページを選んでいます　[直す]　[選ぶのをやめる]」。

**欄**（1 ページのときと同じ欄。上半分だけが変わる）:
- 見出し:「2・5・7 ページ（3 ページ）」。
- PC: 選んだページの絵を縦に並べる（多ければ欄の中でスクロール）。
- スマホ: 上半分に、選んだページの絵を横にめくれる形で出す（「1 / 3」の印付き）。
- テキストの欄は 1 つ。書いた指示は、選んだページ全部への 1 つの指示になる。

```
┌──────────────────────────────┐
│ まとめて直す                × │
│ 経営会議の報告                │
│ 2・5・7 ページ（3 ページ）     │
│ ┌──────────────────────────┐ │
│ │                          │ │
│ │  （2 ページの絵）  ← めくる │ │
│ │                          │ │
│ └──────────────────────────┘ │
│          ● ○ ○  1 / 3         │
│ ┌─┐┌──────────────────┐┌──┐ │
│ │＋││3 ページ全部に効く指示││送信│ │
│ └─┘└──────────────────┘└──┘ │
└──────────────────────────────┘
```

**どう反映されるか**（サーバの動きはいまのまま。`worker/edit.py` の `_revise`）:
- 1 つの仕事として台本係に渡す。台本係はページごとに、文字と構成を直す・絵だけ直す・両方・**変えない** のどれかを選ぶ。1 ページを 2 ページに分けることもある。
- 全部まとめて当てるか、何も当てないか（途中までは当てない）。台本係の答えが検査に通らなければ、決められた回数やり直し、それでも通らなければ失敗にして、ページは前のまま。
- 送信したら選択を外して欄を閉じる。選んだページの枠に「生成中」が出る。描き終わると、選んだページの絵が**同時に**替わる。
- 終わったら 1 行で知らせる:「3 ページのうち 2 ページを直しました（7 ページは変えていません）」。直したページには短く印を付ける（並べ替えたときの強調と同じ）。分けて増えたページも同じ印。
- 選んでいないページへの提案があれば、当てずに知らせる（いまと同じ:「ほかのページへの提案（当てていません）」）。
- 版はページごとに 1 つずつ増える。戻すときは、ページごとに「版を選ぶ…」で戻す。

- **版を選ぶ…**: ダイアログを開く。版の小さな絵を並べ（v1・v2 …・「使用中」の印・作った日時・直したときの指示の頭）、押すと大きな絵で見られる。PC は、いまの版と並べて見比べる（いまの「見比べ」をここに移す）。「この版にする」で切り替えて閉じる。版が 1 つしか無いページでは、押せないようにして理由を出す。
- **このページの記録…**: ダイアログ（スマホは下からの板）で、いまパネルにある記録を出す。

## C. 版は切り替えるだけ

- 「この版にする」で、そのページが指す版を替える。台本も、その版の中身に戻す（次に指示で直すとき、その中身が土台になるように）。
- 描き直さない。回は作らない。新しい版はできない。版の番号は、いまの数え方（中身と絵の組で 1 つ）のまま。
- 画面は押した瞬間にその版の絵に替わる（もう持っている絵なので待たない）。
- **版ごとに残すもの**（回のフォルダに、ページごとに）:

| エンジン | 画面の絵 | 発表 | 書き出し |
|---|---|---|---|
| html-slide | ページの PNG（いまもある） | 回の `deck.html` と区切りの番号（いまもある） | PPTX の部品 JSON（`extract.mjs` の出力。いまは残していない）・1 ページずつの PDF（`deck.pdf` を分けて残す） |
| image-slide | ページの PNG（いまもある） | PNG | PNG（PPTX・PDF は PNG を並べる） |
| motion-slide | 場面の絵（いまもある） | 場面の中身（台本） | HTML 1 枚に組み直す（撮らない。A の段 2） |

- **発表**: html-slide は、ページごとに「どの回の `deck.html` の何番目の区切りか」を持つ。違う回のページが混ざったら、ページを替えるときに読み込む HTML を替える（いまの外枠に、ページごとの HTML の在りかを足す）。
- **書き出し**: html-slide の PPTX は、各ページが指す版の部品 JSON を並べて `pptx_writer` で書く。PDF は 1 ページずつの PDF をつなぐ（PDF を分ける・つなぐ部品を入れる。いまは環境に無い）。
- **部品が残っていない古い版**（この計画より前の回）: 切り替えたとき、画面と発表は PNG で出す。書き出しのときだけ、その中身をいまのエンジンで描き直す。そのページには「書き出しでは、今の作りで描き直します」と添える。
- 設定を替えて全体を描き直す操作は撤去した（ADR 0032）。別の設定なら新しい資料として作る。

## A. 待たせない

### 非表示・並べ替えで本当に変わるもの

| もの | 変わるか | 扱い |
|---|---|---|
| 各ページの絵 | 変わらない（下の 2 つを除く） | いまの絵をそのまま使う |
| ページ番号を入れたスライド（html-slide の `page_numbers`。既定はオフ） | 後ろのページの番号がずれる | ずれるページだけ描き直す（裏で） |
| モーションの「2 / 22」・ここまでの言葉・章のレール | 再生するときに数える | 発表用の HTML 1 枚を組み直す（Chrome は要らない）。場面の絵は撮り直さない |
| 発表の画面 | 隠したページを飛ばし、並びに従う | いまの台本の並びと非表示で出す |
| 書き出し（PPTX・PDF・HTML） | 隠したページを抜き、並びに従う | C と同じく、ページごとの部品から組む |

### 描かない直し（非表示・並べ替え・版の切り替え）

- **サーバ**:
  - 回を作らない。台本の版を保存して受け入れる（`save_script` → `accept_script`）。版の切り替えは、そのページが指す版も替える。
  - 出来事（`events`）に記録を残す。各ページの「記録」に、これまでと同じ文言で出る。
- **順番を守る**: 先に走っている直し（指示での直しなど）は、古い台本を元に新しい台本を作る。その間に非表示を割り込ませると、非表示が消える。だから:
  - 仕事が待っていない・走っていないときは、すぐ当てる（ほとんどがこれ）。
  - 仕事があるときは、これまで通り仕事の列に入れる。ただしその仕事は描かない（列が空けばすぐ終わる）。画面はその場で替えるので、待たされて見えるのは「生成中」のページだけ。
- **画面の決まりを書き直す**: `page_view.py` の冒頭には「何も動いていないとき、いまの台本は見せる回の台本と同じ」とある。これが成り立たなくなるので、「ページの絵は、そのページが指す版のもの」に書き直す。
- **発表の画面**（`present_routes.present_view`）: いまの台本の並びと非表示で、ページを並べる。いまは描いた回の並び順で出しているので、ここを替える。
- **ページ番号を入れたデッキ**: 非表示・並べ替えの後、裏で組み直しの仕事を 1 つ入れる。画面は前の絵のまま先に替える（番号がずれた絵が数秒見える。描き終われば替わる）。

### モーションの発表用 HTML

- 非表示・並べ替え・版の切り替えの後、`motion_slide.py` で `index.html` だけを組み直す。拍は撮らない（1 秒前後の見込み）。
  - いまの `deck` には「組み立てだけ」の口が無い（`--quick` は `check` だけにあり、形の検査で終わる）。`deck` に、形の検査と組み立てだけを行い、Chrome で撮らない口を足す。
- 場面の絵は前のものを使う。後ろの場面の「ここまでの言葉」の札が 1 つずれた絵になることがあるが、受け入れる。

### モーションの場面ごとのキャッシュ

- **鍵**（場面ごと）: 場面の JSON・共通のスタイルと台本・テーマとロゴ・エンジンの版・撮るまでの待ち・前後の文脈（場面の番号と総数・ここまでの言葉）。
- 鍵が同じ場面は、前に撮った拍の絵と一覧の絵を使う。Chrome で撮るのは、鍵が変わった場面だけ。
- 1 場面だけ直したときは、その場面の拍だけを撮る（約 20 枚 → 数枚）。
